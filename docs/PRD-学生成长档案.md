# PRD：学生成长档案

> 版本：V2.0
> 更新日期：2026-08-04

## 1. 概要

学生成长档案用于让学校先定义一套统一的档案内容，再由老师按档案发起采集。老师或家长完成填写后，系统为学生建立或更新该档案，并在学生详情中展示。

第一期只采用一条固定保存规则：

> 同一名学生、同一份档案始终只有一份。第一次采集负责建立，后续再次采集负责更新。

启用档案时不设置生成周期、更新方式或成长数据范围。启用只代表该档案可以被老师用于采集。

档案中的成长字段保存本次档案采集形成的数据快照。以后身高、体重等成长数据通过其他问卷、PC导入或手机编辑发生变化时，不自动改写已经形成的档案。

## 2. 背景

### 2.1 已确认场景

学校会在新生入学时设计一份入学档案，通过采集任务发送给班主任或家长填写。填写完成后，学生详情中应直接出现这份入学档案，老师不应再次进入学生详情重复录入。

此前方案同时存在“实时读取最新成长数据”“按学期或学年生成”“完成并留档”等多套规则，导致以下问题：

1. 学校不知道启用时应该选择哪种更新方式。
2. 同一档案重复发起采集后，无法判断是生成新档案还是更新原档案。
3. 入学档案中的身高、体重会被几年后的最新记录替换，失去入学时的历史意义。
4. 采集任务没有固定结束时间，不能依赖“先结束旧任务”判断能否再次发起。

### 2.2 产品边界

- 新生入学、转学登记、学生基本情况等需要形成稳定学生资料的内容使用档案。
- 家访、谈话、获奖、活动和单次测评属于事件记录，可使用普通问卷，不作为档案。
- 学期目标继续作为待确认的独立功能，本期不进入档案和采集编辑器。
- 本期没有明确的按学期、按学年生成档案场景，因此不提供阶段档案规则。

## 3. 目标

### 3.1 学校目标

1. 先完成档案设计，再明确启用，让学校感知档案存在生效流程。
2. 启用后，老师可以在采集管理中直接选择该档案。
3. 同一学生不会因为重复采集出现多份同名档案。
4. 入学等历史场景中的成长数据不会被后续最新数据静默替换。

### 3.2 老师目标

1. 在档案详情中核实完整内容后启用。
2. 按档案发起采集时不再重新设计题目。
3. 发布前知道哪些学生会建立档案、哪些会更新档案。
4. 在学生详情中查看并编辑已经形成的档案。

### 3.3 非目标

- 不设置“仅生成一次、持续维护、每学期、每学年”等保存方式。
- 不设置档案的数据起止日期。
- 不让档案自动读取学生成长数据最新值。
- 不允许按档案采集时新增、删除、改名或调整题目。
- 不依赖采集任务结束状态判断是否可以再次发起。
- 不把普通问卷答案自动写入档案。
- 不把同名自定义题目自动识别为档案字段或成长字段。

## 4. 核心概念

### 4.1 档案设计

学校定义的内容标准，包括：

- 档案名称。
- 适用年级。
- 是否使用分组及分组顺序。
- 手动填写字段。
- 学校已经启用的成长字段。
- 字段题型、选项和必填状态。

档案设计不包含填写人、发送范围、建议完成时间和更新方式。

### 4.2 学生档案

学生档案是某名学生在某个档案标准下保存的一份当前内容。同一名学生和同一个档案编号构成唯一关系，不按问卷、提交日期或学期重复创建。

### 4.3 成长数据

成长数据是按记录日期持续积累的标准数据，例如身高、体重、肺活量和视力。它可以来自问卷、PC导入和手机编辑，并在成长数据页面展示最新值与变化趋势。

档案引用成长字段时，保存的是档案采集当时的值、记录日期和来源版本，不是对成长数据最新值的实时引用。

### 4.4 普通问卷

普通问卷用于一次性采集。普通题目答案只保留在本次答卷中；只有平台预置成长字段会写入成长数据。普通问卷不更新任何档案。

## 5. 用户流程

### 5.1 设计并启用档案

```text
教师手机端 → 我的 → 更多工具 → 档案设计
→ 新建档案
→ 完全新建 / 从模板创建
→ 保存草稿 / 完成设计
→ 待启用档案详情与真实预览
→ 启用档案
→ 确认启用
```

### 5.2 按档案发起采集

```text
采集管理 → 新建
→ 选择老师填写 / 家长填写
→ 选择采集内容
→ 按档案采集
→ 选择一份已启用档案
→ 查看完整且锁定的档案内容
→ 选择学生范围
→ 查看建立、更新和已有待填写人数
→ 发布
```

### 5.3 查看和编辑学生档案

```text
班级 → 学生详情 → 学生成长档案
→ 选择档案
→ 查看档案保存的普通字段和成长数据快照
→ 直接编辑 / 再次发起采集
```

## 6. 功能方案

### 6.1 档案状态

| 状态 | 可执行操作 | 是否可用于新采集 |
|---|---|---|
| 草稿 | 编辑、保存、完成设计、删除 | 否 |
| 待启用 | 查看详情、继续编辑、启用、删除 | 否 |
| 使用中 | 查看详情、停用 | 是 |
| 已停用 | 查看详情、编辑、重新启用、删除 | 否 |

点击“完成设计”后进入待启用详情。详情必须完整展示成长字段、手动字段、分组、题型、必填状态和全部选项，用于启用前核实。

### 6.2 启用档案

启用不再进入设置页，也不要求学校选择使用方式。

点击“启用档案”后只展示一次确认：

> 启用后，老师可以在采集管理中按此档案发起采集。

确认后状态变为“使用中”，并立即出现在采集管理的“按档案采集”列表中。

停用只阻止新任务选择该档案。已经发布的采集任务、学生已有档案和更新记录不受影响。

### 6.3 档案内容设计

“添加内容”提供两个页签：

1. `手动填写`：文字、单选、多选、日期和数字。
2. `成长数据`：展示学校后台已经启用的运营预置字段，并按生长发育、视力健康、体质测试和健康体检分类。

成长字段只设置“选填/必填”，不再设置“有则带入、缺失可补”和成长数据范围。

`手动填写 / 成长数据`只用于添加字段时选择内容类型，不作为档案中的固定展示分组。字段添加后统一进入老师当前选择的档案分组；预览、按档案采集和学生档案均沿用该分组与顺序。

姓名、班级、学号等学生身份信息不作为可配置档案字段。档案在学生详情中查看时复用当前学生上下文；导出时由系统统一展示必要身份信息。

#### 6.3.1 推荐模板

新建档案提供`一年级初始成长档案`和`学生个性与特长档案`两项推荐模板，不提供学期成长或毕业转衔模板。

使用推荐模板创建档案时，档案名称原样继承模板名称，不自动追加`校本`等前后缀。从空白创建时档案名称保持为空；新建与编辑页面的首个字段统一命名为`档案名称`，输入框为空时显示`请输入档案名称`，完成设计前必须填写名称。

`学生个性与特长档案`用于让班主任和科任老师快速了解学生，不包含成长数据，也不重复姓名、班级和学号等系统身份信息。模板固定包含以下 13 项：

- 性格与相处：性格特点、情绪表达方式、同伴相处特点、与老师沟通偏好。
- 兴趣与特长：兴趣爱好、擅长领域、代表性特长、喜欢参与的活动。
- 学习与支持：课堂参与特点、适合的学习方式、遇到困难时的表现、有效激励方式、需要老师留意的情况。

性格和表现相关选项使用中性、可观察的描述，并提供`待继续观察`或`其他`，避免将阶段性表现固化为学生标签。

### 6.4 按档案采集

按档案采集完整继承并锁定档案结构：

- 继承档案名称、布局、分组、字段顺序、题型、选项和必填状态。
- 不允许新增、删除、改名、排序或移动内容。
- 不允许在档案之外追加普通题目或成长字段。
- 需要采集其他信息时，单独创建自定义采集。
- 填写人仍在创建入口选择，档案本身不配置填写人。

如果档案包含成长字段，创建老师在发布前选择一个任务级记录日期。老师或家长填写端不再选择记录日期。

### 6.5 重复发起采集

重复采集按学生判断，不按任务是否结束判断。

| 学生状态 | 本次处理 |
|---|---|
| 还没有该档案 | 提交后建立档案 |
| 已有该档案，当前没有待填写邀请 | 提交后更新原档案 |
| 已在其他任务中等待填写同一档案 | 本次默认跳过，继续使用原任务 |

发布前展示：

```text
建立档案 12人    更新档案 28人    已有待填写 3人
```

“已有待填写”按学生在其他收集中任务中的实际填写状态判断。采集任务可以长期保持收集中，不要求老师先结束任务。若所选学生全部已在其他任务中待填写，则阻止发布并提示继续处理原任务。

同一任务中，每名学生只能完成一次。已完成学生以后可以被新的任务再次采集。

### 6.6 提交后的更新规则

老师或家长提交后立即执行：

1. 学生没有该档案时，创建一份学生档案。
2. 学生已有该档案时，更新同一份档案。
3. 本次有效填写的档案手动字段替换原值。
4. 未填写的选填字段不清空原值。
5. 单选和多选按本次完整答案替换，不与历史选项机械合并。
6. 成长字段写入成长数据，并同时将本次值、记录日期、来源任务和数据版本保存到该档案。
7. 保留更新人、更新时间和来源任务，供后续追溯。

不需要老师再次点击“确认成档”。

### 6.7 成长数据快照

示例：

```text
2026-09-01 新生入学档案采集
身高：120cm
体重：23kg
```

提交后：

- 成长数据新增2026-09-01的身高、体重记录。
- 新生入学档案保存120cm、23kg以及2026-09-01的记录日期。

两年后，普通成长采集记录身高132cm：

- 成长数据最新身高更新为132cm，趋势增加一条记录。
- 新生入学档案仍显示120cm，不自动变化。

只有再次明确引用“新生入学档案”发起采集，或者老师直接编辑这份档案时，入学档案才会更新。

### 6.8 学生详情

学生详情中的档案列表只按档案名称展示一份，不按提交日期生成多份同名档案。

列表状态：

- `待采集`：学校已经启用，但该学生尚未形成档案。
- `已建立`：已经通过采集或老师直接编辑形成档案。

进入档案后展示：

- 发起采集入口。
- 档案中保存的成长数据快照及其记录日期、来源。
- 档案手动字段。
- 保存修改操作。

低频的历史版本统一进入“更新记录”，不与当前档案并列展示为多份档案。

## 7. 数据与权限

### 7.1 核心数据对象

| 对象 | 唯一规则 | 关键内容 |
|---|---|---|
| 档案模板 | 学校内模板编号唯一 | 状态、适用年级、结构和字段 |
| 学生档案 | 学生编号 + 档案模板编号唯一 | 当前字段值、成长快照、更新时间 |
| 档案更新记录 | 学生档案编号 + 更新版本 | 更新前后值、填写人、来源任务、时间 |
| 成长数据记录 | 学生编号 + 数据项 + 来源记录 | 数值、记录日期、来源和版本 |
| 采集任务 | 任务编号唯一 | 填写人、档案结构快照、学生范围 |

已发布任务冻结档案结构快照。学校以后停用或修改档案设计，不改变已经发布任务中的题目。

### 7.2 权限

- 只有具备档案设计权限的学校角色可以创建、启用和停用档案。
- 管理档案设计不自动获得学生档案内容查看权。
- 老师只能查看自己原本有权限访问的学生档案。
- 家长只能填写与本人绑定学生相关的任务，不能查看学生档案管理页面。
- 查看和修改学生档案保留操作记录。

### 7.3 异常规则

- 成长字段缺少记录日期时不能发布采集任务。
- 记录日期不能用提交时间自动替代。
- 普通问卷中的同名题目不能写入档案。
- 档案停用后不能创建新的按档案采集，旧任务仍可继续填写。
- 模板删除不删除学生已有档案和更新记录。
- 重复提交使用任务和学生唯一约束保证幂等，不重复写入成长记录。

## 8. 发布与验收

### 8.1 第一期范围

- 档案草稿、待启用、使用中和已停用状态。
- 启用确认，不提供更新方式配置。
- 按档案采集及结构锁定。
- 发布前建立、更新和已有待填写人数提示。
- 同一学生、同一档案只保留一份。
- 档案字段自动建立或更新。
- 成长数据写入成长记录并冻结到档案快照。
- 学生详情查看、编辑和再次发起采集。
- 更新记录与来源追溯。

### 8.2 验收标准

- [ ] 完成档案设计后进入待启用详情，可以核实全部字段和选项。
- [ ] 点击启用只需确认，不出现周期、保存方式或数据范围设置。
- [ ] 使用中档案出现在采集管理的按档案采集列表中。
- [ ] 按档案采集不能增删或调整档案内容。
- [ ] 发布前正确展示建立档案、更新档案和已有待填写人数。
- [ ] 其他任务中待填写的学生不会重复收到同一档案邀请。
- [ ] 采集任务没有结束时间时仍可对已完成学生再次发起更新。
- [ ] 首次提交后，学生详情自动出现该档案。
- [ ] 再次提交同一档案后更新原档案，不出现第二份同名档案。
- [ ] 档案中的身高、体重保存本次记录日期和来源。
- [ ] 后续普通成长采集不会改变入学档案中的身高、体重。
- [ ] 老师直接编辑档案并保存后，学生详情立即展示新内容。
