# 教师发展评价教师手机端需求与页面方案

状态：方案评审稿，页面结构和交互建议待产品确认。

首版面向教师与具有审核权限的教师，以微信小程序手机场景完成材料提交、人工智能识别、按指标规则入库、材料审核和成长档案查询。学校管理端暂不制作页面，但学校制定的考核指标、是否审核、审核角色及授权范围是手机端运行的配置依据。

## 1. 概述

让教师通过语音、文字和照片便捷提交成长材料，人工智能提取内容并匹配学校考核指标。字段完整且匹配明确时，无需审核的指标直接通过并更新入库；需要审核的指标进入学校指定角色的审核队列。具有审核权限的教师既能提交本人材料，也能在手机端审核授权范围内其他教师的材料。

首版交付可交互演示，真实语音转写、图片识别及管理端服务接入单独确认。演示能力和样例选择只在手机壳外的演示工具中说明，不在教师业务页面中堆放开发说明。

## 2. 角色与职责

| 角色 | 核心职责 | 首版呈现 |
| --- | --- | --- |
| 教师 | 提交本人材料、查看识别与匹配结果、补充材料、处理退回、查阅个人档案 | 手机端完整核心流程 |
| 兼任审核人员的教师 | 保留教师全部能力，并审核学校授权范围内其他教师的材料 | 手机端增加审核入口、待审列表、审核详情和通过或退回操作 |
| 学校配置人员 | 制定考核维度和具体指标，配置采集要求、是否审核、审核角色与范围及评价规则 | 定义配置结构与演示配置；暂不制作管理页面 |

教师身份与审核权限可以叠加，不能将教师和审核人员设计为互斥身份。人工智能负责提取和指标匹配，自动通过由学校的免审核配置决定；需要审核的指标不因识别成功而跳过人工审核。

## 3. 背景与依据

[玉林中学平台建设规划方案](references/teacher-evaluation/四川省成都市玉林中学教师专业发展数字化平台建设服务规划方案8.5.docx)是评价维度和学校指标建模的重点依据。其第二章“建设目标及策略”明确以《中小学教师专业标准》为建设依据，数据采集、评价维度和数据分析应按照标准开展；“总体评价”正文列举师德师风、专业能力、教学能力、教研能力、社会影响等维度，并支持依学校要求深入分析。

演示指标体系优先以这组正文维度为骨架，具体指标、权重和采集字段来自学校配置。材料要展示匹配的具体考核指标及上级维度，不能只识别成“证书”“培训”等材料类别。玉林方案示例界面的维度名称与正文有所不同，示例截图不等同于最终学校指标库；不得将两组名称直接拼成新的固定体系。

[乐途教师发展评价产品方案](references/teacher-evaluation/乐途-教师发展评价产品方案.docx)用于参考语音录入、证书识别、分类纠错和教师成长体验。其六大维度作为补充参考，不直接替代玉林方案的评价依据与学校制定的考核指标。

本轮产品明确的指标级审核配置与手机端审核流程，是首版业务规则：是否审核、由什么角色审核，都由学校定义。材料类别辅助归档，具体考核指标决定审核路线与评价归属，评价方案决定计分与汇总。

## 4. 首版目标与验收结果

| 目标 | 可验收的结果 |
| --- | --- |
| 便捷提交 | 教师可直接使用语音、拍照或文字提交材料，无需先理解完整指标树 |
| 准确匹配 | 展示原始材料、提取结果、具体考核指标与上级维度；不确定、缺失或冲突字段可补充 |
| 免审核入库 | 命中无需审核的指标且校验通过后，直接显示已通过并更新本人有效档案，无需额外确认提交或人工审核 |
| 按配置审核 | 命中需审核指标后进入指定角色与授权范围的待审队列，通过后入库，退回后可补充重提 |
| 权限叠加 | 普通教师只访问本人提交与档案；兼任审核人员保留个人能力，并访问授权范围内的他人材料 |
| 档案有效 | 自动通过和人工审核通过都进入有效档案；待审核、待补充和退回内容不计入有效结果 |
| 规则可适配 | 指标、采集字段、审核开关与角色来自学校配置；正式计分只按学校已配置的评价方案计算 |
| 演示可复核 | 覆盖免审核通过、人工审核通过、退回重提、无匹配、字段缺失、越权阻止和本人材料不能自审 |

使用效果可后续跟踪记录完成时间、提交完成率、分类更正率和材料退回率。目标数值应在试用得到基线后确定，不预设改善比例。

## 5. 用户与使用场景

核心用户是学校教师，常在课间、活动结束或取得材料后使用手机，时间短、输入条件有限。部分教师兼任学校指定的审核角色，需要在同一手机端处理个人提交和审核工作。首屏按权限展示本人记录和审核入口，避免用总分、排名或长说明占据高频操作空间。

典型任务包括记录一次培训或公开课、提交获奖证书、补充教研过程材料、处理审核退回、查阅已认定档案。专业发展档案同时容纳过程性记录和结果性材料，不要求每次记录都有证书、奖项或分值。

## 6. 用户价值

教师无需反复理解学校指标或重新录入已归档材料。免审核指标识别完成即可入库，需审核的材料能追踪认定进度；审核人员在手机端查看原始材料、匹配指标及学校要求后作出决定。

自动通过和人工审核通过都具有明确依据与留痕，评价汇总只按学校方案计算，不根据材料数量推断正式评价成绩。

## 7. 页面与业务方案

### 7.1 信息架构建议

| 一级入口 | 页面职责 | 首屏内容 | 次级能力 |
| --- | --- | --- | --- |
| 记录 | 提交材料与追踪处理进度，默认进入 | 本人记录流、需补充或退回事项、悬浮录入条；有权限者增加待我审核入口 | 状态筛选、学校考核指标查阅、记录详情、审核列表与详情 |
| 档案 | 查阅已认定的成长证据 | 学年选择、有效档案概览、按玉林参考维度与学校指标组织的材料 | 时间或材料分类浏览、原始材料预览、证据详情 |
| 我的 | 个人资料与低频工具 | 教师身份、任教学科及适用的审核职责 | 学校采集要求、帮助；学校维护字段只读 |

建议普通教师的记录页直接呈现本人记录，不显示单项身份切换。具有审核权限者在记录页顶部显示“我的提交 / 待我审核”，待审入口显示待办数量；切换到待我审核后隐藏本人录入条，专注审核任务。无需退出或切换账号才能在两类任务间切换。

档案按学校维度和具体指标组织有效证据，同时保留时间与材料类别查询。展示自动通过或人工审核通过的依据、来源和时间；学校已配置评价办法时可呈现对应结果，未配置时不生成能力分数、等级或雷达图。证书图片出现在对应材料中，首版不单独增加证书墙视图。完整阶段报告保留后续扩展。

### 7.2 材料识别与指标分流

1. 在记录页语音口述、拍照或输入文字并发送材料，不要求先选表单类别。
2. 人工智能提取材料内容，匹配当前学校的具体考核指标，校验该指标要求的字段与附件。
3. 匹配明确且校验通过时，读取该指标的审核配置：无需审核则直接通过并更新入库；需要审核则进入指定角色与授权范围的审核队列。
4. 无匹配、多项匹配无法确定或必填材料缺失时，保留为待补充，展示问题并允许教师补充或更正后重新识别。不得将这些异常自动当作免审核通过。
5. 显示实际结果、具体指标与上级维度。自动通过不增加统一的“确认入档”步骤，需审核也不要求教师另点一次“提交审核”。

标题、发生时间、人员、颁发单位、活动级别等按材料实际内容和学校配置展示。培训时长、课题阶段、论文刊物、本人承担角色等由匹配指标的采集字段决定，禁止把所有字段堆到每一种记录上。

采集字段依学校具体指标配置，材料类别不单独决定审核策略。免审核不免除必填校验；人工智能不能自行决定是否审核、谁来审核或使用其他学校的指标。每次处理保留学校配置和指标版本，修改指标后必须重新执行校验与分流。

### 7.3 状态与恢复

| 状态 | 教师可进行的操作 | 是否进入有效档案 |
| --- | --- | --- |
| 草稿或待补充 | 修改、保存、删除、补充后发送或重新识别 | 否 |
| 识别处理中 | 查看处理状态；处理完成前不产生有效档案 | 否 |
| 待审核 | 查阅；审核尚未开始时申请撤回，服务端校验是否允许 | 否 |
| 已退回 | 查看原因、修改内容、补充材料、重新提交 | 否 |
| 已通过 | 查阅内容、原始材料和通过依据；区分按学校规则自动通过与人工审核通过 | 是 |

自动通过和人工审核通过共用已通过状态，通过方式分别留痕。免审核记录记录所依据的指标、配置版本和处理时间，不虚构人工审核人员。需审核记录保存审核人员、时间与意见。通过后更新有效档案与学校已配置的评价汇总，重复处理不能重复入库。

审核列表只显示当前用户有权限处理的其他教师材料。详情展示提交人、材料原文与附件、识别字段、具体指标及审核要求；主操作为“通过”，次操作为“退回补充”，退回必须填写原因。通过前校验权限、当前状态与版本，已被处理的材料不允许再次审核。

审核权限按学校指定角色与组织范围判断，不能因账号也是老师就拥有审核权。兼任审核人员提交的本人材料仍按相同指标规则处理；需要审核的本人材料进入其他获授权人员的队列，不能自审。审核配置缺失或没有可接收的审核人员时保留待处理并报告配置问题，不擅自改为免审核。

识别失败时保留原始输入并提供重试或手动补充。字段缺失时定位缺失字段；疑似重复时展示可能重复的既有材料，由教师判断补充或继续提交。提交失败时保留内容，重试不得生成重复记录。

退回重提沿用同一条记录的身份，新增内容版本，保留历次审核，并按重提时有效的指标配置重新匹配与分流。已通过材料的修改不能直接覆盖有效结果；需保留历史版本并重新校验，按指标审核规则处理，具体替换策略在后续版本确认。

语音在当前页原位完成，支持上移取消；取消不提交记录。输入未保存时退出提供继续编辑或放弃的选择。错误、退回和识别状态同时使用文字表达，不只依赖颜色。

### 7.4 管理端衔接规则

| 衔接对象 | 管理端职责 | 手机端消费方式 |
| --- | --- | --- |
| 组织、教师与审核授权 | 提供当前教师、学校、学科、审核角色及授权范围 | 保留本人能力；仅对获授权用户增加他人材料审核能力 |
| 考核维度与具体指标 | 维护指标层级、采集字段、必填条件、附件要求和版本 | 识别时匹配学校具体指标，显示上级维度与必要字段 |
| 指标审核规则 | 配置是否审核、审核角色及适用组织范围 | 无需审核且校验通过则直接入库；需审核则进入对应队列 |
| 档案记录 | 接收原始输入、附件引用、结构化内容、匹配指标与提交版本 | 查询本人记录与档案，允许编辑当前可修改版本 |
| 审核任务与结果 | 产生待审任务，校验审核权限，返回方式、人员、时间、原因及版本 | 手机端审核他人材料，提交通过或退回结果，追踪本人审核反馈 |
| 自动归集数据 | 提供教学、教研等业务来源与关联信息 | 明确来源；学校维护的材料不作为个人手填记录覆盖 |
| 评价方案 | 定义周期、权重、计分和汇总办法 | 通过后按学校已配置办法更新结果，不内置统一封顶或排名规则 |

记录至少保留记录标识、学校与提交教师标识、原始输入、附件、材料类别、结构化字段、匹配指标及维度路径、指标配置版本、提交版本、审核规则快照、状态、通过方式及处理历史。原始输入、人工智能提取结果、教师更正内容与审核认定内容应可区分。

指标配置至少包括标识、上级维度、名称、适用教师范围、采集字段、附件要求、是否审核、审核角色与范围、评价规则引用和版本。审核任务绑定材料与提交版本；同一账号可关联教师身份和多个审核授权，不通过切换角色改变材料归属。

提交、自动通过、人工审核与有效档案更新分别校验权限、状态及版本，防止并发或重复处理。审核路由由业务服务读取学校配置，不能只依赖前端隐藏按钮。计分与评价计算归评价方案职责，不写进基础输入、卡片或弹窗组件。

### 7.5 界面评审结论与规范取舍

评审结论：首版完成识别、指标分流、免审核入库、手机端人工审核和归档链路。本人提交与审核他人的任务明确分开，按权限呈现审核能力，低频配置与个人设置放到次级页面。当前尚未有新版可视页面，字号、对比度和真实设备适配需在实现后验证。

| 项目 | 新版建议 | 与现有规范的关系 |
| --- | --- | --- |
| 导航 | 记录、档案、我的；有审核权的记录页提供“我的提交 / 待我审核” | 现有“记录、班级、我的”服务学生评价业务；新模块中间入口改为档案，仅作业务语义例外 |
| 品牌与文字 | 沿用教师品牌色、字号层级与统一字体，不新增局部主题 | 复用现有设计令牌 |
| 信息层级 | 本人记录突出输入与处理状态，审核页突出待办与材料证据，档案页突出学校维度及有效材料 | 未授权者不展示审核控件；进入审核任务后不展示本人录入条 |
| 触控与状态 | 沿用至少 44 像素触控规格，提供加载、错误、退回和禁用反馈 | 与教师手机端规范一致 |
| 图标 | 采用清晰、统一的项目图标体系；档案入口须使用符合语义的图标 | 不将“班级”图标直接改名用于档案；最终图标方案待确认 |
| 公共能力 | 复用页面标题栏、选择控件、底部弹窗、确认与轻提示 | 通用组件不嵌入教师发展评价业务规则 |

方案确认后，先在教师手机端界面规范中补充新模块的适用范围和导航语义例外，再开始页面编码。保留既有学生评价端的页面、导航和业务规则。

### 7.6 实现边界

新模块独立承载教师发展业务。基础层负责设计令牌、屏幕与通用交互；公共组件层承载按钮、表单、弹窗等能力；业务层负责学校指标、权限叠加、识别匹配、审核分流与材料状态。识别、审核与管理端通信由服务层承载，演示数据实现同一边界。

演示采用预置学校指标与审核授权，不制作学校配置页面。手机壳外提供普通教师和兼任审核人员的样例账号切换，用于复现权限差异；手机端本身无需切换角色才能访问已授权的任务。不同样例账号共享同一份演示数据，能够复现教师提交后由另一教师审核、结果回到原教师档案的完整流程。

演示中的入库通过本地持久化数据层实现，自动通过、审核通过和退回均更新同一份记录，刷新页面或切换样例账号后能够追踪已发生的结果。真实数据库与服务接入后沿用相同业务边界；不得只改变卡片文字而不更新有效档案。

首版不制作学校管理页面，不设固定积分上限或默认计分公式，不增加评价排名，不完成学生发展贡献自动推断，不接入考勤、人事或培训管理的全套业务。这些范围在后续阶段按实际需要扩展。
