整理范围：教师-手机端、学校-PC端、家长-手机端、货柜机（学生在校终端）四个 demo 的全部页面。

- 口径来源：`解决方案.md`《年级与班级展示方案》
- 代码依据：`mobile-app/domain/classInfo.ts`、`mobile-app/domain/teacherSpaceAccess.ts`
- 整理方式：按四端源码逐页检索「年级 / 班级」展示点，供人工核对；未在源码中发现年级/班级文案的页面统一标记为「不出现」。
- 路径说明：下表「源码路径」均为仓库根目录起算的完整相对路径，可直接在编辑器里定位。

状态说明：✅ 与方案一致　⚠️ 与方案不一致　➖ 该页不出现年级/班级　❓ 待人工确认

## 一、标准口径速查

**年级名称**（固定 12 个，全部为中文名称）

一年级　二年级　三年级　四年级　五年级　六年级　七年级　八年级　九年级　高一　高二　高三

**班级名称**

| 学校类型 | 规则 | 示例 |
| --- | --- | --- |
| 小学 / 初中 / 高中 | 入学年份 + 「级」+ 阿拉伯数字班号 + 「班」 | `2026级1班` |
| 九年一贯制 | 加 `小` / `初` 前缀 | `小2026级1班`、`初2026级1班` |
| 十二年一贯制 | 加 `小` / `初` / `高` 前缀 | `小2026级1班`、`初2026级1班`、`高2026级1班` |
| 完全中学 | 加 `初` / `高` 前缀 | `初2026级1班`、`高2026级1班` |

**三条硬规则**

1. 年级只用中文名称（一年级），不写「1年级」。
2. 班号只用阿拉伯数字（1班），不写「一班」。
3. 只有九年一贯制 / 十二年一贯制 / 完全中学才加学段前缀。

**代码落点**

| 能力 | 位置 |
| --- | --- |
| 班级名称拼装 `buildClassName` | `mobile-app/domain/classInfo.ts` |
| 年级名称换算 `getGradeLevel` | `mobile-app/domain/classInfo.ts` |
| 中文班号归一 `normalizeTeacherClassName` | `mobile-app/domain/teacherSpaceAccess.ts` |
| 学段前缀 `getTeacherClassDisplayName` | `mobile-app/domain/teacherSpaceAccess.ts` |
| 按学校类型给年级集合 `getTeacherSchoolGradeOptions` | `mobile-app/domain/teacherSpaceAccess.ts` |

**demo 中的学校空间**（决定是否出现学段前缀）

| 空间 | 学校类型 | 班级前缀 | 定义位置 |
| --- | --- | --- | --- |

### 2. 数据源不干净（建议在源头统一）

- 教师手机端班级基础数据 `mobile-app/constants.ts` 的 `MOCK_CLASSES` 用的是中文班号：`2026级一班`。
- 目前靠展示层 `normalizeTeacherClassName()`（`mobile-app/domain/teacherSpaceAccess.ts`）兜底转成 `2026级1班`；一旦有页面直接读 `classInfo.name` 展示，就会露出「一班」。
- 建议把数据源改成阿拉伯数字班号，展示层的归一逻辑保留作为兜底。

### 3. 需产品确认的口径问题

- **学段前缀的适用范围**：方案规定九年一贯制 / 十二年一贯制 / 完全中学的班级要带 `小 / 初 / 高` 前缀。教师手机端已实现（`getTeacherClassDisplayName`），但学校-PC端、家长端、货柜机都没有这个能力，三端目前都只展示 `2026级1班`。需要确认是否统一补齐。
- **「年级 + 班级」的两种表达**：报告类正文里用「三年级12班」这种合并写法，与独立展示的「年级名称 + 班级名称」是两种口径。需要确认报告正文是否也要统一。
- **班级是否带入学年**：档案明细里的「一（1）班」是入学年缺失写法，需要确认是历史数据问题还是有意保留。
