## 归档规则

新文档先确定所属 Demo，再放入对应项目目录。项目较小时直接存放需求与设计文档；有需要时增加 `参考资料`（原始资料）、`实施计划`（实施计划）、`提示词`（提示词）、`报告样例`（报告样例）、`历史归档`（历史材料）等子目录。原始资料与截图跟随所属项目，避免散落在全局引用目录。

教师评价指“评价教师的专业发展”，教师手机端主要指“教师评价学生”，两者分别归档。校长助理属于教师手机端中的学校管理角色能力，因此其提示词和报告样例归入教师手机端。

跨端资料按业务主题保留一份：例如学生成长档案供学校、教师、家长共用，放在 `shared/student-growth`。货柜机等尚无独立 `docs` 文档的 Demo 不创建空目录，新增文档时再建立。

`实施计划` 记录当时的实施方案，不表示所有内容仍是当前基线；`历史归档` 中已废止内容保留原有状态说明。新需求以对应项目的最新需求文档及明确的选型记录为准。

仓库根目录及 `design-system` 中的公共规范继续在原位置维护。文件路径移动后同步更新引用它的文档、提示词和现有检查脚本。
