# Demo 独立项目：学生评价 · 成长全景

## 场景与设计依据

- 面向学校大厅及接待区的公共屏幕，观看者为来访领导、家长及师生；主要尺寸 1920×1080，兼容 1280×720 和窄屏预览。
- 项目 `frontend-design-codex` 主导设计，公共 `frontend-design-review` 辅助评审。深海军蓝底，蓝／青绿／琥珀配色，三列六面板，突出评价过程与学生成长。
- 第一层展示评价次数、成长记录条数、学生覆盖率及教师参与率；第二层展示五育、年级覆盖及教师育人足迹；第三层用教师动态评价和学生积分变化体现实时过程。
- 对照 `PC_UI_GUIDELINES.md`，本页属于公共展示，使用局部高对比与大字号规范；不将后台表单及操作界面布局直接套用。
- 提供统计周期切换、暂停／继续、年级手动翻页与自动轮播、全屏。减少动态效果时关闭位移动画和自动翻页；页面隐藏时停止演示更新。保留键盘操作与可访问数值。

## 入口与并行维护

- Demo 菜单「数据大屏」与 `?app=data-screen` 都打开本方案。
- 全部组件、样式及演示状态位于 `components/demo-data-screen/`；样式类、动画使用 `demo-` 前缀，不依赖学校 PC 方案。
- 学校 PC 顶部「育人大屏」继续使用 `components/data-screen/`，地址为 `?app=school-pc-screen`。该方案的视觉、页签与图表独立迭代。
- 两套方案由用户最终确认取舍前，均须保留，禁止合并入口、复用展示组件或覆盖对方文件。
- 本方案从 `output/imagegen/school-outcomes/implementation-baseline/` 中保存的原设计恢复，保留此前修复的 720P 五育图表和年级列表裁切处理。

## 数据口径

- 只读适配既有 `mobile-app/services/leaderReportService.ts` 的今日、本周、本月、本学期快照，不修改教师手机端报表。
- `summary.totalRecords` 为评价次数，`summary.totalEvaluationCount` 为成长记录条数；一次评价 N 人，评价次数加 1，成长记录加 N，批量分值按每人变化累加。
- 五育分布采用已归类五育行为条数作为分母，不与全校成长记录总量混用；加分、减分及净得分分别统计。
- 使用既有演示学校及脱敏学生称呼；每 5.2 秒产生一次演示评价，联动更新所有周期，历史样例不重复累加存量，重复评价不增加覆盖人数。
- 页面显示「演示数据」「实时演示」，尚未连接正式实时接口。本方案的演示事件、缓存与播放状态独立于学校 PC 方案。

## 验证

- `node components/demo-data-screen/studentEvaluationScreen.test.mjs`：统计口径、多人评价、正负分、去重、周期同步、覆盖人数、缓存边界及真实组件渲染。
- `node components/data-screen/studentEvaluationScreen.test.mjs`：独立验证学校 PC 方案未受影响。
- `npm run build`：两套方案共同构建。
