# 教师发展评价手机端需求与页面方案

状态：产品需求与第一版页面迭代稿，2026-10-14更新。以精简推荐版举例，指标方案尚未选定；页面结构建议共用记录、档案、报表、我的四个入口。详细页面见[教师手机端页面结构方案](教师手机端页面结构方案.md)。

## 1. 概述

首版面向教师、管理者两种身份：教师便捷记录及查看本人成长；管理者在手机端评价和审核，并查看全校教师档案与学校报表。学校在指标上配置评价角色、是否需审核及计分规则，AI匹配材料与规则，系统按配置计分入档。

本期包含管理者使用的手机端数据、审核和报表页面。学校配置指标、权限和考核办法的管理端页面暂不制作，以预置学校配置定义衔接。

## 2. 角色与职责

| 角色 | 核心任务 | 数据范围 |
| --- | --- | --- |
| 教师 | 提交本人材料、补充缺项、查看AI结果、处理未通过、查看个人档案和报表 | 本人 |
| 管理者 | 评价有权限的其他教师、审核需审记录、查看教师档案与学校报表 | 本校全体教师及学校汇总数据 |

管理者包含校长、教研组长及获授权评选人，是一种权限身份。账号可兼任教师，保留本人记录和个人档案，不通过退出账号切换工作。页面中的“全校／我的”是查看范围，不增加角色。

全校数据查看权与指标评价权分别判断；审核不能处理自己提交的记录。全校查看仅限本校，不能因姓名搜索或保存页面地址取得其他学校的数据。

## 3. 背景与依据

[玉林中学平台建设规划方案](参考资料/四川省成都市玉林中学教师专业发展数字化平台建设服务规划方案8.5.docx)是指标建模重点依据。其正文以《中小学教师专业标准》为建设依据，列举师德师风、专业能力、教学能力、教研能力、社会影响等维度，并支持依学校要求深入分析。

[指标模型研究与建议](教师发展评价指标模型研究与建议.md)保存正文、十张内嵌图片、正式2012年中学教师专业标准和相关研究的核对；[五套候选方案](指标方案/README.md)分别体现不同来源和颗粒度。国家标准为3个维度、14个领域、63项基本要求；候选B的28项是产品转译。方案C的4维12项及分值均是产品示例，不是国家或玉林已发布的计分标准。

[乐途教师发展评价产品方案](参考资料/乐途-教师发展评价产品方案.docx)及[竞品完整体验与取舍](参考资料/教师成长记录竞品体验与方案取舍.md)用于参考语音、图片识别、成果分类、级别和时光轴；不改变学校指标配置及评价依据。

学校可调整层级、数量、名称、评价角色、是否需审核、证据字段、分值、周期和版本。手机端读取学校配置，不把精简版写成固定产品模型。正式选型以[方案选型记录](方案选型记录.md)为准。

## 4. 目标与验收

| 目标 | 验收结果 |
| --- | --- |
| 便捷记录 | 语音、拍照、文字均可开始；不要求先选材料类别或写固定格式报告 |
| 配置通用 | 相同页面支持不同指标树、评价角色和审核开关；更换配置后正确分流 |
| AI减少人工 | 展示匹配指标、规则依据及分值；系统计算，无单独人工打分任务 |
| 审核清晰 | 不需审直接通过；需审一次审核通过计分；自己提交不能自审 |
| 两种身份 | 教师只访问本人；管理者可查看全校、处理有权限的评价和审核，并保留个人能力 |
| 全校可追溯 | 学校报表能下钻到分组、教师、指标和具体记录，返回保留筛选 |
| 数据一致 | 同一已通过事件同步记录、档案、个人及学校报表；附件、审核意见和修订不重复计数 |
| 结果可信 | 无规则只归档，缺项可补充；待审、未通过、撤销不进入有效分数 |

后续试用可跟踪完成时间、补充率、指标更正率及审核耗时，不预设未经验证的改善比例。

## 5. 用户与场景

教师常在课间、培训或教研后用手机记录，优先提供直接录入和少量补充。管理者常在碎片时间处理待审、查看教师成长及学校趋势，需从汇总快速找到对象和证据。

两种身份使用同一设备和组件体系。教师不被全校名单和管理操作干扰；管理者不需要在多名教师账号间切换才能查看数据。

## 6. 用户价值

教师只需提供事实或材料，AI负责分类、提取字段及匹配学校规则，免审时自动处理，需审时能追踪状态。

管理者一次确认事实和规则即可完成审核；全校教师目录、学校报表及记录证据相互连通，查到一项统计后可理解其来源。学校按自己的指标运行，不依赖某套模板的固定名称或数量。

## 7. 页面与业务方案

### 7.1 导航和页面范围

| 入口 | 教师 | 管理者 |
| --- | --- | --- |
| 记录 | 我的提交及AI录入 | 全校记录、待审核、评价教师，可切我的记录 |
| 档案 | 我的时光轴、指标分及材料 | 全校教师目录、教师档案，可切我的档案 |
| 报表 | 个人成长、分数及记录统计 | 全校概览、分组汇总、教师明细，可切我的报表 |
| 我的 | 本人资料、指标说明与帮助 | 本人资料、已有身份说明、指标说明与帮助 |

四个入口的首屏层级、详情、筛选及异常状态见[页面结构方案](教师手机端页面结构方案.md)。审核放在记录页，学校报表使用独立底部入口；不增加审核中心、教师管理等额外常驻入口。

记录首页只保留快速录入；管理者顶部“记录／审核（待办数）”复用原教师手机端胶囊。教师仅有记录功能。指标入口下方是状态标签；记录标签为全部、已通过、待审核、未通过，审核标签为待审核、已通过、未通过。未通过原因直接展示，提交人可修改重提；管理者审核已处理项可在对应标签追溯。查询集中在档案，记录与待办不受档案周期或筛选影响。

管理者的全校档案默认教师目录，进入教师后始终显示对象姓名。全校报表先显示事实概览，按学校→学科或年级→教师→指标记录下钻，不把所有筛选和图表堆在首屏。

### 7.2 指标配置与统一处理

| 核心配置 | 含义 |
| --- | --- |
| 评价角色 | 教师、管理者或两者；教师评价本人，管理者评价本校有权限的他人 |
| 是否需审核 | 每个末级指标一个开关，适用于该指标所有允许提交的角色 |
| 规则与证据 | 指标定义、触发及排除条件、必要字段、材料类别、级别及具体计分规则 |
| 计分边界 | 基础分、上限分、下限分及汇总方式 |
| 周期与版本 | 生效期、考核周期、历史版本及更正权限 |

流程：录入事实或材料→AI匹配对象、指标及规则→校验→按审核开关直接生效或待审核→计分入档。教师免审记录不增加确认入档动作；需审记录不要求再点一次提交审核。

管理者录入他人评价时，结果卡显示对象、事实、指标、规则及分值，确认后提交。若指标需审，由另一名管理者审核；录入确认不能替代审核。若指标不需审，提交后直接生效。这由一个指标开关决定，不再按角色、心得或成果设置隐含免审例外。

学校未发布规则时仅归档；字段缺失、匹配歧义、证据冲突或事实未核实时在录入处提示具体问题，尚未提交，不新增待补充、待核实业务状态。AI不自行编造分值，也不从反思中的困难、探索失败或未经核实投诉直接推断扣分。正式师德等次按学校制度另行形成。

### 7.3 审核与状态恢复

| 状态 | 可做什么 | 是否进入有效档案和得分 |
| --- | --- | --- |
| 尚未提交（录入状态） | 编辑；信息不足或识别失败原位提示，修正后再提交 | 否；不生成已提交记录 |
| 待审核 | 查看，按规则撤回；另一名有权管理者审核 | 否 |
| 未通过 | 查看原因；提交人修改后重提同一条记录 | 否 |
| 已通过 | 查看依据、分数、材料及历史 | 是；无计分规则时仅归档 |
| 已撤销 | 查看原因及历史；有效分数重新计算 | 否 |

审核详情优先显示AI整理的事实、指标、规则及分值，原始材料可展开查看。主操作通过，次操作不通过，必须写明原因；更正规则匹配须有依据和原因，由系统重算，不另设打分页面。

对象重名、人员不明或找不到时先选择正确教师，不能自动把评价归给本人或猜测对象。无其他管理者可审核时保留待审并提示配置问题。服务端验证学校、权限、状态和版本，不只依赖前端隐藏控件。

识别、网络或提交失败时保留输入并可重试，不新增重复记录。未通过、编辑及撤销保留修订链；已通过内容更正后重算档案和报表，不直接覆盖旧记录。

### 7.4 全校报表与数据口径

管理者首版学校报表覆盖全校教师人数、有已通过记录的教师人数、已通过教师成长记录数、待审核记录数，以及维度分布、记录趋势、学科或年级汇总、教师明细。个人报表复用相同查询，只限定本人。

待审、未通过、撤销不计入有效记录及分数。一个教师的一件事件只计一条教师成长记录，附件、多指标关联、审核意见及重提不增加条数。发起评价次数与按对象生成的记录数分开统计。

精简版当前候选基础合计100、上限145、下限25，按学期累计。没有事件时保留基础分，不自动标为优秀；学校得分统计应包括所选周期内全部适用教师，不只统计上传过材料的人。不同规则版本、岗位不适用项及不同周期不能未经说明直接排名或求均值。

报告默认提供事实统计和明细，不用AI主观给教师排名。报表查询保存学校、周期、适用方案版本及筛选条件，图表和明细来自同一数据来源。

### 7.5 竞品体验后补充的首版要求

| 要求 | 页面及验收 |
| --- | --- |
| 多材料归并 | AI录入先区分一件事多页材料与多件成果；批量结果逐件生效、待审或补充，不强制免审项再确认入档 |
| 识别可核对 | 结果包括标题、对象、指标、类别、适用级别与阶段、本人贡献；必要字段定位到原文／原图依据 |
| 重复防止 | 重复证书、同一成果多页及失败重试不重复计数或奖励；可给旧记录补充材料 |
| 分类边界 | 本人赛课、作品比赛、公开课、指导他人分别判别；行政级别、刊物属性、课题阶段不混用 |
| 档案统一 | 时光轴与按指标视图共用同一档案；类别、级别、阶段渐进筛选；详情预览材料，首版不新增照片库、成长树、荣誉墙入口 |
| 成果报告 | 管理者可按类别、认定级别及阶段汇总并查到教师和记录；无级别／未关联指标单独表达，不强行计分 |
| 摘要有据 | 可选报告摘要依当前筛选与生效数据生成并链接明细；不按材料数推断教学质量，不自动评优排名 |

十二类成果分类沿用统一名称，但不等于十二个考核指标；学校按类别启用必要字段，AI只追问缺项。没有计分映射的合规成果可仅归档，不能借归档绕过指标评价权限或形成未经核实的负面评价。未关联指标的材料只有在学校明确归档权限及审核策略后才进入正式学校档案；未配置时保存为个人待整理材料，不纳入学校报表。

依据用户最新要求，基本个人信息、任职信息、资格证书、工作经历纳入本期档案查看；资料维护和人事系统对接后续设计。职称申报对标、同龄比较、公开荣誉展示和问答式报表不扩入本期。

竞品照片库入口未进入页面，荣誉墙图片为空，实际AI上传识别及后台审核未执行；这些不作为已验证能力。详细覆盖矩阵见竞品体验文档。

### 7.6 管理端衔接及实现分层

学校后台提供组织及账号权限、指标树、评价角色、审核开关、采集字段、计分规则、周期、版本、记录及审核结果。手机端按配置展示可用能力和查询范围，不硬编码精简版角色名单或指标路径。

基础层负责样式令牌和通用交互；公共组件层承载输入、筛选、选人、日期及弹窗；业务层负责指标、对象、权限、状态、计分及报表。数据服务与演示持久化使用同一职责边界。

全校查看、评价及审核是不同权限。管理者查看本校全体教师数据和学校汇总；评价角色限制可提交的指标，审核权限限制可处理的任务。个人草稿不出现在全校列表和报表，管理者不能通过他人档案入口覆盖其个人原文。

### 7.7 手机端规范与专业评审

本轮采用frontend-design-review审视任务层级、渐进披露与可信反馈，并对照[教师手机端UI规范](../../../design-system/teacher-mobile/TEACHER_MOBILE_UI_GUIDELINES.md)。复用项目字号、图标、44像素触控、日期及底部弹窗；档案、教师目录和报表使用纯色分层背景。

现有学生评价“记录、班级、我的”导航服务其他业务；教师发展评价建议四入口，新增报表用于本期管理者全校分析。用户已授权先设计页面并迭代；该四项结构已实现且仅影响新模块，已补入适用规范。复用教师手机端既有令牌与组件，不更换其他模块主题和导航。

## 8. 首版交付与后续

用户已授权先以精简版举例制作记录、完整档案、个人／学校报表、我的及必要详情，再边体验边修改；正式方案选择仍待确认。当前可交互范围见[Demo使用说明](教师评价Demo使用说明.md)。演示预置教师与管理者账号；账号切换和配置模拟位于手机壳外，不向业务用户展示开发备注。

AI演示覆盖日常描述、证书提取、多页归并、分类歧义及重复识别。预置演示数据和真实识别接入的区别由手机壳外工具层标明；业务页展示事实、证据和状态，不展示开发说明。

不同演示账号共享同一持久化数据：教师提交后，管理者可处理需审任务；生效后本人档案与全校报表同步。页面刷新及账号切换后能够追踪结果，不能只修改状态文字。

演示至少覆盖免审记录、需审记录、管理者直接评价、全校教师目录、个人档案及报表、学校到教师的报告查询、本人需审不能自审、指标配置改变后按新版本分流。完整路径见页面结构方案。

真实语音和图片识别、学校管理端、学校正式计分规则及外部业务系统接入在后续单独确认。以精简版举例不代表本期方案已选定，最终学校配置以[方案选型记录](方案选型记录.md)为准。

### 第一版已实现与未接入能力

已实现独立入口、两种身份、完整资料查看、四项导航、全校目录、周期／指标／类别／级别查询、基本个人与学校报表、预置识别分流、审核通过／不通过、修改重提、撤回和浏览器持久化。原始图片定位、真实语音／图片识别、多页归并、批量部分失败、语义去重、跨期全部经历和学年汇总保留为目标要求，尚未接入。第一版报告提供事实统计，不生成大模型摘要。外侧可模拟角色与审核配置，不能据此宣称学校管理端已经实现。
