B的28项是本项目转译，并非国家发布了28项新标准；正式标准有63项基本要求。E只还原截图可见范围，不能据此判断该产品完整指标体系。A、C、D的细化与计分建议也均不代表已经过校本验证或正式发布。

若本轮优先向学校演示提交与审核，建议先比较C与E：C兼顾日常过程，E更贴近证书与成果归档。若围绕玉林项目沟通，优先比较A；若强调标准覆盖选B；若需要更多细分维度和诊断选D。推荐不改变当前待选状态。

## 不同结构如何由后台统一配置

后台配置应支持以下能力，供后续实现使用。本期不制作管理端页面，当前文档不表示这些能力已经实现。

| 配置对象 | 学校可调整内容 | 对手机端的影响 |
| --- | --- | --- |
| 方案模板 | 从A至E复制，保留来源，形成学校自己的方案和版本 | 使用学校启用的方案；不混用别校指标 |
| 指标树 | 两级或三级起步；节点增删、重命名、排序、移动、停用 | AI（人工智能）匹配可提交的末级节点，页面按实际路径展示，不固定五维或三级 |
| 指标含义 | 行为定义、纳入和排除条件、常见材料及匹配示例 | 相似奖项或记录能够解释归属，避免只看关键词 |
| 采集字段 | 名称、日期、机构、角色、学时、附件等必填或选填要求 | 只补充当前指标需要的信息 |
| 录入与审核规则 | 允许录入角色、每项指标统一配置评价角色和是否需审核、管理者可评价及审核范围 | 教师免审自动计分，需审一次通过计分；管理者评价他人提交后同样按指标审核开关处理 |
| 适用人群 | 学段、学科、校区、岗位和发展阶段 | 教师只使用适用指标；审核按范围授权 |
| 评价方式 | 仅归档、事实累计、行为量规、正式结论引用 | 有规则才计算学时或分数，不把所有材料变为能力分 |
| 考核方案 | 指标选择、基础分、上限分、下限分、事件加减分规则、权重、去重、周期 | 同一档案支持不同用途，但每次计算可追溯 |
| 发布与版本 | 草稿、启用、停用、生效时间及历史版本 | 新记录按生效配置；历史结论保留原依据 |

方案模板、学校定制方案、学校考核方案是不同对象。模板解决“从哪里开始”，定制方案解决“学校采集和认定什么”，考核方案解决“本周期如何汇总和评价”。

指标编号在各方案内唯一；保存材料时同时记录学校、方案标识、版本及指标编号，不能仅用C01之类的短编号跨方案查找。复制模板后保留来源映射，历史已认定记录不因更名、移动或停用指标而失去归属。

每个末级指标统一配置评价角色与一个审核开关，适用于允许提交的角色，不按心得、反思、证书分别分流。不同类别仍可使用不同采集字段和计分条件；AI匹配规则，系统执行计算，需审时由管理者一次确认事实与规则。审核通过后不再另行打分。

## 录入职责与通用名称

详见[录入审核与通用文案规则](录入审核与通用文案规则.md)。155项指标均已分别说明教师录入内容、指标级审核要求、管理者录入内容及角色、管理者确认规则；同义成果名称沿用截图的十二个通用类别，未覆盖的类别不强行映射。

## 所有候选方案共用的业务约定

- 免审指标匹配明确、字段完整并通过校验后按规则自动计分入档，不增加确认入档步骤。
- 需审指标自动进入指定角色的队列；审核人员不能审核本人材料。
- 材料真实性认定、能力质量评价、正式师德结论分别明确权限与依据。过程记录入档不自动认定能力优秀。
- 团队成果、学生获奖必须记录本人角色或贡献，不能直接将所有成果归给每位教师。
- 一份材料可关联多个指标，但认定状态和计分贡献分别处理；同一事实去重。
- 指标层级、数量、是否计分均可变化。多指标不要求教师每项上传一份材料，优先复用已有证据。
- 日常持续积累，学期反馈、学年汇总作为发展性方案建议；正式人事及师德周期遵循学校适用制度。
- 学校没有公布评分方法时，只展示档案事实，不展示模拟能力总分或排名。

各方案表中的“免审”表示按已发布规则自动计分入档；“需审核”表示管理者一次通过后系统计分入档。质量类规则须先有明确量规和证据条件，AI不能凭印象给分。来源归集保留认定依据，不增加人工评分任务。

## 选型后的落地

先在[方案选型记录](../方案选型记录.md)确认方案和必要调整，再准备该方案的学校配置、示例材料及审核账号，最后制作手机端。候选方案不自动成为产品中的多学校切换功能，也不要求本期同时实现五套演示页面。

## HTML 展示版维护

[导图与明细](教师评价指标方案-导图与明细.html)包含五套方案、155项指标，支持方案浏览、分支折叠、搜索、维度及录入通道筛选、指标定位与打印。HTML 可离线打开。

逐项定义、加扣分理由和录入审核分工同时保存在各方案 Markdown，为校本讨论稿，未启用正式计分。修改 Markdown 后运行 `python3 scripts/generate-teacher-indicator-html.py` 更新展示版；脚本不改变方案选型状态。

二、三级指标已采用精简展示名：155个末级指标中152个为四字名称，3个复合项保留必要长度。各方案末尾有原名对照，HTML可用原名、简称及通用类别检索。

## 事件计分与汇报字段

[指标字段与事件计分模型](指标字段与事件计分模型.md)定义基础分、上限分、下限分、事件规则与确认流程。精简版新增12项数值演示，基础合计100、上限145、下限25；采用末级求和，不叠加原先的试配权重。其他方案分值待配置。

HTML面向汇报统一显示九列：指标名称、定义、示例、评价人、加分理由、减分理由、基础分、上限分、下限分。技术配置、详细权限与来源保留在Markdown中。默认浏览精简版不代表选定该方案。

## 角色、成果级别与时光轴

Demo统一为教师、管理者两个角色；155项汇报明细按教师通道标明免审／需审核。管理者是学校授权评价他人的权限角色，可兼任教师，不能审核本人需审材料。

[成果级别与成长时光轴设计](成果级别与成长时光轴设计.md)记录竞品只读观察、精简版12项的级别使用方式、配置字段、示例规则及手机端时光轴建议。级别是材料类别启用的记录属性，不增加指标层级。

## 手机端页面结构

[教师手机端页面结构方案](../教师手机端页面结构方案.md)以精简版举例，建议共用记录、档案、报表、我的四个入口。教师看本人，管理者看全校教师数据与学校报表，可查看自己的成长档案。页面按学校指标的评价角色和是否需审核运行，方案仍待选定。
