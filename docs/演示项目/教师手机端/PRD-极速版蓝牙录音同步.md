# 教师手机端极速版：蓝牙录音与同步

更新：2026-11-06。状态：已确定部分已更新交互 Demo；正式同步规则为推荐方案，待产品与厂商联调确认。本文不代表真实硬件、服务端或微信授权已经接通。

## 1. 概要

老师继续以微信小程序使用完整功能，需要麦克风时安装手机极速版。极速版当前只做班级评价，通过 AIREC 麦克风采集课堂及校园场景录音，优先验证实际收音效果、同步可恢复性和老师的操作负担。

Demo 采用手机竖屏布局，不额外适配平板。设备发现、连接、录音清单、本机接收和云端回执均为模拟；本轮不将硬件录音自动变成评价或分数。

## 2. 协作角色

| 角色 | 需要确认的事项 |
| --- | --- |
| 产品负责人 | 试点场景、评价归属、识别后是否人工核对、录音保留与清理规则 |
| 试点老师及学校管理员 | 真实收音环境、借用设备流程、学校与班级权限、录音核对方式 |
| 硬件厂商 | SDK（软件开发工具包）接口、录音编号稳定性、音频格式、传输与清理能力 |
| App 与服务端开发 | 账号复用、真实设备接入、同步恢复、云端防重、故障诊断 |

具体负责人随试点确定，不预设姓名。

## 3. 背景与约束

- 微信小程序功能最全，当前不迁移全部功能到 App。
- 厂商提供 Android（安卓）及 iOS（苹果手机系统）SDK；接口资料与样例尚未纳入本项目，不能据此假定其支持全部同步能力。
- 硬件有 8 GB 存储，支持离线录音，回到办公室连接老师手机后同步。存储容量不等于可用录音时长，时长依赖格式和码率。
- 实机已发现不能切换录入方式，因此本期只支持班级评价；学生评价延后。
- “扫码”已澄清为扫描附近蓝牙设备，不是扫描二维码。
- 公共学生使用的身份授权是独立场景；本期极速版仍是老师登录的 App，不在本轮附带新增学生公共账号体系。

## 4. 目标与验证指标

首轮试点结束时确认：老师能完成首次连接、离线录音、回到办公室同步、核对收音，并在中断后找到继续操作入口。

建议验收目标，须用真机实测，不把 Demo 结果当作硬件结论：

| 目标 | 验证办法 |
| --- | --- |
| 同步完整 | 已结束且可读取的 10 段录音，云端最终可核对 10 段；逐段核对完整性 |
| 重复入库为 0 | 重连、重试、重装、同校换老师后，原 10 段不新增录音记录；未来不重复生成评价与计分 |
| 可恢复 | 分别在接收、上传阶段断开，已完成段保留，恢复后只补未完成部分 |
| 收音可评估 | 每个测试场景记录距离、噪声、佩戴方式及原音频，老师试听判定能否听清班级与事实；阈值在首轮样本后确定 |
| 容易操作 | 试点老师能在简短指导后独立完成连接和同步；记录失败原因、操作耗时及求助次数，作为下一轮改进依据 |

## 5. 目标用户与任务

| 使用者 | 当前任务 | 约束 |
| --- | --- | --- |
| 上课老师 | 少拿手机，通过麦克风采集班级表现，课后同步核对 | 不能依赖课堂有一体机；不能用手机当前班级推定全部离线录音的班级 |
| 校园值日学生 | 持设备在多个场所离线采集，交回办公室 | 采集人和上传老师可能不同；设备不登录微信 |
| 接收设备的老师 | 知道设备是否连接、还有多少待同步、何时可以离开 | 蓝牙连接与手机联网是两件事；到手机不等于到云端 |

## 6. 提供的价值

老师保留熟悉的微信入口，只为硬件安装轻量 App。设备回到办公室后可直观看到待处理量，连接中断后仍能继续；同一段录音在换手机、换老师、重装后有统一记录，减少重复处理与重复计分。

### 7.2 首次连接与日常使用建议

1. 老师登录后，从“我的 → 更多工具 → 蓝牙设备”进入；第一版记录页暂不展示设备状态。从未添加设备时也先进入列表空状态，不直接开始扫描；插图与14像素常规字重的辅助提示“还没有添加设备”整体位于内容区中点上方，底部保留添加设备按钮。
2. 点击底部“添加设备”进入添加子页，开始扫描。真实接入时在此按系统要求申请蓝牙权限；未开蓝牙或权限被拒绝时说明原因并提供恢复入口，不在 App 启动时集中索要权限。
3. 扫描时展示直径280像素、逐层外扩的涟漪，小屏自适应缩小，中心麦克风插图保持原大小；使用不随扩散变粗的0.75像素细描边，并保证浅灰底上的可辨识度。列表标题为“附近的设备”，不重复显示“扫描中”，卡片最小高度56像素；设备结果依次出现且仅含 AIREC 开头的设备。点选连接，成功后返回设备列表并置顶；失败留在添加页，保留错误与重试入口。无结果时提示开机、靠近手机、检查是否被其他手机占用，并允许重扫。
4. 真实接入时，连接后通过厂商接口确认设备身份、就绪状态与录音清单；设备卡上半部只显示麦克风插图与名称。无需同步时，下方白卡显示绿色呼吸小点和“已连接”，不显示“已同步”“无同步任务”、待同步数量或右箭头。未连接时点击箭头直接连接，文案变为“连接中”，原箭头位置显示旋转加载图标；演示连接约2.2秒，禁止重复点击，失败恢复入口。系统蓝牙设置显示已配对，不等于 App 已可读取录音。
5. 已确定：连接或重连成功后，有未保存录音就自动同步，不需要老师点击开始，不提供暂停按钮；无新录音或已保存则保持绿色“已连接”。不擅自切换学校，不重复保存已有录音。
6. 同步时使用橙色呼吸小点和“同步中(已云端保存段数/总段数)”。进度条与文案统一按已云端保存段数除以总段数计算，以300毫秒缓动平滑变化，归零时立即清空；完成后保留约350毫秒的100%收尾，再收起进度条、回到绿色“已连接”，通过公共轻提示显示一次“同步完成”，约1.8秒自动消失。没有任务、重复连接、取消及失败不触发完成提示。后续试听与评价核对另设明确入口。

交互层级：第一版记录页不显示设备图标或状态；设备页以“图片＋名称、下方状态卡”回答“有哪些设备、哪个正在用、是否在同步”，正常同步无需操作，异常时才在卡片内提供重试，不提供详情弹层或逐条录音。添加页负责发现与连接，连接完成自动同步并返回列表。未连接设备的箭头始终用于连接，不显示“查看同步”。

第一版暂不展示记录页设备状态；蓝牙设备页内的连接状态、呼吸小点和同步进度继续保留。

第一版记录页不显示设备状态，配对失败、断网及异常在设备操作页提供明确反馈。设备卡在同步时显示橙色呼吸小点和“同步中(已云端保存段数/总段数)”，例如“同步中(9/10)”，计数表示录音保存段数；下方直接显示总体进度条，读屏可获取接收与云端保存各自段数，不显示右箭头，也不打开弹窗。小点采用6像素实色内圆与12像素同色浅外圆，尺寸固定，只让外圆透明度按2.4秒周期在12%至36%间变化，以深浅对比体现呼吸；减少动态效果时保留静态颜色与文字。

总体百分比统一按“已云端保存段数”除以“总段数”计算，与“同步中(x/总段数)”保持一致；0/10对应0%，6/10对应60%。接收到手机但未保存到云端不计为同步完成，设备卡百分比与进度条共用同一计算规则，不代表剩余时间。待联网时保留已完成段数，网络恢复后自动继续；完成后收起进度条，恢复已连接状态并显示一次完成轻提示。扫描涟漪是表示查找中的不确定动效，与同步的确定进度环分开。

连接或同步期间均可添加、扫描或切换设备，不增加“正在连接，请稍候”“同步完成后，可添加其他设备”等提示，也不禁用添加按钮。扫描独立于连接和同步，进入添加页不打断原设备任务；选中另一台设备时切换会话，停止旧任务后续写入，保留已接收和已保存录音，切回原设备后自动补齐。添加页返回只取消该页未完成扫描与配对，不取消设备列表发起的重连。单设备连接，不承诺多麦克风同时传输。自动同步不等于自动重连，是否自动重连须由厂商接口与实测确认，Demo 不自动抢占其他老师的设备。

添加页与列表空状态使用[麦克风概念插图](../../../mobile-app/assets/airec/microphone-pairing-v1.png)，由内置 imagegen 生成，透明背景，不代表厂商具体外观；[完整生成提示词](../../../mobile-app/assets/airec/README.md)随资源保留。外围动画与百分比由代码控制，不烘焙进图片。

系统配对是否必需、是否需要按硬件配对键、能否自动重连，必须按厂商接口和真机结果给出指引，不能只让老师去系统蓝牙连接就认为流程完成。

### 7.3 连接与同步的状态规则

连接状态与同步状态分开管理。例如蓝牙断开后，已完整接收到手机的文件仍可上传；没有网络时，蓝牙仍可继续接收。

| 场景 | 用户看到的状态与恢复方式 |
| --- | --- |
| 正在读取清单，总数未知 | “正在核对录音…”；不显示虚构百分比 |
| 设备有 10 段，尚未同步 | 连接成功后自动同步，显示橙点、“同步中(0/10)”及真实进度 |
| 正在接收第 4 段 | 已核对并接收 3/10，当前段完整接收且校验后才计为 4/10 |
| 已到手机 10 段，上云 6 段 | 状态卡显示“同步中(6/10)”、总体进度60%；读屏可获取接收10/10、保存6/10，不提示整体完成 |
| 蓝牙断开 | 已接收完整段保留并可继续上云；未接收部分显示重新连接继续 |
| 无网络 | 保留手机副本，提示“等待联网”；联网后自动继续云端保存 |
| 用户离开设备页或返回记录页 | 同步继续，完成后显示一次“同步完成”轻提示；切学校/账号停止原会话，不能把原学校录音放入新学校 |
| 文件校验失败/手机空间不足 | 当前段不算成功；保留设备源文件，说明原因并允许重试；不回滚已完成段 |
| 退到后台、锁屏或 App 被系统结束 | 首期不承诺持续传输；提示保持前台，重新打开核对清单并恢复；平台能力另行实测 |

“核对并接收”包含已由云端确认、无需重新下载的录音，不宣称它们仍存在于当前手机。对于很长的单段文件，SDK 若提供字节进度，再补该段百分比；否则只用真实完成段数，不模拟剩余时间。

### 7.4 卸载重装与重复同步：推荐规则

**防重依据放在云端，不能只靠本机的“已同步”标记。** 原音频是否重复传输，与是否重复生成业务记录要分别处理。

| 10 段录音处于什么状态 | 卸载重装后怎么处理 |
| --- | --- |
| 10 段均已获云端保存回执 | 登录同校后核对云端清单；仍是原 10 段，新增 0 段；设备再提供同一批文件也不重复入库或计分 |
| 10 段只到手机，未上云 | 本机副本可能随卸载丢失；从仍保留原录音的设备重新接收再上云 |
| 4 段到手机，其中 2 段已上云 | 云端 2 段跳过；剩余从本机完整副本或硬件恢复；重装后本机丢失则从硬件补 |
| 云端已保存，但手机未收到成功回执 | 用同一录音编号重试，服务端返回原保存结果，不创建新记录 |
| 设备在原 10 段外新增 2 段 | 已有 10 段跳过，只新增 2 段；不能只比较总数量判断 |
| 老师删除或撤销过由该录音生成的评价 | 保留已处理/已撤销的最小防重凭证，重同步不让评价自动恢复；重新处理须显式操作并可追溯 |
| 手机未上云且设备源也被删 | 无可恢复副本，不能承诺恢复；因此不能接收进手机后就自动删除硬件源 |

推荐落地方式：

- 云端录音唯一标识为“学校 + 稳定设备编号 + 稳定录音编号”。录音编号在设备重启后仍不变，格式化后不能复用旧编号；可采用全局唯一编号，或设备存储代次加递增编号。
- 对文件记录大小、时长和内容校验值；同编号但内容不同作为异常处理，禁止静默覆盖或直接跳过。
- 云端查重、原音频确认与防重记录要形成一致的保存结果；数据库加唯一约束。重复请求返回原记录与状态，网络超时可安全重试。
- AIREC 名称只用于缩小扫描列表，不能作为唯一编号或身份认证。蓝牙临时地址、文件名、时间戳也不能单独承担跨重装防重。
- 若 SDK 没有稳定录音编号，可评估内容校验值加文件信息作为过渡，但可能合并两段内容完全相同的合法录音，不能作为无损方案承诺；优先要求厂商补齐编号。
- 未来评价生成再单独防重：用“来源录音 + 片段编号”追溯每条评价。保存录音、识别、待核对、已生效各有状态；同一录音可以包含多个班级和多条评价，不能把一段录音直接等同一次评价。

此处是本项目的推荐设计；稳定请求编号、重复返回原结果及原子保存的原则可参考 [AWS 的安全重试与幂等设计](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/)。幂等指同一操作重复请求，仍只产生一次业务结果。

### 7.5 同步过程、存储与设备清理

推荐顺序：读取设备录音清单 → 查询云端已有记录 → 接收缺失文件并校验 → 手机持久保存 → 上传并获云端确认 → 如厂商支持，再写设备同步标记。不能在“已到手机”时就给出允许清理的确认。

- 对大容量设备分页读取清单、按段传输，不一次把 8 GB 全部读进内存；开始前检查手机空间和网络。
- 若厂商支持按文件位置续传，则断点续传；若不支持，未完成的当前段重新接收，已完整段不重来。不能在厂商能力未知时承诺按字节续传。
- 只同步已结束、可稳定读取的录音；正在录制的片段下次核对。录制同时同步是否影响收音和传输需实测。
- 本期建议保留设备原录音，不自动清空。后续云端确认后再单独设计清理入口与保留期限；空间不足先提醒，不默默覆盖未保存录音。
- 云端可查询已有记录时先跳过下载；接口不足或无网络时可能发生物理重传，但后台仍须只保存一份业务记录。
- 同一设备被两位老师同时操作时，建议限定一个传输会话，另一端提示正在使用；即使发生重复上传，云端仍须防重。

### 7.6 学校、班级与采集人的归属

建议设备绑定学校，借用给学生时关联采集任务或批次，分别记录采集人/小组、发生时间、同步老师与上传时间；不能把接收设备的老师自动当成全部评价的原始发起人。未知采集人保持未知，待核对，不能编造。

离线在多个班级录入时，约定每段说清“年级班级 + 发生事实”。示例：“三年级2班，早操队伍整齐，做操规范。”录音没有班级、班级歧义、超出学校范围时进入待确认，不按同步手机当前所选班级自动落账。

同校老师的云端防重清单应共享，避免换老师就当新录音；录音访问仍按授权，不因能连接设备就允许查看。不同学校设备应拒绝导入并提示切换到所属学校或由管理员处理，不复制到另一学校。上述设备绑定和学生采集授权尚未实装。

### 7.7 收音验证与评价处理边界

首轮建议先完成原音频上传、试听、采集时间/时长核对。选择课堂授课、早操、走廊和值日巡查等真实环境，记录距离、噪声、是否佩戴及是否丢段；转写仅辅助对照收音，不替代试听。

收音达到可用后，再接班级识别、指标匹配、老师核对、正式计分；无法确认班级或内容的录音保持待处理。现有班级评价界面继续使用原 Demo 数据，硬件同步模拟不会生成新评价，因此本轮没有“误识别就自动扣分”的行为。

### 7.8 厂商必须确认的接口与降级

| 待确认事项 | 对方案的影响及降级 |
| --- | --- |
| 设备如何进入可发现状态，是否需要系统配对；提供何种稳定设备编号 | 决定首次连接指引和学校绑定；不能只靠名称认设备 |
| 文件清单是否含稳定录音编号；重启、删除、格式化后是否复用编号 | 决定跨重装防重能否可靠落地，是进入正式试点前的关键条件 |
| 音频格式、采样率、声道、单段结束规则、是否要专用解码库 | 决定能否上传、试听、识别；不能直接假设蓝牙麦克风会成为系统通用音频输入 |
| 离线文件下载接口、文件大小/校验值、进度、分页、按位置续传 | 决定进度粒度与恢复方式；不支持按位置则从当前未完成段重传 |
| 实时音频和离线录音关系，连接时能否录制，是否自动切换 | 决定是否还需要实时通路；首期可先仅做离线采集后同步 |
| 电量、可用空间、正在录制状态是否可读取 | 有可靠返回才显示；不显示虚构电量、容量或剩余时间 |
| 设备时间、校时和时区，断电后是否保留 | 时间异常标注待核对；上传时间不能冒充发生时间 |
| 已接收标记、云端确认标记、单段删除、误删恢复 | 无相关接口则以云端清单防重，继续保留硬件源，暂不做自动清理 |
| 单设备多手机连接、占用通知、异常断开原因 | 决定重连和占用提示；首期优先单会话 |
| 锁屏/后台的传输限制、权限和最低系统版本 | 两个平台分别实测；先提供前台同步，不承诺后台长时间完成 |

### 7.9 实现分层与可观测性

本次把纯同步规则、设备历史、Demo 存储适配、会话控制与设备子页分开；原记录页保留通用右侧插槽，第一版不挂载蓝牙状态。完成提示由会话回调触发，在应用层复用公共 MobileToast，不把蓝牙业务写入公共弹层或基础录入组件。未来替换厂商及云端适配时沿用清单、进度和回执契约。

问题诊断建议记录设备编号、录音编号、同步批次、阶段、已完成段数、错误码与重试结果；不在普通页面展示内部编号或协议细节。正式日志避免携带录音内容及登录凭证。
