# 教师手机端方案六弥散渐变开发说明

版本：1.0  
日期：2026年10月20日  
适用端：教师微信小程序手机端  
交付目标：复原当前演示中的「方案六 · 红青平衡」与「弥散」组合。

本说明完整定义背景颜色、图层、屏幕适配、页面范围与切换逻辑。开发无需另外阅读演示工程的三个源文件即可实现。本文只定义背景迁移，原有文字、按钮、卡片、图标与业务行为沿用对应页面规范。

| 生产渲染方式 | 实现方式 | 需要的交付内容 |
| --- | --- | --- |
| WebView（网页渲染引擎） | 使用本文的五层渐变样式 | 本说明，包含正向与反向完整代码 |
| Skyline（微信原生渲染引擎） | 建议使用正向、反向两张纯背景图片，按同一规则切换 | 本说明，以及按第7节要求制作的两张背景图 |

本文附带样式代码，不附带背景图片。若生产采用 Skyline，图片制作属于接入前的待办项。目标基础库与微信客户端上的显示效果仍需按第9节验收。

## 2 固定颜色

| 角色 | 十六进制颜色 | RGB（红绿蓝通道） | 用途 |
| --- | --- | --- | --- |
| 主色 A 品牌红 | `#E02727` | `224, 39, 39` | 正向左侧光晕 |
| 辅色 B 清青色 | `#45CED1` | `69, 206, 209` | 正向右侧光晕与底部续色 |
| 点缀 C 金橙色 | `#FA9C00` | `250, 156, 0` | 顶部极淡光晕 |
| 顶部底色 | `#FFF1F1` | `255, 241, 241` | 纵向底色起点 |
| 中部底色 | `#FBFAF9` | `251, 250, 249` | 纵向底色中间点 |
| 下部底色 | `#FFFFFF` | `255, 255, 255` | 纵向底色终点 |

所有百分比透明参数均指“不透明度”：16% 应写作 `0.16`，4% 应写作 `0.04`。只给对应光晕设置不透明度，不给整页或内容容器设置不透明度。

## 3 五层背景的精确构成

设完整背景容器的宽为 W、高为 H，左上角为坐标原点，横坐标向右增加，纵坐标向下增加。下表按照实际绘制顺序由底层到顶层排列。

| 顺序 | 图层 | 位置与尺寸 | 颜色及停止点 |
| --- | --- | --- | --- |
| 1 最底层 | 纵向底色 | 覆盖 W × H，从上向下 | 高度0%为 `#FFF1F1`；52%为 `#FBFAF9`；82%为 `#FFFFFF`；82%至100%保持白色 |
| 2 | 顶部金橙光晕 | 中心 `(0.20W, -0.02H)`；横向半径 `0.44W`；纵向半径 `0.24H` | 中心金橙色4%；径向进度70%处完全透明，之后保持透明 |
| 3 | 右侧青色光晕 | 中心 `(1.08W, 0.34H)`；横向半径 `0.82W`；纵向半径 `0.52H` | 中心青色14%；径向进度74%处完全透明，之后保持透明 |
| 4 | 左侧红色光晕 | 中心 `(-0.08W, 0.24H)`；横向半径 `0.84W`；纵向半径 `0.50H` | 中心红色16%；径向进度72%处完全透明，之后保持透明 |
| 5 最顶层 | 底部续色 | 覆盖 W × H，从上向下 | 高度0%至52%完全透明；52%至100%逐渐增加到青色5% |

参数解释：

- 椭圆尺寸是半径，不是直径。左右光晕的中心位于屏幕外，这是原设计的一部分，不要移回屏幕内。
- 线性渐变角度为 `180deg`，即从顶部向底部。
- 径向进度按椭圆半径计算，不是按页面高度计算。对某个光晕，归一化距离 `d = sqrt(((x-cx)/rx)^2 + ((y-cy)/ry)^2)`；中心为0，定义的椭圆边界为1。
- 光晕不透明度在中心与透明停止点之间线性递减；例如左侧为 `0.16 × max(0, 1-d/0.72)`。
- 使用普通透明叠加，不添加特殊混合模式。保留下面代码的完整图层顺序。
- 没有额外高斯模糊、噪点、纹理、光斑移动或循环动画。弥散感来自椭圆径向渐变本身。
- 最终底部不是纯白。正向底部是白色叠加5%青色，约为 `#F6FDFD`；反向底部是白色叠加5%红色，约为 `#FDF4F4`。

## 4 页面范围与正反向规则

| 页面或状态 | 背景 |
| --- | --- |
| 登录页 | 正向 |
| 记录页中的记录学生 | 正向 |
| 记录页中的记录班级 | 反向 |
| 班级列表中的班级 | 正向 |
| 班级列表中的社团与团队 | 反向 |
| 我的首页 | 正向 |
| 学生详情、班级详情中的学生列表、设置、报表、表单等原有纯色页面 | 保持各页面既有纯色规则 |
| 班主任助理、校长助理等专属角色背景页面 | 保持原有角色背景 |

反向只交换 A、B 两种颜色，不镜像整个背景，也不交换几何参数：

| 项目 | 正向 | 反向 |
| --- | --- | --- |
| 左侧光晕 | 红色16% | 青色16% |
| 右侧光晕 | 青色14% | 红色14% |
| 底部续色终点 | 青色5% | 红色5% |
| 顶部点缀 | 金橙色4% | 金橙色4% |
| 三个光晕的位置、尺寸和透明停止点 | 按第3节 | 全部不变 |
| 纵向底色 | 浅粉 → 暖白 → 白 | 全部不变 |

切换规则：正向完整背景始终以100%不透明度留在底层；反向完整背景覆盖其上。切到反向时，仅将反向层的不透明度从0变成1；切回正向时，从1变成0。

时长为 `320ms`，缓动函数为 `cubic-bezier(0.22, 1, 0.36, 1)`。禁止同时把正向层淡出、反向层淡入，这会使中间帧露出底色。首次进入页面直接设置对应方向，挂载完成后再启用切换过渡，不额外播放背景入场动画。用户开启减少动态效果时直接切换。

## 5 屏幕适配与组件结构

演示基准画布为393 × 852逻辑像素。生产环境使用真实页面完整背景区域的 W、H，继续按百分比计算，不把393 × 852写死为页面尺寸。

1. 背景为公共屏幕层，覆盖顶部状态栏、导航区域背后、正文区域与底部安全区域；业务内容单独避让安全区。
2. 背景与滚动区域为同级元素。背景固定在屏幕上，正文独立滚动，滚动容器保持透明。
3. 不以列表内容高度计算 H，不重复背景，不让渐变随长列表拉伸。
4. 不把导航栏下方重新当作渐变起点，否则所有光晕会向下偏移。
5. 横向百分比参考 W，纵向百分比参考 H；不要把纵向参数全部换成仅随屏幕宽度变化的 rpx（小程序响应式尺寸单位）。
6. 背景层无内边距、无边框，不参与点击，不阻挡正文滚动。
7. 不复制演示手机壳的圆角、外部阴影、模拟状态栏与胶囊。实际微信胶囊由平台提供，内容按设备实际位置避让。
8. 若要求渐变连续延伸到顶部，应采用 `navigationStyle: "custom"` 的自定义导航方式。导航栏高度、安全区与胶囊避让值从实际设备能力获取，不复制演示中的固定数值。
9. 输入键盘出现时建议维持键盘弹出前的背景几何尺寸，由内容层处理避让，避免光晕被压缩。横竖屏或窗口尺寸真实变化时再更新背景尺寸。

建议封装一个公共背景组件，仅接收方向参数。颜色与几何参数集中维护，业务页面只传入当前状态，不各自复制渐变。

## 6 WebView 完整参考代码

以下 WXML（小程序页面结构）展示背景与内容的分层关系。`isReverse` 表示当前是否反向；`transitionReady` 初次挂载时为false，初始状态显示后置为true。业务导航和滚动布局在内容层内接入。

```xml
<view class="teacher-background" aria-hidden="true">
  <view class="teacher-background-panel teacher-background-forward"></view>
  <view class="teacher-background-panel teacher-background-reverse {{isReverse ? 'is-visible' : ''}} {{transitionReady ? 'can-transition' : ''}}"></view>
</view>

<view class="teacher-page-content">
  <!-- 放置已有自定义导航栏、业务滚动区域及底部导航 -->
</view>
```

以下 WXSS（小程序样式）展开了所有颜色，正反向可直接对照。背景尺寸以固定定位容器为准；背景应位于页面根层，避免放进会改变固定定位参考范围的变换容器。

```css
.teacher-background {
  position: fixed;
  top: 0;
  right: 0;
  bottom: 0;
  left: 0;
  z-index: 0;
  overflow: hidden;
  pointer-events: none;
  background-color: #FFF1F1;
}

.teacher-background-panel {
  position: absolute;
  top: 0;
  right: 0;
  bottom: 0;
  left: 0;
  background-color: #FFF1F1;
  background-repeat: no-repeat;
  background-size: 100% 100%;
}

/* background-image 中越靠前的图层，实际显示越靠上。 */
.teacher-background-forward {
  opacity: 1;
  background-image:
    linear-gradient(180deg,
      transparent 52%, rgba(69, 206, 209, 0.05) 100%),
    radial-gradient(ellipse 84% 50% at -8% 24%,
      rgba(224, 39, 39, 0.16) 0%, transparent 72%),
    radial-gradient(ellipse 82% 52% at 108% 34%,
      rgba(69, 206, 209, 0.14) 0%, transparent 74%),
    radial-gradient(ellipse 44% 24% at 20% -2%,
      rgba(250, 156, 0, 0.04) 0%, transparent 70%),
    linear-gradient(180deg,
      #FFF1F1 0%, #FBFAF9 52%, #FFFFFF 82%);
}

.teacher-background-reverse {
  opacity: 0;
  background-image:
    linear-gradient(180deg,
      transparent 52%, rgba(224, 39, 39, 0.05) 100%),
    radial-gradient(ellipse 84% 50% at -8% 24%,
      rgba(69, 206, 209, 0.16) 0%, transparent 72%),
    radial-gradient(ellipse 82% 52% at 108% 34%,
      rgba(224, 39, 39, 0.14) 0%, transparent 74%),
    radial-gradient(ellipse 44% 24% at 20% -2%,
      rgba(250, 156, 0, 0.04) 0%, transparent 70%),
    linear-gradient(180deg,
      #FFF1F1 0%, #FBFAF9 52%, #FFFFFF 82%);
}

.teacher-background-reverse.is-visible {
  opacity: 1;
}

.teacher-background-reverse.can-transition {
  transition: opacity 320ms cubic-bezier(0.22, 1, 0.36, 1);
}

.teacher-page-content {
  position: relative;
  z-index: 1;
  background-color: transparent;
}

@media (prefers-reduced-motion: reduce) {
  .teacher-background-reverse.can-transition {
    transition: none;
  }
}
```

不要对 `.teacher-page-content` 设置整页白色背景。卡片等局部承载面按原规范显示白色即可。上述代码只负责背景分层，业务滚动区域仍使用生产项目已有的布局与高度管理。

## 7 Skyline 图片实现要求

微信官方公开的 Skyline 样式说明指出：径向渐变仅支持圆形，不支持本方案的椭圆；单个 `background-image` 最多支持两个值。因此，第6节的五层椭圆样式不能原样用于 Skyline。将其拆成多个元素只能解决图层数量问题，仍需处理椭圆限制。

优先保持当前视觉时，采用两张预合成图片：

| 项目 | 要求 |
| --- | --- |
| 正向文件名 | `teacher-scheme6-diffuse-forward.png` |
| 反向文件名 | `teacher-scheme6-diffuse-reverse.png` |
| 建议导出尺寸 | 1179 × 2556像素，即演示393 × 852画布的3倍 |
| 文件格式 | PNG，无损，sRGB色彩空间 |
| 图像内容 | 按第3节合成完整五层背景，包含不透明底色 |
| 禁止包含 | 文字、卡片、按钮、手机壳、模拟状态栏、模拟微信胶囊 |
| 展示方式 | 小程序 `image` 组件，宽高铺满背景容器，`mode="scaleToFill"` |
| 切换方式 | 正向图常驻底层，反向图覆盖上方，仅改变反向图的不透明度 |
| 资源加载 | 两张图就绪后启用切换，避免切换时才加载出现空白 |

图片须按精确渐变参数渲染导出，不通过人工涂抹或生成式绘图猜测效果。反向图独立按参数生成，不使用水平翻转。

采用 `scaleToFill`（分别按容器宽高铺满），是因为原算法的横向和纵向尺寸本就分别随 W、H 变化。不要使用会裁切画面的 `aspectFill`，也不要使用可能留空的 `aspectFit`。图片缩放会产生采样差异，应在目标真机上检查色阶与过渡。

若背景需在更大尺寸窗口中展示，可提高图片输出分辨率，但不得改变归一化坐标和透明参数。图片层仍应位于正文下方，不承担点击事件。

## 8 生产接入与原规范衔接

当前演示通过 `schemeId: 'scheme-6'` 与 `styleId: 'diffuse'` 启用方案六。生产应把该组合固化为本次迁移范围内的公共背景配置，不依赖演示预览控件传参，也不把配色选择控件带入教师业务页面。

现有工程中存在两处历史差异，需要在生产迁移时同步收敛：

- 通用背景规范仍有“品牌红与辅助橙”的描述。本次方案六的右侧主光晕为清青色，金橙仅作顶部4%点缀，应按本文对应参数更新范围内的描述。
- “我的”页在没有预览参数时，存在方案八「红蓝清晖」的回退。本次范围内应明确使用方案六，避免记录页为红青、我的页仍为红蓝。

只调整第4节明确列出的氛围页面。不得顺带覆盖纯色详情页、报表、表单及专属角色背景。公共背景组件集中维护参数，页面只负责方向状态；演示代码内借用的图表颜色，在生产中应通过独立背景语义配置引用，避免以后修改图表色时连带改变页面背景。

## 9 验收清单

- [ ] 在393 × 852逻辑像素背景区域下，正向、反向均与本说明参数一致。
- [ ] 正向左红右青；反向左青右红；反向的顶部金橙位置不变。
- [ ] 底部保留5%续色，不额外叠加纯白收净层。
- [ ] 三个椭圆的半径没有误当成直径，屏幕外光晕中心没有被移入屏幕。
- [ ] 滚动长列表时，背景不移动、不重复、不按内容高度拉伸。
- [ ] 顶部渐变连续，导航与胶囊避让正常，底部安全区没有背景接缝。
- [ ] 正反向切换为320ms；正向底层始终完整可见，切换中无闪白。
- [ ] 快速连续切换时可从当前不透明度继续过渡，没有背景重建闪烁。
- [ ] 初次进入直接显示正确方向；减少动态效果时直接切换。
- [ ] 不改变文字、卡片、按钮等内容的不透明度；背景不拦截触摸与滚动。
- [ ] 至少覆盖一款 iOS 与一款 Android 真机，以及不同宽高比；检查目标最低微信客户端与基础库版本。
- [ ] Skyline 图片路径下，两张图已就绪、没有有损压缩色块、没有裁切或留白。
- [ ] 纯色页面和专属角色页面保持各自原背景。
