# PRD-班主任助理

> 文档版本：V1.0
> 更新日期：2026-08-12
> 适用端：教师手机端
> 文档状态：统一产品需求基线

## 1. 摘要

班主任助理是面向班主任的统一人工智能入口。学校可分别开通学生评价和班级评价，页面根据实际能力组合学生问题、班级数据面板和班级问题，不要求老师先选择分析模式。

学生评价与班级评价保持独立的数据口径和业务实现，但共用一个入口、一个班级上下文和一致的人工智能交互外壳。“班主任助理 V2”不再作为用户可见产品名称。

## 2. 联系人

| 角色 | 负责人 | 主要职责 |
|---|---|---|
| 产品负责人 | 待补充 | 确认能力组合、问题文案和验收口径 |
| 学校业务负责人 | 待补充 | 确认学生评价与班级评价开通范围 |
| 班主任代表 | 待补充 | 验证信息层级和问题是否符合日常任务 |
| 后端研发 | 待补充 | 提供能力权限、学生评价和班级评价数据工具 |
| 人工智能研发 | 待补充 | 实现问题路由、工具调用和结果校验 |
| 教师端研发 | 待补充 | 实现统一入口、能力组合和报告承接 |
| 测试负责人 | 待补充 | 覆盖三种能力组合及数据隔离 |

## 3. 背景

学校按 SaaS（软件即服务）方式选择开通学生评价、班级评价或两者。旧方案把两类能力分别命名为“班主任助理”和“班主任助理 V2”。当学校同时开通时，“我的”页会出现两个相同角色的入口，老师需要先判断应进入哪个助理，违背 Agent（智能助理）应主动理解任务的预期。

两类能力不能简单合并成一组问题：

- 学生评价已有两项高价值任务，分别生成本周行动建议和教师评价复盘。
- 班级评价已有本周数据面板、三个快捷问题和自由对话。
- 两类数据来源、周期、报告协议和历史记录不同，不能混用统计口径。

因此本次统一产品入口与页面结构，同时保留两类能力的业务边界。

## 4. 目标

### 4.1 产品目标

1. “我的”页最多只出现一个“班主任助理”入口。
2. 老师进入后不需要选择学生评价或班级评价模式。
3. 页面根据学校开通能力自动组合内容，未开通能力不展示占位、禁用态或说明。
4. 学生问题保持更高信息层级，班级问题作为输入区附近的轻量快捷提问。
5. 两类能力使用同一班级上下文，但数据查询、回答和历史记录保持隔离。

### 4.2 关键结果

| 指标 | 首版目标 |
|---|---:|
| 双开学校的班主任助理入口数 | 1 个 |
| 三种能力组合页面正确率 | 100% |
| 未开通能力误展示率 | 0% |
| 学生任务原有报告链路可用率 | 100% |
| 班级数据与对话原有链路可用率 | 100% |
| 学生与班级数据串用事件 | 0 次 |

## 5. 用户与场景

### 5.1 用户

- 已开通学生评价的班主任或授权副班主任。
- 已开通班级评价的班主任或授权副班主任。
- 同时使用两类评价服务的班主任或授权副班主任。

### 5.2 能力组合

| 学校开通能力 | 页面内容 |
|---|---|
| 仅学生评价 | 欢迎区 + 2 个学生评价问题 |
| 仅班级评价 | 欢迎区 + 班级数据面板 + 输入区上方 3 个班级评价问题 + 对话输入 |
| 学生评价和班级评价 | 欢迎区 + 班级数据面板 + 中部 2 个学生评价问题 + 输入区上方 3 个班级评价问题 + 对话输入 |
| 两者均未开通 | 不显示班主任助理入口 |

## 6. 价值主张

### 6.1 对老师

- 只需要识别一个班主任助理，不需要理解产品版本。
- 常用的学生任务在内容区直接可见，班级问题靠近输入控件，层级与使用频率一致。
- 不需要先选模式；点击预设问题或直接提问即可。

### 6.2 对学校

- 开通哪类服务，就只展示对应能力。
- 同时开通不会产生重复入口，也不会丢失原有能力。
- 后续可继续给统一 Agent 增加数据工具，不需要再新增助理版本。

## 7. 解决方案

### 7.1 统一入口

入口固定为：`教师手机端 → 我的 → 管理工具 → 班主任助理`。

- 图标、人工智能角标和角色色沿用班主任助理。
- 页面和入口均不得出现“V1”“V2”“学生版”或“班级版”。
- 旧权限值在迁移期继续兼容，但前端菜单必须归并成一个入口。

### 7.2 页面结构

页面从上到下按以下顺序组合：

1. 顶部返回。
2. 问候文案与班主任助理形象。
3. 当前班级上下文卡片：存在多个带班班级时顶部提供班级切换，单班级时不展示控件及占位；卡内按开通能力组合班级评价数据面板和学生评价能力入口。
4. 当前会话内容。
5. 班级评价预设问题，仅班级评价已开通时展示。
6. 语音或文字输入，仅当前已支持自由对话的班级评价能力开通时展示。
7. 人工智能内容声明。

页面不增加模式切换、能力标签或“你可以这样问”等解释文案。概览态标题栏不展示班级切换；切换控件收纳在当前班级上下文卡片中，使控件与其控制的数据及能力处于同一视觉范围。
页面背景使用覆盖状态栏与内容区的连续整屏渐变，不随正文滚动。班级评价快捷问题、输入控件和人工智能内容声明组成固定底部栏；中间内容独立滚动，最后一条消息不得被底部栏遮挡。

当前班级上下文卡片采用一层总卡与内部内容块：只有老师存在多个带班班级时，顶部才展示无底色、无阴影的正文级班级切换；单班级不展示控件和占位。总卡使用较实的玻璃表面承载共同班级上下文；班级评价数据使用带轻角色底色和环境阴影的卡内数据区，并相对总卡主动缩进；学生评价能力使用更窄的独立白色操作块，并与总卡底边保留明确间距。数据卡突出总分，年级排名和学校排名作为次级信息，底部只保留分类入口，不为视觉装饰增加分析结论。数据标题及两项报告入口使用克制的语义图标增强识别。允许这一级嵌套以表达共同班级上下文，但不得在内部内容块继续嵌套卡片。

### 7.3 学生评价能力入口

学生评价能力位于班级上下文卡片中，使用两项完整宽度的单行高层级操作。文案直接概括报告内容，不向老师暴露“学生评价”等后台能力分类：

1. `本周学生情况洞察与班级跟进建议`
2. `上月评价记录复盘与改进建议`

第一项进入现有“本周行动建议”，第二项进入现有“我的评价复盘”。两项能力的生成条件、报告结构、历史记录和数据口径继续遵循原学生评价能力说明。入口只保留一行文字和右箭头，不增加第二行描述或可见分类标题；文字使用正文级字号和中等字重，避免长文案形成标题式压迫感。

点击学生能力时使用班级上下文卡片中的当前班级，不再次弹出班级选择。若老师在卡片顶部切换班级，本周数据和两项学生能力同步使用新班级。

进入对应的“本周行动建议”或“我的评价复盘”后，标题栏中间展示当前班级并支持切换。切班后立即加载目标班级对应的当前报告或数据不足状态；退出正在查看的报告示例，不继承上一班级的生成反馈。首页、两类学生报告和往期记录共用一个当前班级状态。

### 7.4 班级评价数据面板

数据面板只在班级评价已开通时展示，继续提供本周总分、年级排名、学校排名、分类数据和周数据子页面。详细规则继续遵循班级周评分析能力说明。

### 7.5 班级评价预设问题

班级问题位于对话输入控件上方，使用内容自然定宽的横向滑动按钮：

1. `班级评价主要扣在哪？`
2. `班级评价较上周哪项变化最大？`
3. `根据班级评价，下周优先关注什么？`

三个问题属于低层级快捷提问，问题本身明确数据来自班级评价，避免双开状态下与学生评价能力产生歧义。问题不与学生能力入口混排，也不增加分类标题。老师点击后直接进入同一页面的对话流。回答后的连续追问仍在输入控件上方更新。

### 7.6 对话与数据路由

- 当前首版只有班级评价开放自由对话，因此仅班级评价开通时显示输入控件。
- 学生评价自由对话后续开放后，仍复用同一输入控件，由编排层根据问题选择学生评价或班级评价工具，不新增模式切换。
- 学生评价问题继续进入对应报告；班级评价问题进入当前会话。
- 两类数据工具必须分别校验权限和数据范围，模型不得自行跨口径计算。
- 当前班级变化时清空班级评价会话，学生报告历史不受影响。

### 7.7 权限与兼容

目标权限模型使用统一能力和数据范围：

```ts
headteacherAssistantEnabled: boolean
evaluationScopes: ('student' | 'class')[]
```

迁移期兼容旧菜单权限：

| 旧权限配置 | 统一入口 | 能力范围 |
|---|---|---|
| `headteacherAssistant` | 显示 | 学生评价 |
| `headteacherAssistantV2` | 显示 | 班级评价 |
| 两者同时存在 | 只显示一次 | 学生评价 + 班级评价 |
| 两者均不存在 | 不显示 | 无 |

前端不得把旧权限编号直接映射为两个菜单项。后端完成新权限迁移后，可删除旧编号兼容逻辑。

### 7.8 数据与状态隔离

- 当前班级由统一页面维护，学生任务和班级数据共同消费。
- 学生周建议、学生评价复盘、班级周报和班级对话分别保存。
- 不因打开学生报告生成班级报告，不因班级对话改写学生报告。
- 每类报告继续保存自己的数据快照和提示词版本。

### 7.9 异常状态

- 单项能力数据不足时，只在该项操作后反馈，不影响另一项能力展示。
- 班级评价数据暂不可用时保留页面和输入能力，数据面板显示对应缺省态。
- 学校取消某项能力后，该项入口立即隐藏；历史数据的保留与访问期限由学校数据策略决定。
- 两项能力均取消后，“我的”页不显示班主任助理。

### 7.10 详细能力文档

- 学生评价报告规则：`docs/PRD-班主任助理本周行动建议.md`
- 班级评价数据、周报与对话规则：`docs/PRD-班主任助理V2-班级周评分析Agent.md`

上述文档是能力子规范。若入口、能力组合、页面顺序或命名与本文冲突，以本文为准。

## 8. 发布

### 8.1 首版

- 合并“我的”页入口。
- 兼容旧权限并生成学生、班级两种能力范围。
- 使用当前班级评价对话页作为统一外壳。
- 接入两个学生评价问题和现有报告链路。
- 覆盖仅学生、仅班级和双开三种状态。
- 删除所有用户可见的“班主任助理 V2”名称。

### 8.2 后续版本

- 后端切换为统一权限字段并停止下发旧菜单编号。
- 学生评价开放自由对话，接入统一问题路由。
- 支持在一次自由提问中按需联合查询两类数据，但回答必须说明统计对象和周期。

### 8.3 不在首版范围

- 在页面中增加学生评价与班级评价模式切换。
- 把五个预设问题改写成一组融合问题。
- 把学生评价报告历史与班级评价周报历史合并存储。
- 自动生成报告或主动推送结论。
