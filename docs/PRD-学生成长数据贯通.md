# PRD-学生成长数据贯通

> 版本：V2.5
> 更新日期：2026-08-10
> 适用端：学校PC后台、教师手机端、家长手机端
> 当前阶段：产品方案确认，进入交互Demo调整
> 关联文档：`PRD-教师端问卷采集.md`、`PRD-学生成长档案.md`

## 1. 摘要

学生成长数据贯通用于连接成长数据设置、问卷采集、PC导入、学生详情、成长档案和期末报告。标准字段由运营平台统一内置，学校PC后台只负责启用本校要使用的字段，不创建字段、不做字段映射。学校启用一次后，问卷采集、PC导入、教师手机编辑和档案设计共同读取同一份启用结果。

首期教师端使用统一采集能力。老师点击新建后先选择由老师或家长填写，再选择`按档案采集`或`自定义采集`：

1. `按档案采集`：整体选择一份学校已启用档案，完整继承并锁定档案的分组、字段、顺序和必填规则。成长字段写入成长记录，自定义档案字段按稳定字段标识合并到学生当前档案。
2. `自定义采集`：自由组合普通题目和本校已启用成长字段。普通题目只保留本次答卷和统计，成长字段按记录日期沉淀为学生成长记录。

两种创建方式互斥。按档案采集不能增删字段、调整分组或混入自定义题目；档案之外的信息另建自定义采集。完成方式只决定任务接收人和记录形态，不决定数据去向。首期信息主体固定为学生，平台不根据自定义题目名称猜测或建立数据项关联。

学校启用档案后，该档案进入老师的可采集范围，不会自动为每名学生生成空档案。学生首次完成档案填写后建立当前档案；以后再次填写只更新这一份，不按任务、提交日期或学期创建同名档案。档案设计只配置`仅填写一次 / 可重复填写`，该设置只控制能否再次发起。每次成功写回都保存当时的档案内容、业务数据更新日期和来源；期末报告再根据平台预置的报告内容方案生成结构化证据包，交给AI（人工智能）生成文字。

## 2. 问题

1. 身高、体重等信息采集后，老师仍需到学生详情重复录入。
2. 身高、体重会连续更新，如果直接复制进档案，会丢失测量时间和历史变化。
3. 学校难以理解数据项关联、档案映射和报告数据来源等技术概念。
4. 体检数据可能来自PC批量导入，不一定来自问卷；以问卷作为唯一数据入口无法承接历史数据和外部系统数据。
5. 体检数据包含身份证号和健康结论，必须限制用途、权限和AI输入范围。

## 3. 用户与职责

| 角色 | 主要职责 |
|---|---|
| 平台 | 维护标准成长数据项、成长信息模板、档案模块和报告取数规则 |
| 学校管理员 | 在PC后台启用本校字段，管理导入权限和导入批次 |
| 校医或数据管理员 | 在PC端导入本校已启用的成长数据，处理匹配与异常 |
| 有学生权限的老师 | 在手机端查看学生成长数据；有健康数据管理权限时可修正或新增体检记录 |
| 家长 | 填写学校发起的普通题目、成长字段和档案带入字段 |
| 报告管理员 | 选择报告内容模块，生成并发布期末报告 |

## 4. 目标与非目标

### 4.1 目标

1. 本校已启用的成长字段完成后自动进入学生详情，不要求老师重复录入。
2. 同一学生的身体、视力、体能和健康数据按发生时间连续保存，可查看历史和变化。
3. PC成长数据导入完成匹配、格式校验、重复识别和异常处理后才写入学生记录。
4. 教师手机端可以查看单个学生的成长数据，并在授权范围内修正或新增记录。
5. 同一学生和同一档案只维护一份当前档案；档案中的成长字段保存本次采集值、记录日期、来源和版本，不随后续其他成长记录自动改写。
6. 期末报告只读取经规则筛选的结构化证据，不读取整份问卷或身份证号。
7. 学校端只显示字段名称、分类、格式和启用状态，不出现内部编号、字段关联和证据包等技术配置。

### 4.2 非目标

首期不包含：

- 学校自建标准成长数据项。
- 自定义问卷题目关联标准数据项。
- 根据“身高”等自定义题目文案自动猜测字段含义。
- 学校自由配置任意问卷进入档案或报告。
- 手写签名图像；首期使用账号身份、确认人和确认时间完成业务确认。
- 将身份证号、签名信息或原始健康结论默认发送给AI。
- 手机端批量导入Excel（电子表格）或处理错误学生匹配。
- 学期目标采集、确认、版本、调整和期末回顾；该能力暂缓，待业务方明确后按独立固定功能设计。

## 5. 核心概念

| 学校看到的名称 | 系统内部含义 |
|---|---|
| 成长数据 | 统一采集编辑器中可选择的平台预置字段页签 |
| 成长数据设置 | 学校从运营平台内置目录中启用本校要使用的字段 |
| 预置成长字段 | 已绑定标准数据结构、单位、范围和时间语义的可录入字段 |
| 普通题目 | 只形成一次性答卷和统计的自定义题目 |
| 身体成长 | 身高、体重、BMI（身体质量指数）及其测量历史 |
| 健康检查 | 视力、戴镜类型、体检结论和体检日期 |
| 档案内容 | 手动填写字段或平台预置成长数据字段 |
| 按档案采集 | 以一份已启用档案作为本次采集的完整内容标准，任务内不可拆改 |
| 自定义采集 | 不使用档案，自由组合普通题目和学校已启用成长字段 |
| 记录日期 | 成长记录实际发生的日期，用于排序、趋势和档案取值，不等同于提交时间 |
| 档案数据更新日期 | 当前档案本次业务内容所属的日期；有成长字段时取任务记录日期，否则取学生提交日期 |
| 当前档案 | 某名学生在某个档案标准下已经形成的唯一当前内容，尚未填写的已启用档案不构成学生档案 |
| 更新记录 | 当前档案历次有效填写、纠错的日期、来源和操作人追溯信息 |
| 报告内容模块 | 期末报告希望分析的主题及其固定取数规则 |

## 6. 总体流程

```text
采集任务中的成长字段 / PC导入 / 教师手机编辑 / 档案补录
  ↓
标准学生成长记录
  ↓
学生详情展示实时有效值和历史
  ↓
按档案采集或老师直接填写
  ↓
建立或更新学生唯一当前档案
  ↓
期末报告按内容模块生成证据包
  ↓
AI生成报告，保存输入和提示词版本
```

采集任务中的普通题目只进入问卷结果和学生采集记录，不进入上述链路。只有按档案采集中明确绑定的档案字段才合并到当前档案。档案成长字段仍先写入标准成长记录，再将本次值、记录日期、来源和版本保存到当前档案快照中。

## 7. 标准成长数据

### 7.1 首期预置范围

运营平台同时定义成长字段和一级分类，学校只启用或禁用具体字段，不修改分类、字段含义或排序。分类服务于学校后台配置、问卷采集、档案设计和手机录入的统一查找路径，不改变字段键和成长记录存储结构。

| 分类 | 当前字段 | 分类判断 |
|---|---|---|
| 生长发育 | 身高、体重 | 描述学生随时间变化的身体形态，避免“身体成长”与整个成长数据概念混淆 |
| 视力健康 | 左右眼裸眼视力、左右眼矫正视力、戴镜类型 | 同属视力筛查和矫正管理，保持一组便于成套选择 |
| 体质测试 | 肺活量、50米跑、坐位体前屈、一分钟跳绳、一分钟仰卧起坐、立定跳远、长跑成绩 | 同属学生体质健康测试；“体质测试”可同时覆盖身体机能和运动素质，比“体能测试”边界更准确 |
| 健康体检 | 健康结论 | 承接常规体检结论及未来扩展的健康检查字段，与单独的视力和体质测试区分 |

- 分类顺序由运营平台维护，所有使用成长字段的页面必须复用，不能在采集或档案侧另建分类。
- 手机端选择器先展示分类标签和分类内字段数量，每次只展开当前分类；切换分类时保留其他分类的已选字段，并在分类标签反馈已选数量。
- 本期不增加“全部”分类和搜索框。单分类字段继续增长到难以浏览时，再按真实目录规模评估分类内搜索，避免低频能力侵入当前选择流程。

#### 基础信息

- 姓名、性别、出生日期、学号、班级。
- 基础信息只有一个当前有效值；成长采集和体检导入只用于匹配和核对，不直接覆盖姓名、班级等主数据。

#### 身体成长

- 身高，单位厘米。
- 体重，单位千克。
- BMI，根据身高体重计算，不作为独立手工维护字段。
- 每条记录必须保存记录日期；身体成长页面显示为测量日期。日期是记录元数据，不作为学校可选择或启停的成长字段。

#### 健康检查

- 裸眼视力左、右。
- 矫正视力左、右。
- 矫正戴镜类型。
- 体检结论原文及结构化标签。
- 健康检查记录的记录日期在页面显示为体检日期。

#### 体能测试

- 肺活量。
- 50米跑。
- 坐位体前屈。
- 一分钟跳绳。
- 一分钟仰卧起坐。
- 立定跳远。
- 长跑成绩。

### 7.2 字段启用规则

入口：学校PC后台 → 数据中心 → 成长数据设置。

- 运营平台维护完整字段目录、类型、单位、范围、选项和敏感级别。
- 学校只能启用或停用字段，首期不能新增、改名或改变单位。
- 只要字段处于启用状态，就必须同时出现在新建问卷的成长数据选择、PC导入模板、教师手机新增记录和新建档案的成长数据选择中，禁止各入口再做业务能力过滤。
- 停用只影响以后新建和录入；已发布采集任务、历史成长记录、档案快照和报告快照继续保留。
- BMI、变化趋势、日常评价摘要等系统生成项不进入可录入字段目录，由系统按依赖和规则生成。

### 7.3 通用记录规则

每条连续成长记录至少保存：

```text
学生编号
记录类型
记录日期
有效值
采集来源
来源任务或导入批次
创建人和创建时间
当前版本
修正记录
```

- 记录日期表示测量、检查或测试实际发生的日期，提交时间只用于审计，不参与新旧排序。
- 记录日期不能为空。问卷、导入或手机新增缺少记录日期时必须阻止保存，不能用提交时间、导入时间或系统当前日期兜底。
- 读取最近值时先按记录日期倒序；同一来源记录被修正时再按版本倒序。
- 同一学生、同一字段、同一记录日期出现不同来源和不同值时进入冲突处理，不按最后提交时间静默覆盖。
- 手机端修正同一次体检时更新当前有效版本，系统保留导入原值和修改前后内容。
- 后续重新测量必须新增记录，不得覆盖上一次记录。
- 草稿档案和未发布报告读取当前有效版本；已成档快照和已发布报告不自动改写。

### 7.4 问卷记录日期

- 一份采集任务只有一个成长记录日期，任务内所有成长字段共用该日期。
- 添加第一项成长字段后，系统自动生成记录日期规则，不把它作为可改名、复制或删除的普通题目。
- 本期MVP（最小可行产品）由创建老师在发布前直接选择记录日期，不提供日期方式选项；老师或家长填写端均不展示日期题。
- 同一任务中的普通题目不受记录日期影响。
- 产品不提供“成长数据组”概念，也不支持在一份任务内配置多个成长记录日期；不同日期的数据必须使用不同采集任务。

## 8. PC成长数据导入

### 8.1 入口与权限

入口：学校PC后台 → 数据中心 → 成长数据导入。

只有具备`导入健康数据`权限的用户可以新建导入；具备`管理导入批次`权限的用户可以查看批次和处理错误匹配。

### 8.2 导入流程

```text
选择文件
  ↓
识别固定模板和工作表
  ↓
按学生匹配并标准化字段
  ↓
识别重复、异常和未匹配记录
  ↓
用户确认
  ↓
写入学生体检记录并保存导入批次
```

首期支持平台提供的固定模板。模板列由本校已启用字段生成，学校不手动建立字段映射；未启用字段不能通过导入写入。

### 8.3 匹配与去重

- 优先使用平台学生编号或受保护的证件标识匹配。
- 无稳定编号时使用姓名、班级进行候选匹配，并要求人工确认冲突。
- 身份证号只用于匹配和审计，不进入学生详情普通页面、档案正文和AI输入。
- 记录唯一性按`学生编号 + 体检类型 + 体检日期`判断。
- 同一文件不同工作表出现相同记录时只保留一条，并在导入预览中显示重复数量。
- 已存在完全相同记录默认跳过；值不同的同键记录进入冲突处理，不能静默覆盖。

### 8.4 格式处理

- 数字和日期即使在Excel中保存为文本，也必须转换为标准类型。
- 身高、体重和视力按平台范围规则校验。
- BMI按标准公式重新计算，附件值仅用于差异核对。
- `测不出`等特殊值保存为明确状态，不伪装成数字。
- 混合了视力值和屈光度的内容进入待确认，不自动拆分错误数据。
- 体检结论保留原文，并按平台规则提取视力异常、龋齿、偏瘦、超重、肥胖等标签。

### 8.5 导入结果

导入完成页展示成功写入、重复跳过、未匹配、格式异常数量，以及导入批次、操作者和完成时间。

## 9. 教师手机端

### 9.1 信息架构

学生详情保留`成长概览 / 成长报告 / 采集记录`三个页签，不新增顶部页签。

`成长概览`增加：

1. `成长数据`：本校已启用字段的最近值、记录日期和历史记录。
2. `健康检查`：最近体检日期、视力摘要、戴镜类型和体检结论摘要。

模块默认只展示足以判断的摘要；点击进入独立详情页查看完整历史。

### 9.2 成长数据详情与编辑

- 成长记录按日期倒序排列。
- 新增时先选择本次要录入的已启用字段，再填写具体数值，避免一次展示全校全部字段。
- 详情展示本次实际填写字段、来源和版本；修正时保留该次记录的字段快照。
- 编辑入口位于内容区更多菜单，不放在小程序标题栏。
- 完整体检编辑使用独立页面，避免复杂表单挤入底部浮层。
- BMI只读并随身高、体重重新计算。
- 学生身份和错误匹配不能在体检编辑页修改。
- 手机端保存修正后展示有效值，后台保留原始导入值和修正历史。
- 新的测量使用`新增记录`，不能通过编辑旧记录制造新的成长数据。
- 无`编辑健康数据`权限时不展示编辑和新增入口。

## 10. 暂缓能力

学期目标不作为问卷或成长字段进入本期范围。原因是同一学生同一学期应存在唯一有效目标，并且必须先明确目标版本、调整、作废、回顾以及多人协作规则；通用问卷允许同一学期重复发起，无法保证哪一份提交是正式目标。

后续应结合业务方访谈，将学期目标评估为独立固定功能，而不是继续扩展通用问卷。本期页面、数据模型、档案字段和期末报告输入均不展示学期目标预告或禁用项。

## 11. 成长档案

### 11.1 模板配置

学校在“添加内容”中切换`手动填写`和`成长数据`。手动填写提供文字、单选、多选、日期和数字；成长数据直接读取学校PC后台已启用字段，与问卷和导入使用同一字段目录。

学校可以从已启用字段中决定档案包含哪些成长字段，以及哪些字段必填；字段的数据来源、时间语义、单位和计算规则由平台维护。系统生成项由平台按依赖提供，不作为可录入字段混入问卷或导入模板。

档案基础设置只保留`仅填写一次 / 可重复填写`，默认仅填写一次。不配置生成周期、归属周期或成长数据范围。成长字段的记录日期在发起具体采集时确定，不由档案设计预先指定一段自动取值范围。

### 11.2 当前档案与快照

- 已启用档案只进入老师可选的采集范围；学生档案首页只展示该学生已经形成的档案，不铺出尚未填写的空档案。
- `学生编号 + 档案模板编号`构成当前档案唯一关系。多次有效提交更新同一份档案，不按采集任务、提交日期或学期生成同名副本。
- 档案中的手动字段只合并本次有效答案，未填写的选填字段不清除已有值。
- 档案中的成长字段保存本次采集值、记录日期、来源记录和数据版本。问卷、PC导入或手机编辑以后产生的其他成长记录，不自动改写该档案快照。
- 打开已有档案编辑属于纠错，覆盖当前档案并保留操作记录；不创建第二份同名档案。

### 11.3 填写与更新

- 学生没有该档案时，首次有效保存直接建立当前档案。
- 已形成且配置为`可重复填写`时，可以从学生档案的`新增档案`入口再次填写，提交后更新当前档案并保留更新记录。
- 已形成且配置为`仅填写一次`时，不允许从新增入口再次建立；仍可以打开已有档案纠错。
- 同一档案已有待填写采集任务时，新增入口显示`待填写中`并直接进入原任务，不创建并行任务。

### 11.4 通过采集更新当前档案

- 学生当前档案提供`发起采集`，进入与问卷采集完全相同的创建流程。系统预选当前档案，只要求老师选择填写人。
- 老师也可以从问卷采集新建任务，先选择填写人，再选择`按档案采集`或`自定义采集`。两处入口只改变创建起点，不创建两套任务模型。
- 按档案采集完整展示档案的成长字段和自定义字段，并继承布局模式、分组顺序、字段所属分组、题型和必填规则，形成任务结构快照。
- 按档案采集不允许逐项移除、继续添加、改名、排序、移动字段、切换分组模式或新增分组。需要采集档案外信息时另建自定义采集。
- 姓名、班级等系统已有信息不生成填写题，也不在创建页展示自动带入规则。
- 发布时冻结档案编号、版本、布局、分组、字段顺序、必填规则和字段稳定标识。提交时成长字段写入学生成长记录，自定义档案字段合并到当前档案。
- 合并采用局部更新：只覆盖本次实际提交的档案字段，当前档案中未出现在任务里的字段保持不变。
- 学生已有当前档案时，以当前值为基础合并本次提交，避免更新一个字段后其他历史内容丢失。
- 老师填写和家长填写使用同一写回规则。填写人变化不改变字段去向。
- 每次成功写回都更新当前档案的业务数据更新日期：任务包含成长字段时，取任务级记录日期；不含成长字段时，取该学生实际提交日期。
- 档案的`仅填写一次 / 可重复填写`只决定能否再次发起填写，不决定是否产生数据更新日期。

### 11.5 档案采集来源与复用

- 问卷采集只能选择本校已启用且未删除的档案模板。模板提供字段结构，不提供一份可被全班复制的学生答案。
- 填写人属于采集任务，不属于档案模板或档案分组。档案设计不增加老师、家长或双方填写配置；同一模板可以分别用于老师任务和家长任务。
- 具体填写人打开学生任务时，系统按`学生编号 + 档案模板编号`读取当前档案，并把本次包含的档案手动字段预填到表单中；尚未形成档案时保持空白。
- 身高、体重等成长字段不读取最近值作为答案。填写端保持空白，本次提交按记录日期生成新的成长记录；最近值只用于学生详情和档案实时展示。
- 一份采集任务最多保存一个档案模板编号和一份字段快照，同一模板不能重复加入。同一档案模板可以跨任务、班级和学期重复使用，不因为已经创建过任务而失效。
- 按档案采集整体使用一份模板，不存在向任务再次添加档案字段或成长字段的入口。
- 同一档案可跨任务、班级和学期使用。同一学生和同一档案存在收集中且尚未完成的任务时，新任务默认跳过该学生并继续使用原任务，不按字段类型放开并行采集。
- 模板后续修改、停用或删除不改变任务已保存的字段快照。停用模板只影响新任务选择，已保存草稿和已发布任务可以继续完成。
- 采集答案只合并到当前档案，同时保留本次更新日期、来源和操作人供后续追溯。

## 12. 期末报告

### 12.1 学校配置

学校选择日常表现、身体成长、体能表现、健康概览和教师评价等报告内容，不选择问卷任务名称。报告内容方案在平台侧绑定所需标准成长字段和已确认档案字段；成长字段无论来自问卷、PC导入还是手机编辑，均按字段键进入证据。普通题目不能作为首期报告来源。

### 12.2 结构化证据包

生成前由后台按学生、学期和权限生成证据包：

```text
学生与学期范围
选中的报告内容模块
标准成长数据及有效版本
日常评价的结构化证据
已确认档案中的指定字段
来源编号和发生时间
数据缺失与证据边界
```

AI不直接读取整份问卷，也不自行计算BMI、变化量、数量、比例和排序。

### 12.3 隐私与版本

- 身份证号、签名确认和健康数据操作日志永不进入AI输入。
- 原始体检结论默认不进入AI，仅在学校开启健康概览且具备授权时提供必要结构化标签。
- 学生私密留言默认不进入AI输入。
- 报告保存数据方案版本、输入快照、提示词版本、生成时间和证据引用。
- 已发布报告不随后续数据修改自动重写；未发布报告可重新生成。

## 13. 权限

| 权限 | 能力 |
|---|---|
| 查看成长数据 | 查看学生身体成长摘要 |
| 配置成长字段 | 启用或停用本校可使用的运营预置字段 |
| 查看健康数据 | 查看完整体检记录 |
| 编辑健康数据 | 修正已有体检记录、新增测量记录 |
| 导入健康数据 | 在PC端创建体检导入批次 |
| 管理导入批次 | 处理冲突、错误匹配和批次状态 |
| 生成期末报告 | 生成并查看未发布报告 |
| 发布期末报告 | 确认报告并冻结正式版本 |

前端无权限操作直接隐藏；服务端必须按学校空间、学生范围和能力权限再次校验。

## 14. 异常与边界

| 场景 | 处理方式 |
|---|---|
| 体检文件存在重复工作表 | 预览显示重复数量，确认后只写入一条 |
| 学生无法匹配 | 不写入学生记录，保留在待处理列表 |
| 同一学生同一天已有不同体检值 | 进入冲突处理，不静默覆盖 |
| 手机新增记录与已有日期重复 | 引导编辑已有记录 |
| 已成档后修正体检数据 | 当前学生数据更新，历史档案保持原快照 |
| 已发布报告后修正来源数据 | 正式报告保持不变，审计记录标记数据后续发生修正 |
| 普通问卷存在同名“身高”题 | 仍只保留在问卷结果，不写入身体成长 |
| 同一采集同时包含普通题目和成长字段 | 普通答案留在答卷，成长字段按标准标识写入学生成长数据 |
| 按档案采集还需增加其他问题 | 当前任务不允许增加；另建自定义采集 |
| 档案模板在任务发布后修改 | 已发布任务继续使用发布时冻结的档案版本和字段标识 |
| 档案模板已被其他任务使用 | 仍可创建新任务；对同一学生已有待填写的同档案任务时，本次跳过该学生 |
| 家长和老师分别使用同一档案模板 | 由各自采集任务决定填写人，档案模板和分组不保存填写人 |
| 相同学生和相同档案正在采集 | 本次默认跳过该学生并继续使用原任务；所选学生全部已在待填写时阻止发布 |
| 相同学生的成长字段由多个任务采集 | 允许写入多条记录，按记录日期排序；同日不同值进入冲突处理 |
| 尝试修改按档案采集的字段或分组 | 前端不提供入口，服务端拒绝与冻结快照不一致的结构变更 |
| 同一学生多次完成同一档案采集 | 按稳定字段标识合并到一份当前档案，覆盖档案数据更新日期，不生成“档案-采集日期”副本 |
| 不含成长字段的按档案采集 | 不要求创建老师额外选日期；学生提交后以实际提交日期更新档案 |
| 包含成长字段的按档案采集 | 创建老师发布前必选任务记录日期；提交后以该日期更新档案 |
| 采集提交后其他入口再次更新成长数据 | 学生成长数据正常追加新记录；已保存到档案的值、日期和来源不自动变化 |
| 只采集身高或只采集体重 | 保存本次实际采集值；缺少另一项时不计算BMI |

## 15. 验收标准

### 15.1 PC设置与导入

- [ ] 学校可启用或停用运营平台预置字段，不能创建、改名或改变单位。
- [ ] 启用字段在问卷、PC导入、手机编辑和档案设计中保持一致。
- [ ] 只有具备权限的用户能看到并操作成长数据导入。
- [ ] 固定模板可以识别学校、班级、学生、身体数据、视力、结论和体检日期。
- [ ] 导入前展示成功、重复、异常和未匹配数量。
- [ ] 相同学生、体检类型和日期的完全重复记录不会重复写入。
- [ ] BMI由系统计算，附件值只用于核对。
- [ ] 导入完成后保存批次、操作者和结果。

### 15.2 教师手机端

- [ ] 学生详情不新增顶部页签。
- [ ] 成长概览展示身体成长和健康检查摘要。
- [ ] 点击摘要可以进入完整详情和历史记录。
- [ ] 有权限老师可以编辑体检记录，BMI不可手工修改。
- [ ] 编辑同一次记录保留历史；新的测量新增一条记录。
- [ ] 无权限用户不展示编辑和新增入口。
- [ ] 修正数据不会修改已确认档案和已发布报告。

### 15.3 统一采集写入

- [ ] 点击新建后先选择老师或家长填写，再选择按档案采集或自定义采集；两种方式互斥。
- [ ] 填写人在进入编辑器前选择；进入编辑器后不再展示或修改填写人，字段的数据去向不受填写人影响。
- [ ] 按档案采集完整展示档案内容并继承布局、分组、顺序、题型和必填规则；姓名、班级等系统已有信息不生成题目。
- [ ] 按档案采集不允许新增、删除、改名、排序、移动字段或调整分组。
- [ ] 按档案采集不能混入普通题目和额外成长字段；档案外信息另建自定义采集。
- [ ] 自定义采集可自由组合普通题目和任意已启用成长字段，但不能选择档案自定义字段。
- [ ] 档案填写人不在模板或分组中重复配置，只由采集任务统一决定。
- [ ] 同一档案模板可以被不同任务重复使用，一份任务最多使用一次。
- [ ] 按档案采集整体使用一份档案，不存在重复添加档案或字段的入口。
- [ ] 档案自定义字段在老师或家长打开任务时预填当前值，成长字段保持空白。
- [ ] 同一档案可以被不同任务、班级和学期使用，但同一学生和同一档案只保留一份当前档案。
- [ ] 同一学生和同一档案的多次有效提交只合并一份当前档案，空答案不清除已有值。
- [ ] 同一学生和同一档案存在待填写任务时，新任务跳过该学生；所选学生全部已待填写时阻止发布。
- [ ] 记录日期和成长数据按平台字段键写入学生成长记录。
- [ ] 自定义题目即使与预置字段同名，也不会写入成长数据。
- [ ] 档案自定义字段按发布时冻结的稳定标识合并到当前档案，同名普通题目不写入档案。
- [ ] 老师和家长提交使用同一档案写回规则，只更新本次实际提交字段。
- [ ] 包含成长字段时，档案数据更新日期等于任务记录日期；不含时等于该学生实际提交日期。
- [ ] 后续其他来源更新成长数据时，不自动改写已保存到档案的成长数据快照。
- [ ] 学期目标不出现在采集、档案或报告配置中。

### 15.4 档案与报告

- [ ] 档案模板可选择平台预置的具体成长字段，不要求学校建立数据项映射。
- [ ] 档案设计只配置`仅填写一次 / 可重复填写`，不展示生成周期或成长数据范围。
- [ ] 学生档案首页只展示已经形成的档案，已启用但未填写的档案只在`新增档案`选择器中出现。
- [ ] 当前档案提供`发起采集`入口，自动预选当前档案并先选择填写人。
- [ ] 学生已有当前档案时，采集写回会继承当前内容并局部更新本次有效字段。
- [ ] 档案成长字段保存本次数值、来源、记录日期和版本快照。
- [ ] 报告配置选择分析内容，由平台方案绑定所需成长字段，不选择原始问卷。
- [ ] AI输入不包含身份证号、确认签名和未授权健康原文。
- [ ] 正式报告保存输入快照、提示词版本和证据引用。

## 16. 指标

| 指标 | 说明 |
|---|---|
| 体检导入成功率 | 成功写入记录数 ÷ 可导入有效记录数 |
| 自动匹配率 | 无需人工处理的学生记录数 ÷ 总记录数 |
| 重复拦截率 | 被正确识别的重复记录数 ÷ 实际重复记录数 |
| 手机端重复录入率 | 采集后仍由老师手工重复录入的比例，目标为0 |
| 体检记录修正率 | 被手机端或PC端修正的记录比例，用于改进导入规则 |
| 报告证据覆盖率 | 报告结论中存在可回查证据的比例，目标为100% |

## 17. 发布计划

### 第一阶段：交互Demo

- PC成长数据设置、导入列表、导入预览和结果状态。
- 教师手机端身体成长和健康检查摘要。
- 体检详情、编辑和新增记录。
- 自定义采集编辑器中的普通题型与学校已启用成长字段混合选择。
- 统一采集先选择填写人，再选择按档案采集或自定义采集；按档案采集完整继承并锁定档案结构。
- 学生当前档案的`发起采集`入口与统一采集预选跳转。
- 期末报告配置的数据内容模块。

### 第二阶段：真实数据闭环

- 标准成长数据服务和版本记录。
- 固定体检模板解析、匹配、去重和批次管理。
- 手机端权限校验、编辑审计和并发控制。
- 档案引用快照和报告证据包。

### 后续版本

- 第三方体检系统接口同步。
- 更多平台标准成长信息模板。
- 经平台审核的学校模板扩展机制。
- 手写签名或具备法律效力的电子签名能力评估。
- 学期目标独立固定功能的唯一性、版本、调整、作废、回顾和协作规则。
