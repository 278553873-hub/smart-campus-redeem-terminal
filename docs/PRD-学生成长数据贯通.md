# PRD-学生成长数据贯通

> 版本：V1.2
> 更新日期：2026-07-30
> 适用端：学校PC后台、教师手机端、家长手机端
> 当前阶段：产品方案确认，进入交互Demo调整
> 关联文档：`PRD-教师端问卷采集.md`、`PRD-学生成长档案.md`

## 1. 摘要

学生成长数据贯通用于连接成长信息采集、学生详情、成长档案和期末报告。系统底层使用平台预置的标准学生数据项与阶段记录；学校和老师只接触业务模板，不接触数据项关联、保存位置和报告字段映射。

首期先判断采集内容，再独立选择填写方式：

1. `成长信息`：平台预置的身高体重和学期目标计划，可由老师或家长填写，完成后沉淀到学生长期数据。
2. `普通问卷`：学校自定义题目，可由老师或家长填写，只保留本次答卷和统计，不进入学生长期数据、档案或期末报告。

填写方式只决定任务接收人和记录形态，不决定数据去向。首期信息主体固定为学生，平台不根据自定义题目名称猜测或建立数据项关联。

成长档案引用标准成长数据并在确认成档时冻结快照；期末报告根据平台预置的报告内容方案生成结构化证据包，再交给AI（人工智能）生成文字。

## 2. 问题

1. 身高、体重等信息采集后，老师仍需到学生详情重复录入。
2. 身高、体重会连续更新，如果直接复制进档案，会丢失测量时间和历史变化。
3. 学期目标需要学生、老师和家长参与，并在期末与日常记录共同分析，不能作为普通问答文本处理。
4. 学校难以理解数据项关联、档案映射和报告数据来源等技术概念。
5. 体检数据可能来自PC批量导入，不一定来自问卷；以问卷作为唯一数据入口无法承接历史数据和外部系统数据。
6. 体检数据包含身份证号和健康结论，必须限制用途、权限和AI输入范围。

## 3. 用户与职责

| 角色 | 主要职责 |
|---|---|
| 平台 | 维护标准成长数据项、成长信息模板、档案模块和报告取数规则 |
| 学校管理员 | 启用模板、配置校训维度、管理体检导入权限和导入批次 |
| 校医或健康数据管理员 | 在PC端导入体检数据、处理匹配与异常 |
| 有学生权限的老师 | 在手机端查看学生成长数据；有健康数据管理权限时可修正或新增体检记录 |
| 学生 | 填写或确认本人学期目标；访谈模式下由老师代录并记录访谈人和时间 |
| 家长 | 补充家长回应并完成业务确认 |
| 报告管理员 | 选择报告内容模块，生成并发布期末报告 |

## 4. 目标与非目标

### 4.1 目标

1. 标准成长信息采集完成后自动进入学生详情，不要求老师重复录入。
2. 同一学生的身高、体重和体检信息按发生时间连续保存，可查看历史和变化。
3. PC体检导入完成匹配、格式校验、重复识别和异常处理后才写入学生记录。
4. 教师手机端可以查看单个学生的成长数据，并在授权范围内修正或新增记录。
5. 学期目标计划支持学生、老师、家长分阶段参与和确认，确认后保留初始版本。
6. 档案模板选择具体成长数据字段，确认成档时冻结数值、来源和时间快照。
7. 期末报告只读取经规则筛选的结构化证据，不读取整份问卷或身份证号。
8. 学校端不出现“标准数据项”“字段关联”“证据包”等技术配置。

### 4.2 非目标

首期不包含：

- 学校自建标准成长数据项。
- 自定义问卷题目关联标准数据项。
- 根据“身高”等自定义题目文案自动猜测字段含义。
- 学校自由配置任意问卷进入档案或报告。
- 手写签名图像；首期使用账号身份、确认人和确认时间完成业务确认。
- 将身份证号、签名信息或原始健康结论默认发送给AI。
- 手机端批量导入Excel（电子表格）或处理错误学生匹配。

## 5. 核心概念

| 学校看到的名称 | 系统内部含义 |
|---|---|
| 成长信息 | 平台预置、可以长期沉淀的结构化数据 |
| 成长信息模板 | 已经绑定标准数据结构的采集表或导入模板 |
| 普通问卷 | 只形成一次性答卷和统计的自定义问卷 |
| 身体成长 | 身高、体重、BMI（身体质量指数）及其测量历史 |
| 健康检查 | 视力、戴镜类型、体检结论和体检日期 |
| 学期目标计划 | 一学期内可确认、调整和期末回顾的目标记录 |
| 档案内容 | 手动填写字段或平台预置成长数据字段 |
| 报告内容模块 | 期末报告希望分析的主题及其固定取数规则 |

## 6. 总体流程

```text
成长信息采集 / PC导入 / 系统同步
  ↓
标准学生成长记录
  ↓
学生详情展示实时有效值和历史
  ↓
档案模板引用并在成档时冻结快照
  ↓
期末报告按内容模块生成证据包
  ↓
AI生成报告，保存输入和提示词版本
```

普通问卷只进入问卷结果和学生采集记录，不进入上述链路。

## 7. 标准成长数据

### 7.1 首期预置范围

#### 基础信息

- 姓名、性别、出生日期、学号、班级。
- 基础信息只有一个当前有效值；成长采集和体检导入只用于匹配和核对，不直接覆盖姓名、班级等主数据。

#### 身体成长

- 身高，单位厘米。
- 体重，单位千克。
- BMI，根据身高体重计算，不作为独立手工维护字段。
- 测量日期。

#### 健康检查

- 裸眼视力左、右。
- 矫正视力左、右。
- 矫正戴镜类型。
- 体检结论原文及结构化标签。
- 体检日期。

#### 学期目标计划

- 所属学期、上学期回顾。
- 目标一至目标三，其中目标三可选。
- 每个目标包含目标类型、校训维度、原因、具体行动或达成标志、初始自评。
- 学生留言、教师回应、家长回应和共同约定。
- 学生、教师、家长的确认身份与时间。
- 目标调整版本和期末回顾。

### 7.2 通用记录规则

每条连续成长记录至少保存：

```text
学生编号
记录类型
发生日期
有效值
采集来源
来源任务或导入批次
创建人和创建时间
当前版本
修正记录
```

- 手机端修正同一次体检时更新当前有效版本，系统保留导入原值和修改前后内容。
- 后续重新测量必须新增记录，不得覆盖上一次记录。
- 草稿档案和未发布报告读取当前有效版本；已成档快照和已发布报告不自动改写。

## 8. PC体检数据导入

### 8.1 入口与权限

入口：学校PC后台 → 数据中心 → 体检数据。

只有具备`导入健康数据`权限的用户可以新建导入；具备`管理导入批次`权限的用户可以查看批次和处理错误匹配。

### 8.2 导入流程

```text
选择文件
  ↓
识别固定模板和工作表
  ↓
按学生匹配并标准化字段
  ↓
识别重复、异常和未匹配记录
  ↓
用户确认
  ↓
写入学生体检记录并保存导入批次
```

首期支持平台提供的固定体检模板。学校不手动建立字段映射。

### 8.3 匹配与去重

- 优先使用平台学生编号或受保护的证件标识匹配。
- 无稳定编号时使用姓名、班级进行候选匹配，并要求人工确认冲突。
- 身份证号只用于匹配和审计，不进入学生详情普通页面、档案正文和AI输入。
- 记录唯一性按`学生编号 + 体检类型 + 体检日期`判断。
- 同一文件不同工作表出现相同记录时只保留一条，并在导入预览中显示重复数量。
- 已存在完全相同记录默认跳过；值不同的同键记录进入冲突处理，不能静默覆盖。

### 8.4 格式处理

- 数字和日期即使在Excel中保存为文本，也必须转换为标准类型。
- 身高、体重和视力按平台范围规则校验。
- BMI按标准公式重新计算，附件值仅用于差异核对。
- `测不出`等特殊值保存为明确状态，不伪装成数字。
- 混合了视力值和屈光度的内容进入待确认，不自动拆分错误数据。
- 体检结论保留原文，并按平台规则提取视力异常、龋齿、偏瘦、超重、肥胖等标签。

### 8.5 导入结果

导入完成页展示成功写入、重复跳过、未匹配、格式异常数量，以及导入批次、操作者和完成时间。

## 9. 教师手机端

### 9.1 信息架构

学生详情保留`成长概览 / 成长报告 / 采集记录`三个页签，不新增顶部页签。

`成长概览`增加：

1. `身体成长`：最新身高、体重、BMI、最近测量日期和历史变化。
2. `本学期目标`：一至三个已生效目标和当前状态。
3. `健康检查`：最近体检日期、视力摘要、戴镜类型和体检结论摘要。

模块默认只展示足以判断的摘要；点击进入独立详情页查看完整历史。

### 9.2 体检记录详情与编辑

- 体检历史按日期倒序排列。
- 详情展示身体数据、视力、戴镜类型、体检结论、来源和最近修改时间。
- 编辑入口位于内容区更多菜单，不放在小程序标题栏。
- 完整体检编辑使用独立页面，避免复杂表单挤入底部浮层。
- BMI只读并随身高、体重重新计算。
- 学生身份和错误匹配不能在体检编辑页修改。
- 手机端保存修正后展示有效值，后台保留原始导入值和修正历史。
- 新的测量使用`新增记录`，不能通过编辑旧记录制造新的成长数据。
- 无`编辑健康数据`权限时不展示编辑和新增入口。

### 9.3 学期目标展示与编辑

- 学生详情展示当前学期已生效目标摘要。
- 点击进入完整目标计划，展示上学期回顾、目标、三方回应、共同约定和确认状态。
- 草稿允许继续填写；三方确认后锁定。
- 学期中调整目标时生成新版本，初始目标继续保留。
- 访谈代录必须记录实际记录人和访谈时间。

## 10. 学期目标计划流程

### 10.1 平台预置模板

首期提供`新学期目标清单`标准模板。学校只配置任务标题、学期、班级范围、建议完成时间和校训维度选项，不创建或关联自定义字段。

### 10.2 状态

```text
草稿
→ 待学生填写或访谈代录
→ 待教师回应
→ 待家长回应
→ 待共同确认
→ 已生效
→ 已调整
→ 已完成期末回顾
```

教师访谈模式允许老师代录学生部分，但学生确认必须记录为访谈确认，不能伪装为学生账号提交。

### 10.3 校训维度与确认

- `目标维度`是平台预置字段，选项读取学校配置的校训或育人维度；学校配置选项不等于创建新的标准数据项。
- 首期采用账号身份、确认人和确认时间完成业务确认，不采集手写签名图像。
- 三方确认后形成学期目标计划初始快照。
- 调整目标必须产生新版本并记录调整人、时间和原因。

### 10.4 期末目标回顾

期末回顾至少包含达成状态、我做到了什么、最能证明进展的记录、下一阶段计划和教师期末评价。没有期末回顾时，AI只能描述观察到的进展，不得直接断言目标已经达成。

## 11. 成长档案

### 11.1 模板配置

学校在“添加内容”中切换`手动填写`和`成长数据`。手动填写提供文字、单选、多选、日期和数字；成长数据提供平台预置的具体字段，学校不需要理解内部数据项编号或建立映射。

首期可选成长字段至少包括：

- 身体成长：测量日期、身高、体重、身体质量指数。
- 健康检查：体检日期、裸眼视力、矫正视力、戴镜类型、健康结论。
- 学期目标：上学期回顾、目标清单、三方留言、共同约定、确认状态。
- 日常表现：本学期评价摘要。

学校可以控制具体字段是否展示和是否为成档必需；字段的数据来源、时间语义、单位和计算规则由平台维护。

### 11.2 实时值与快照

- 档案草稿读取当前有效成长数据。
- 确认成档时保存数据值、发生日期、来源和版本快照。
- 后续体检修正或目标调整不修改历史档案。
- 已成档内容错误时创建修订记录，不直接覆盖原快照。

## 12. 期末报告

### 12.1 学校配置

学校选择目标达成情况、日常表现、身体成长、健康概览和教师评价等报告内容，不选择原始问卷或数据库字段。报告内容方案在平台侧绑定所需成长字段和已确认档案字段；普通问卷不能作为首期报告来源。

### 12.2 结构化证据包

生成前由后台按学生、学期和权限生成证据包：

```text
学生与学期范围
选中的报告内容模块
标准成长数据及有效版本
学期目标初始版本和调整记录
期末目标回顾
日常评价的结构化证据
已确认档案中的指定字段
来源编号和发生时间
数据缺失与证据边界
```

AI不直接读取整份问卷，也不自行计算BMI、变化量、数量、比例和排序。

### 12.3 隐私与版本

- 身份证号、签名确认和健康数据操作日志永不进入AI输入。
- 原始体检结论默认不进入AI，仅在学校开启健康概览且具备授权时提供必要结构化标签。
- 学生私密留言默认不进入AI输入。
- 报告保存数据方案版本、输入快照、提示词版本、生成时间和证据引用。
- 已发布报告不随后续数据修改自动重写；未发布报告可重新生成。

## 13. 权限

| 权限 | 能力 |
|---|---|
| 查看成长数据 | 查看学生身体成长和学期目标摘要 |
| 查看健康数据 | 查看完整体检记录 |
| 编辑健康数据 | 修正已有体检记录、新增测量记录 |
| 导入健康数据 | 在PC端创建体检导入批次 |
| 管理导入批次 | 处理冲突、错误匹配和批次状态 |
| 管理学期目标 | 发起任务、教师回应和调整目标 |
| 生成期末报告 | 生成并查看未发布报告 |
| 发布期末报告 | 确认报告并冻结正式版本 |

前端无权限操作直接隐藏；服务端必须按学校空间、学生范围和能力权限再次校验。

## 14. 异常与边界

| 场景 | 处理方式 |
|---|---|
| 体检文件存在重复工作表 | 预览显示重复数量，确认后只写入一条 |
| 学生无法匹配 | 不写入学生记录，保留在待处理列表 |
| 同一学生同一天已有不同体检值 | 进入冲突处理，不静默覆盖 |
| 手机新增记录与已有日期重复 | 引导编辑已有记录 |
| 已成档后修正体检数据 | 当前学生数据更新，历史档案保持原快照 |
| 已发布报告后修正来源数据 | 正式报告保持不变，审计记录标记数据后续发生修正 |
| 学期目标未完成三方确认 | 保留草稿或待确认状态，不作为已生效目标进入正式档案 |
| 学期中调整目标 | 生成新版本，报告同时保留初始目标和调整记录 |
| 缺少期末目标回顾 | 报告降低结论确定性，不断言目标达成 |
| 普通问卷存在同名“身高”题 | 仍只保留在问卷结果，不写入身体成长 |

## 15. 验收标准

### 15.1 PC体检导入

- [ ] 只有具备权限的用户能看到并操作体检数据导入。
- [ ] 固定模板可以识别学校、班级、学生、身体数据、视力、结论和体检日期。
- [ ] 导入前展示成功、重复、异常和未匹配数量。
- [ ] 相同学生、体检类型和日期的完全重复记录不会重复写入。
- [ ] BMI由系统计算，附件值只用于核对。
- [ ] 导入完成后保存批次、操作者和结果。

### 15.2 教师手机端

- [ ] 学生详情不新增顶部页签。
- [ ] 成长概览展示身体成长、本学期目标和健康检查摘要。
- [ ] 点击摘要可以进入完整详情和历史记录。
- [ ] 有权限老师可以编辑体检记录，BMI不可手工修改。
- [ ] 编辑同一次记录保留历史；新的测量新增一条记录。
- [ ] 无权限用户不展示编辑和新增入口。
- [ ] 修正数据不会修改已确认档案和已发布报告。

### 15.3 学期目标

- [ ] 平台预置模板支持上学期回顾和最多三个目标。
- [ ] 每个目标保存校训维度、原因、具体行动和初始自评。
- [ ] 支持学生、教师、家长回应和账号确认时间。
- [ ] 访谈代录记录实际记录人和时间。
- [ ] 三方确认后保留初始版本，调整目标生成新版本。
- [ ] 期末回顾与原目标关联。

### 15.4 档案与报告

- [ ] 档案模板可选择平台预置的具体成长字段，不要求学校建立数据项映射。
- [ ] 成档时保存数值、来源、发生时间和版本快照。
- [ ] 报告配置选择分析内容，由平台方案绑定所需成长字段，不选择原始问卷。
- [ ] AI输入不包含身份证号、确认签名和未授权健康原文。
- [ ] 正式报告保存输入快照、提示词版本和证据引用。

## 16. 指标

| 指标 | 说明 |
|---|---|
| 体检导入成功率 | 成功写入记录数 ÷ 可导入有效记录数 |
| 自动匹配率 | 无需人工处理的学生记录数 ÷ 总记录数 |
| 重复拦截率 | 被正确识别的重复记录数 ÷ 实际重复记录数 |
| 手机端重复录入率 | 采集后仍由老师手工重复录入的比例，目标为0 |
| 体检记录修正率 | 被手机端或PC端修正的记录比例，用于改进导入规则 |
| 学期目标生效率 | 已生效目标计划数 ÷ 已发起学生数 |
| 三方确认完成率 | 完成学生、教师、家长确认的计划比例 |
| 报告证据覆盖率 | 报告结论中存在可回查证据的比例，目标为100% |

## 17. 发布计划

### 第一阶段：交互Demo

- PC体检导入列表、导入预览和结果状态。

- 档案引用快照和报告证据包。

- 第三方体检系统接口同步。
