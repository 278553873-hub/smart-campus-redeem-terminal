# PRD-教师端采集管理

> 版本：V2.0
> 更新日期：2026-07-31
> 适用端：教师手机端、家长手机端  
> 当前阶段：统一采集编辑器与成长字段闭环 Demo 调整中
> 文档状态：待产品、研发和测试评审

## 1. 摘要

采集管理是面向学校多种信息收集场景的统一能力。V1.8取消互斥任务入口，新建后直接进入统一采集编辑器。老师可以在同一任务中同时添加普通题目和本校已启用的成长字段，再独立设置由老师或家长填写。信息主体首期固定为学生，页面不要求老师额外选择。

填写人只决定任务发给谁，不决定数据去向。普通题目只保留在本次答卷；成长字段按平台字段键写入学生成长数据。系统不根据题目文案猜测字段含义，自定义题目即使名称为“身高”也仍是普通题目。

本功能不使用 AI（人工智能）生成分析。所有统计均基于结构化答卷进行确定性计算，确保结果可解释、可复核。

普通自定义问题只保留在本次采集结果中；本校已启用的标准成长字段进入学生成长数据。家长或老师提交后直接生成一条带记录日期的成长记录，不要求老师到学生详情重复录入。跨模块规则以`PRD-学生成长数据贯通.md`为准。

产品采用人工控制采集状态的方式。家长填写任务可以结束收集，未达到100%时允许重新开放；老师填写任务结束后允许恢复编辑，以满足资料纠错。分配给老师的采集通过应用内聚合待办触达，不按学生拆成大量待办。建议完成时间只用于家长填写任务提示，不会自动阻止提交。只有草稿可以永久删除，已开始的采集任务通过结束和归档完成生命周期管理。

### 1.1 首期产品模型

| 采集内容 | 配置方式 | 数据去向 |
|---|---|---|
| 普通题目 | 单选、多选、评分、多项填空、问答、日期、数字 | 仅本次采集结果 |
| 成长字段 | 从学校PC后台已启用的运营预置字段中选择 | 提交后生成学生成长记录 |
| 填写人 | 整个任务选择老师或家长填写 | 只影响任务路由，不改变字段去向 |

同一任务可以同时包含普通题目和多个分类的成长字段。成长字段目录与PC导入、手机编辑和档案设计共用，问卷侧不得再次按能力过滤。任务内所有成长字段共用一个记录日期；不同日期的数据必须新建不同采集任务，产品不提供“成长数据组”概念。

旧数据结构中的`guardian_questionnaire`和`student_information`只作为答卷/逐生记录的内部路由兼容，不再作为老师创建时看到的采集类型。

## 3. 背景与问题

学校常见的课后服务、研学活动、阅读习惯、校服尺码和家校需求调查，通常由老师在班级群中临时发起。现有方式存在以下问题：

1. 问卷与学生名单分离，老师难以确认哪些家庭已经完成。
2. 年级组长需要面向多个班级时，逐班查找和选择效率低。
3. 截止时间过于刚性，忙碌家长错过时间后无法补填。
4. 简答题回答数量较多时，全部堆在统计页会导致页面过长。
5. 问卷结束后缺少归档和恢复机制，列表会持续膨胀。
6. 删除规则不清晰，容易误删已经产生答卷的正式问卷。

此外，同一类内容可能由老师访谈代录，也可能由家长直接填写。如果用“家长问卷”和“学生信息采集”定义两种功能，内容性质和填写人会被错误绑定。因此底层必须同时保存内容类型和填写方式，再按填写人路由到答卷或逐生记录。

## 4. 产品目标

### 4.1 目标

1. 老师可以在手机端快速完成问卷创建和发布。
2. 发送范围按后端返回的权限班级进行“左侧年级、右侧班级”的级联选择。
3. 家长可以从待办直接填写，并在提交前完成必答校验。
4. 老师可以清楚查看完成情况、逐题统计和单份答卷。
5. 已结束问卷可以归档，低频数据不干扰日常使用。
6. 所有统计口径固定，不依赖 AI，前后端结果一致。
7. 创建人可以选择本人填写或按班级分配给班主任，老师可以按学生逐条填写资料、保存草稿和完成。
8. 教师可以从“我的”待办直达本人负责的聚合采集任务，完成本人负责的全部学生后待办自动消失。
9. 底层为未来面向教师发放问卷预留填写方、信息主体和任务分配能力。

### 4.2 非目标

V1 不包含以下能力：

- 不提供提醒未完成家长。
- 不自动催交，不发送二次提醒通知。
- 不包含微信服务通知等系统外消息通道，V1 以家长端待办作为送达结果。
- 不使用 AI 总结、生成结论或分析简答内容。
- 不支持问卷模板市场和公共题库。
- 不支持题目复制和复杂跳题逻辑；题目排序统一通过题目前的拖动把手完成。
- 不支持匿名问卷。
- 不支持家长修改已经提交的答卷。
- 不支持导出 Excel（电子表格）或 PDF（便携式文档格式）。
- 不支持已发布问卷直接编辑题目或发送范围。
- 不支持已发布问卷永久删除。
- 本期不支持指定学生发送，发送范围最细到班级。
- 本期不开放以教师为信息主体的问卷创建和填写。
- “我的”页面不展示没有待办的空入口。
- 老师填写的普通问卷不提供题目统计和答卷分析，先保持逐生录入任务简洁。
- 普通问卷不支持图片、附件、地址级联和复杂字段联动。
- 不支持学校自建标准成长数据项。
- 不支持自定义问题关联成长数据，也不根据题目文案自动识别“身高”“体重”等字段。
- 普通问卷答卷不自动进入学生成长数据、成长档案或期末报告。
- 学期目标不纳入本期采集管理、成长档案和期末报告范围；待业务方明确唯一性、版本、调整和回顾规则后，按独立固定功能另行设计。

## 5. 用户与权限

### 5.1 教师

- 创建、编辑和删除本人创建的草稿。
- 发布问卷到本人有权管理的学生范围。
- 查看本人创建问卷的数据和答卷。
- 结束收集、重新开放未满额问卷、复制、归档和恢复问卷。
- 创建老师填写任务，并按学生保存草稿或完成资料。
- 在确认开始时选择“我来填写”或“各班班主任”。
- 查看本人发起任务的整体进度和各班记录。
- 结束老师填写任务，并在需要纠错时恢复编辑。

### 5.2 发送范围权限

- 候选班级由后端组织权限服务返回，前端不得根据科目、部门或教师角色自行扩大范围。
- 领导、管理员可以获得全校班级；勾选“全部年级”代表选择当前学校全部学生。
- 年级组长只能获得所负责年级的班级；班主任、副班主任和科任老师只能获得实际带班或任教班级。
- 同一教师具有多个身份时，后端返回各身份权限的并集并去重。
- 页面按年级组织后端返回的班级，复用教师个人信息页的双栏级联：左侧切换年级，右侧勾选该年级下有权限的班级。
- 领导、管理员使用“全部年级”一次选择全部权限班级；其他教师使用“全部班级”一次选择后端返回的全部权限班级。
- 页面不展示权限推导过程，不增加“系统已根据权限生成范围”等说明。

### 5.3 老师填写任务

- 当前老师被分配学生记录后，收到一个按采集任务聚合的待办，不按学生生成多条待办。
- 从“待我填写”进入时，只能查看和编辑分配给本人的学生记录。
- 本人负责记录全部完成后，待办自动完成并从待填写入口消失。
- 填写人不能结束、恢复、归档或复制任务，这些生命周期操作只属于任务创建人。

### 5.4 家长

- 查看与当前绑定学生相关、仍在收集且尚未提交的问卷。
- 预览题目、填写并提交答卷。
- 问卷已结束或该学生已经提交后，不得再次提交。

### 5.5 以教师为信息主体的问卷填写人（后续版本）

- 校长或有权人员向教师范围发布问卷后，每名教师形成一条独立填写任务。
- 待填写采集通过教师待办提醒，已提交记录可在“采集管理－我收到的”查看。
- 本期只预留以教师为信息主体的数据模型，不在新建采集入口展示预告或禁用项。老师填写学生信息的聚合待办属于本期能力。

### 5.6 权限原则

- 前端隐藏操作不等于完成权限控制，后端必须再次校验教师、空间、学生范围和问卷状态。
- 问卷归属当前学校或个人空间，跨空间不可查询或操作。
- V1 以学生为答卷主体。同一学生绑定多个家长时，任一家长提交后即视为该学生已完成，其他家长不可重复提交。
- 老师填写任务的目标范围仍受创建人组织权限约束。创建人选择“我来填写”时全部记录分配给本人；选择“各班班主任”时按发布时班级快照分配给对应班主任。
- 创建人可以查看任务全部学生记录；填写人只能查看和修改分配给本人的记录。
- 发布时没有可用班主任的班级不能完成“各班班主任”分配，必须先调整范围或补齐班主任关系。
- 底层必须分别校验填写人、信息主体和任务分配关系，不能只用用户编号代替三者。

## 6. 核心概念与数据口径

| 概念 | 定义 |
|---|---|
| 表单定义 | 标题、说明、布局模式、分组、字段、选项、必填规则等可复用内容结构 |
| 采集任务 | 一次面向指定范围发起的信息收集任务，同时保存内容结构、填写方式、状态和范围快照 |
| 采集内容 | 普通题目和平台预置成长字段；两类内容可以出现在同一任务中 |
| 填写方式 | 老师填写或家长填写；决定任务路由到逐生记录还是家长答卷 |
| 信息主体 | 本条信息描述的对象；本期均为学生，未来以教师为信息主体的问卷为教师 |
| 填写人 | 实际完成内容录入的老师或家长 |
| 填写分工 | 老师填写时的分配方式；分为创建人填写和各班班主任填写 |
| 聚合待办 | 同一采集任务分配给同一教师的全部学生记录合并成一个待办 |
| 对象记录 | 一个信息主体在一次采集任务中的独立状态与内容记录 |
| 范围规则 | 发布时保存的班级范围；收集中动态跟随班级成员变化 |
| 目标学生 | 根据范围规则生成的学生接收记录；保留姓名、班级和送达状态快照 |
| 有效目标学生 | 当前仍处于发送范围内的目标学生 |
| 已退出目标学生 | 曾进入发送范围、后因转班或离校退出的学生；保留历史但不再产生待办 |
| 可送达学生 | 当前有效目标中已存在可用家长绑定关系、可以生成家长待办的学生 |
| 未绑定学生 | 当前有效目标中没有可用家长绑定关系、暂时无法生成家长待办的学生 |
| 已完成 | 已成功提交一份有效答卷的学生 |
| 未完成 | 可送达但尚未提交答卷的学生 |
| 完成率 | 已完成学生数 ÷ 可送达学生数 |
| 建议完成时间 | 仅用于提示的可选时间，不是强制截止时间 |
| 有效回答 | 某道题实际存在回答的答卷数量 |
| 归档 | 将已结束问卷移出高频列表，保留数据并允许恢复 |
| 逐生草稿 | 老师填写时，某名学生已部分填写但尚未标记完成的记录 |

### 6.1 完成率规则

```text
可送达人数 = 有效目标学生中 reachable = true 的人数
已完成人数 = 已提交答卷且当前仍为有效目标学生的人数
完成率 = 可送达人数为0时取0，否则四舍五入为整数百分比
```

未绑定学生和已退出目标学生不计入完成率分母。已退出学生的历史答卷保留，但不进入当前范围完成率。

老师填写整体口径：

```text
目标人数 = 当前有效目标学生数
已完成人数 = 当前有效目标中 record_status = completed 的对象记录数
完成率 = 目标人数为0时取0，否则已完成人数 ÷ 目标人数
```

逐生草稿不计入已完成数，但退出后必须可以继续编辑。

老师填写待办口径：

```text
本人负责人数 = respondent_id 为当前教师的对象记录数
本人已完成人数 = 本人负责记录中 record_status = completed 的数量
待办存在 = 任务状态为收集中，且本人至少有1条未填写或草稿记录
待办数量 = 满足上述条件的采集任务数，不是学生记录数
```

### 6.2 范围规则与接收记录

- 发布时保存班级范围规则，同步策略固定为 `follow_classes`；同时为发布时班内学生生成独立接收记录。
- 任务处于收集中时，班级新增学生自动生成接收记录；已绑定家长时生成待办，未绑定时先进入未绑定状态，绑定后再生成待办。
- 学生转班或离校后，未提交待办停止展示，接收记录标记为已退出；已经提交的答卷和审计信息保留。
- 学生重新进入原范围时恢复原接收记录，不重复生成任务或清空历史内容。
- 已结束和已归档任务不再同步班级成员。恢复收集后重新对账当前班级成员，但不删除历史记录。
- 接收记录以“采集任务编号 + 信息主体类型 + 学生编号”建立唯一约束，成员变更事件重试不得生成重复任务。

### 6.3 统一采集内容与数据边界

- 点击新建后直接进入统一采集编辑器，不先选择互斥任务类型。
- `添加内容`底部浮层提供`普通题型`和`成长数据`两个页签。
- 普通题型由学校自定义；成长数据提供学校PC后台已经启用的全部运营预置字段。
- 选择任一成长字段后自动加入一条系统记录日期规则；任意字段均可独立选择，也可与普通题目混合。
- 记录日期提供`填写人选择`和`本次统一日期`两种方式。填写人选择时在填写端显示必填日期；本次统一日期由老师发布前设置，填写端不再展示日期题。
- 一份任务只有一个记录日期，任务内所有成长字段共用。不同日期的数据使用不同任务，不提供第二个日期或成长数据组。
- 记录日期用于判断成长数据新旧；提交时间只用于审计，不参与排序，也不能在记录日期缺失时作为兜底值。
- 填写人在确认发布时选择老师或家长，填写人变化不修改任何字段的数据去向。
- 普通题目无论由老师还是家长填写，结果都只进入本次答卷、统计和学生采集记录。
- 同名字段不代表同一数据含义。普通问卷中名为“身高”的自定义题仍不写入学生身体成长。
- 成长数据Excel（电子表格）导入属于PC端并列录入入口，不作为教师手机端采集类型。
- 标准成长信息的存储、学生详情展示、档案引用和报告取数统一遵循`PRD-学生成长数据贯通.md`。

## 7. 产品流程

### 7.1 统一采集任务

```text
教师新建采集
  ↓
编辑内容：普通题目 + 可选成长字段
  ↓
选择学生范围 → 设置老师或家长填写 → 确认发布
  ↓
老师逐生填写 / 家长端生成待办并填写
  ↓
教师查看数据与答卷
  ↓
结束收集 ←→ 未满额时重新开放
  ↓
归档 ←→ 恢复到已结束
```

草稿可以永久删除；进入收集后的问卷不再允许永久删除。

### 7.2 老师填写任务

```text
教师创建草稿
  ↓
编辑问卷 → 选择学生范围 → 确认开始并选择填写分工
  ↓
系统按创建人或班主任生成填写分配
  ↓
填写人收到聚合待办 → 按学生保存草稿 / 标记完成
  ↓
本人负责学生全部完成 → 待办自动完成
  ↓
结束采集 ←→ 恢复编辑
  ↓
归档 ←→ 恢复到已结束
```

老师接收的是一个聚合采集任务，不生成与学生数量相同的教师待办。任务详情通过学生名单承载逐条记录。创建人从“我发起的”查看整体范围；填写人从“待我填写”进入时只查看本人负责范围。

### 7.3 成长字段采集

```text
教师在统一编辑器中添加成长字段
  ↓
从本校已启用字段中选择本次所需内容
  ↓
设置记录日期：填写人选择 / 本次统一日期
  ↓
可继续添加普通问题
  ↓
选择老师或家长填写，并设置班级范围
  ↓
提交后普通答案进入本次采集，成长字段形成学生成长记录
```

- 成长字段完成后生成带记录日期的学生成长记录，不覆盖历史记录；记录日期不能为空。
- 任务只保存本次实际选择和填写的字段；同时包含身高与体重时系统计算BMI（身体质量指数），BMI不作为人工录入字段。
- 标准成长信息可以在学生详情对应业务模块查看，不与普通问卷答案混合展示。
- 同一学生、同一字段按记录日期判断新旧。同日不同来源出现不同值时进入冲突处理，不按提交先后自动覆盖。

## 8. 页面与交互需求

### 8.1 功能入口

发起入口：教师手机端 → 我的 → 更多工具 → 采集管理。

填写入口：教师手机端 → 我的待办数量提示 → 待填写采集 → 待我填写。

- 更多工具保持一行4列。
- 采集管理位于已有工具之后，不调整其他工具顺序。
- 顶部导航与科目管理、部门管理统一，导航高度44px。
- 当前教师存在待填写采集时，“我的”底部导航展示轻量数量提示，“我的”头像区下方展示紧凑的“待填写采集”入口；没有待办时两处都隐藏。
- 待办数量按采集任务计数，不按学生人数计数。

### 8.2 我发起的列表

“采集管理”默认展示当前教师创建的任务。其他教师创建但分配给当前教师的任务不进入该列表。

顶部导航只保留返回与页面标题，不承载业务操作。新建入口使用内容区右下角的通用悬浮加号，点击后打开采集类型选择；列表底部必须预留安全滚动空间，避免遮挡最后一张卡片。“待我填写”只从“我的”待办入口进入，不在“我发起的”列表重复展示快捷入口。

顶部只保留3个高频页签：

1. 收集中。
2. 已结束。
3. 草稿。

不增加“已归档”作为第四个顶部页签。仅在存在归档数据时，在“已结束”页签顶部右侧展示轻量“已归档”二级入口，不展示归档数量，点击后进入独立归档列表。

#### 收集中和已结束卡片

展示：

- 问卷名称。
- 建议完成时间；未设置时展示“不限时间”。
- 短进度条。
- `已完成数/可送达数`，例如 `8/11`。
- 业务标签按实际内容展示：`普通问卷 · 老师填写 / 家长填写`、`成长采集 · 老师填写 / 家长填写`或`混合采集 · 老师填写 / 家长填写`。

老师填写任务卡片的分母为目标学生数，分子为已完成的逐生记录数；不使用家长可送达口径。

不展示：

- “收集中”“已结束”等重复状态标签。
- “已提交”解释文案。
- 完成百分比数字。
- 展开箭头或“点击查看”说明。
- 发送对象和题目数量。

#### 草稿卡片

- 只展示问卷名称。
- 不展示草稿标签、题目数量和“继续编辑”。
- 点击卡片直接进入编辑页。

#### 待我填写

- 仅展示状态为收集中、至少有一条记录分配给当前教师、且本人尚未全部完成的老师填写任务。
- 每个任务只展示一张卡片，不按学生拆分。
- 卡片展示采集名称、创建人和`本人已完成数/本人负责人数`。
- 点击后只展示当前教师负责的学生，不能看到其他班主任负责的学生。
- 当前教师负责记录全部完成后，任务自动从“待我填写”和“我的”待办入口消失。
- 从“待我填写”进入详情时不展示结束、恢复、归档、复制等创建人操作。
- 选择“我来填写”的任务在未完成期间会同时出现在“我发起的”和“待我填写”，两处分别服务任务管理和内容填写。

### 8.3 新建和编辑问卷

#### 新建类型选择

点击内容区右下角的悬浮新建按钮后直接进入统一编辑器：

1. 第一步编辑采集名称、说明和内容。
2. `添加内容`浮层通过`普通题型 / 成长数据`页签渐进披露可选内容。
3. 第二步选择学生范围。
4. 第三步设置`老师填写 / 家长填写`，并根据填写人展示填写分工或建议完成时间。

浮层只展示当前一步必要选项，不放置业务规则说明。关闭浮层后不改变列表状态。

创建流程分为3步：

1. 编辑问卷。
2. 发送范围。
3. 确认发布。

三步底部操作保持一致：

- 左侧始终为“保存草稿”，可保存当前题目、发送范围、建议完成时间和老师填写分工。
- 右侧为“下一步”或“确认发布”。
- 顶部返回按钮在第2、3步返回上一步，不在底部重复提供“上一步”。
- 所有采集任务的新建与编辑流程提供“预览”；预览不与“保存草稿”和“下一步”争夺层级。
- 预览直接读取当前未保存内容，退出后返回进入预览前的编辑步骤，不触发保存、发布或答卷提交。

#### 第1步：编辑问卷

字段：

| 字段 | 必填 | 限制 |
|---|---|---|
| 问卷标题 | 发布必填 | 最多40个字符 |
| 问卷说明 | 否 | 最多500个字符 |
| 题目 | 发布必填 | 至少1题 |

- 新建采集默认不创建任何内容。
- 普通题目不重复展示“题目”标题，只保留紧凑的“分组”开关；无论老师还是家长填写，都使用同一套题型和编辑器。
- 问卷说明编辑时由单行触控高度随内容增高，最多展开约6行并在聚焦时显示字数；失焦后完整展示，不截断内容。
- 题目为0时，不再在内容区重复展示“添加第一题”。
- 题目更多菜单提供复制；复制题目完整保留题干、选项、必填与题型设置，插入原题下一位并进入编辑态。
- 保存草稿时允许标题或题目不完整，空标题保存为“未命名问卷”。
- 在发送范围和确认发布步骤也可以保存草稿，保存后返回草稿列表。
- 进入下一步前，必须完成标题和题目校验。

#### 题型

| 题型 | 配置 | 家长作答 | 统计方式 |
|---|---|---|---|
| 单选题 | 至少2个非空选项 | 只能选择1项 | 各选项人数和占有效回答比例 |
| 多选题 | 至少2个非空选项 | 可选择多项 | 各选项人数和占有效回答比例，比例之和可超过100% |
| 评分题 | 默认1至5分，可配置起始分和结束分，结束分最高10分 | 选择1个分值 | 平均分、各分值人数和比例 |
| 多项填空题 | 2至6个名称不可重复的填空项，每项独立设置必填 | 在同一题中逐项输入短文本 | 按填空项分别展示回答列表和有效回答数 |
| 问答题 | 无选项 | 输入文本 | 回答列表和确定性高频词统计 |
| 日期 | 默认年-月-日，可配置年-月或年份 | 按格式选择或输入日期 | 回答列表 |
| 数字 | 默认整数，可配置1位或2位小数 | 使用对应数字键盘输入 | 平均值与回答列表 |

除多项填空题外，每道题支持设置“必答”。多项填空题由各填空项独立设置必填，题目必答状态由是否存在必填子项派生。

题目编辑器交互规则：

- 采集管理和档案设计复用同一套表单构建器；业务层通过`普通题型 / 成长数据`页签注入各自允许的内容，成长字段名称、单位和数据标识不可修改。
- 题目列表态仅展示连续题号、必填标识、题干和真实填写控件预览；题干不得以标题和输入框两种形态同时出现。点击题目后进入编辑态，才展示题干输入、选项编辑、必填和更多操作。
- 题号固定在最左侧并同时作为拖动排序抓手，问题和选项位于右侧；列表态不展示题型标签或管理说明。
- “使用分组”为表单级开关，默认关闭；开关与题目标题同行，不使用独立卡片。关闭时题目连续排列且不展示所属分组，开启后才显示分组管理。
- 首次开启分组时只在列表末尾展示“添加分组”入口，不自动创建或展示“默认分组”，也不展示分组数量；创建第一个分组后，现有题目自动归入该组。
- 每个分组使用浅中性底的标题行建立结构层级，标题采用卡片标题字号和加粗字重，右侧只保留“更多”图标；不为整个分组增加重卡片或阴影。重命名、分组排序和删除通过底部抽屉渐进披露，页面不常驻展示这些低频操作。
- 关闭分组不删除已有分组关系，重新开启后恢复；平铺期间新增的题目在重新开启时归入第一个已有分组。
- 选择题型后新增题目自动展开，并直接聚焦题目输入框。
- 题目和选项输入框使用白色编辑面、清晰边框和聚焦态，不得使用容易被理解为禁用的灰色输入框。
- 配置选项时使用中性序号，不展示单选框或复选框；老师此时是在编辑选项，不是在勾选答案。列表态则使用真实单选框、复选框、评分、日期和数字控件外观进行不可填写预览。
- 每道题目前展示可操作的拖动把手，支持鼠标、触控和键盘排序；题目展开区不再提供上移、下移按钮。
- 开启分组时，拖动仅调整当前分组内的题目顺序；跨组移动通过“所属分组”完成。
- 多选题更多设置支持最少选择数和最多选择数，满足 `1 <= 最少选择数 <= 最多选择数 <= 选项数`。
- 评分题更多设置支持起始分和结束分，默认1至5分，满足 `1 <= 起始分 < 结束分 <= 10`。
- 日期更多设置支持年-月-日、年-月和年份；数字更多设置支持整数、1位小数和2位小数。
- 多项填空题默认创建2个空白子项，最多增加到6项；子项名称不能为空或重复，每项独立设置必填。删除后不得少于2项，复制题目时必须为子项生成新的稳定编号。

#### 自定义答案选项

单选题和多选题支持增加“其他（请填写）”：

- 该能力收进题目编辑器的“更多”菜单，默认不展示，符合渐进披露。
- 添加后，该选项标记为“选中后需填写”。
- 家长只有选中该选项后，才展示补充文本框。
- 选中后补充文本为空时，不允许提交。
- 老师可以修改该选项名称，也可以删除该选项。
- 答案必须结构化保存选中项和补充文本，不得拼接成不可解析的普通字符串。

#### 第2步：发送范围

页面直接展示后端返回的权限班级，不再提供范围模式切换。班级选择复用教师个人信息页的双栏级联组件，保持操作习惯一致。

| 层级 | 行为 |
|---|---|
| 全部范围 | 领导、管理员显示“全部年级”；其他教师显示“全部班级”，只覆盖后端返回的权限班级 |
| 年级 | 左栏按年级聚合权限班级，点击只切换右栏内容；已选班级数显示在年级下方 |
| 班级 | 右栏展示当前年级下有权限的班级，支持多选，并显示班级当前学生数 |

规则：

- 班级集合完全由后端权限接口提供，前端只分组和展示，不自行推导教师可见班级。
- “全部范围”支持全选、半选和未选状态；班级支持选中和未选状态。
- 所有已选班级默认跟随收集期间的班级成员变化。
- 不展示额外摘要卡片，仅在“全部范围”行展示当前目标学生数。
- 已选班级内未绑定家长的学生仍计入目标范围，发布确认时显示未绑定人数。
- 发送范围为空时不能进入发布。

#### 第3步：确认发布

展示：

- 标题和说明。
- 题目数。
- 目标学生数。
- 可送达学生数。
- 建议完成时间设置。
- 未绑定人数提示，仅在大于0时出现。

建议完成时间：

- 默认关闭。
- 开启后默认填入7天后的20:00，老师可以修改。
- 发布后只作为提示，不会自动结束问卷。
- 到达建议完成时间后，问卷仍保持收集中，家长仍可提交。

#### 老师填写任务的第3步

老师填写任务仍使用同一套3步流程，不增加第4步。确认页展示采集名称、说明、字段数和目标学生数，并增加一行可点击的“填写分工”：

1. 我来填写：默认值，全部学生记录分配给任务创建人。
2. 各班班主任：按每名学生发布时的班级快照，分配给该班当前有效班主任。

点击“填写分工”后通过统一底部浮层选择，不在确认页直接铺开两种选项。选择“各班班主任”时：

- 同一班级的学生记录分配给同一名班主任。
- 创建人本人也是某班班主任时，该班记录正常分配给本人，并生成本人的聚合待办。
- 任一目标班级缺少有效班主任时不能开始采集，页面只指出需要处理的班级，不展示组织权限推导过程。
- 开始采集后固化填写分配，班主任关系变化不自动改写历史任务。

### 8.4 草稿操作

编辑已有草稿时，顶部更多菜单提供“删除草稿”。新建但尚未保存的问卷不展示该入口。

删除前必须二次确认：

```text
删除草稿？
删除后无法恢复
取消 / 删除
```

只有草稿可以永久删除。后端收到删除请求时必须再次校验状态。

### 8.5 采集详情

顶部基本信息使用一张卡片展示：

- 采集名称。
- 问卷说明，有内容时完整展示。
- 建议完成时间，仅设置后展示。
- 预览入口。

不展示：

- 发送对象。
- “收集中”“已结束”等状态标签。
- 解释性摘要和操作说明。

详情页包含两个页签：

1. 数据。
2. 答卷。

不再拆分“概览”和“题目分析”。

### 8.6 数据页签

#### 完成情况

只展示一次整体完成情况：

- 已完成数/可送达数。
- 待提交人数。
- 未绑定人数。
- 整体进度条。

每道题的统计卡片不再重复“共8份答卷”等整体信息。

#### 选择题和量表题

- 单选题、多选题展示各选项人数和比例。
- 自定义答案计入对应选项人数。
- 量表题展示平均分，保留1位小数，并按题目实际配置展示1至N级分布。
- 某题无人回答时，各项人数和比例均为0。
- 某题有效回答数与总答卷数不一致时，才展示“有效回答 N”。

#### 简答题

回答数量不超过5条时：

- 在题目卡片内全部展示。

回答数量超过5条时：

- 展示最多3个高频词及出现次数。
- 只展示最新2条回答，每条最多3行。
- 提供“查看全部回答”入口。

高频词必须使用确定性算法，不调用 AI：

1. 使用标准中文分词能力。
2. 去除停用词、标点、单字和空白内容。
3. 只统计出现次数不少于2次的词。
4. 按出现次数倒序，最多展示3个。
5. 相同次数使用稳定顺序，确保前后端结果一致。

“全部回答”页面：

- 默认按提交时间倒序。
- 支持搜索回答内容、学生姓名或学号。
- 存在多个班级时支持按班级筛选。
- 每次加载20条，支持继续加载。
- 展示回答内容、学生姓名、班级和提交时间。

#### 多项填空题

- 统计卡片按填空项分段展示，不把多个值拼成一条答案后再统计。
- 每个填空项独立计算有效回答数；不超过5条时全部展示，超过5条时展示最新2条并提供“查看全部回答”。
- “查看全部回答”沿用问答题的搜索、班级筛选和每次20条加载能力，但入口和结果仅对应当前填空项。
- 答卷详情按“填空项名称：填写内容”展示，未填写的可选项明确显示“未填写”。

### 8.7 答卷页签

提供3个筛选：

1. 已完成。
2. 未完成。
3. 未绑定。

规则：

- 已完成列表展示学生姓名、家长关系和提交时间，点击进入答卷详情。
- 未完成列表展示可送达但尚未提交的学生。
- 未绑定列表展示发布时没有有效家长绑定的学生。
- 不展示“已完成8”等重复数量。
- 不提供“提醒未完成家长”或“发送提醒”。

答卷详情按题目顺序展示题目、题型和格式化答案。自定义选项显示为：`其他：补充内容`。

### 8.8 预览问卷

- 问卷详情卡片提供“预览”。
- 家长填写任务的新建与编辑流程顶部提供“预览”，并保持底部只有“保存草稿”和“下一步 / 确认发布”两个操作。
- 预览必须复用真实家长填写任务组件，避免预览与实际页面不一致。
- 预览模式可操作选择和输入，但不能创建真实答卷。
- 顶部提供“结束预览”，从编辑流程进入时返回原编辑步骤，从详情进入时返回问卷详情。
- 编辑态预览使用当前内存中的未保存内容；没有题目时提示老师先添加题目，不自动创建占位题目。
- 问卷说明在真实填写和预览中完整展示，不截断内容。

### 8.9 家长端待办与填写

家长端待办出现条件：

- 问卷状态为收集中。
- 当前学生在目标快照中。
- 当前学生发布时可送达。
- 当前学生尚未提交该问卷。

家长填写页展示：

- 问卷名称。
- 问卷说明，仅有内容时展示。
- 建议完成时间，仅设置后展示。
- 题目和必答标记。
- 提交按钮。

提交校验：

- 单选题必答时必须选择1项。
- 多选题必答时至少选择1项。
- 量表题必答时必须选择1个分值。
- 简答题必答时去除首尾空格后不能为空。
- 选中“其他（请填写）”时，对应补充文本不能为空。

提交时后端必须再次校验问卷仍在收集中。若老师在家长填写期间结束问卷，提交失败后提示：`问卷已结束或已经提交`。

提交成功后：

- 当前学生待办立即消失。
- 不允许重复提交。
- 老师端完成情况和答卷列表更新。

### 8.10 老师填写任务

创建流程：

```text
新建采集 → 添加普通题目和成长字段 → 选择学生范围 → 选择老师填写 → 确认填写分工并开始采集
```

内容规则：

- 老师填写与家长填写共用同一套单选、多选、评分、多项填空、问答、日期和数字题；填写人不改变内容结构。
- 身体成长使用平台预置字段，老师可以选择字段但不能修改字段含义。
- 老师填写时每名学生形成一条逐生记录，可以保存草稿或标记完成。

采集详情：

- 基本信息卡展示采集名称、可选说明、完成进度和短进度条。
- 不展示采集对象摘要和“收集中”等状态标签。
- 默认展示学生名单，支持搜索，并按全部、待完成、已完成筛选。“待完成”合并未填写和已保存草稿的记录。
- 草稿是用于恢复内容的底层状态，不作为一级筛选项；草稿记录在学生行内显示“待继续”，并在“待完成”列表中排在完全未填写记录之前。
- 每名学生对应一条对象记录，状态独立，不把全班学生拆成多个教师待办。
- 点击学生进入单页表单；未完成时可保存草稿，必填字段完整后可标记完成。
- 已完成记录在采集进行中仍可重新进入修改；保存后保持已完成状态。
- 采集结束后记录只读，通过“恢复编辑”重新进入可编辑状态。
- 老师填写任务不展示数据、答卷页签，不做题目统计分析。
- 创建人从“我发起的”进入时，完成进度和学生名单使用全部目标学生口径。
- 填写人从“待我填写”进入时，完成进度和学生名单只使用本人负责记录口径。
- 后端必须按填写分配过滤记录；不能只依赖前端隐藏其他班级学生。

### 8.11 教师端采集待办与以教师为信息主体的问卷预留

老师填写任务的教师待办本期启用，采用两层结构：

1. “我的”底部导航在存在待办时显示红点或数量；进入“我的”后按条件展示紧凑待办入口。没有待办时整块隐藏。
2. “采集管理”提供“待我填写”二级页面，用于查看本人尚未全部完成的聚合采集任务。

不新增第四个底部导航，也不在每次启动时强制弹窗。微信服务通知可作为后续外部触达渠道，点击后直接打开任务。以教师为信息主体的问卷仍只预留 `respondent_type=teacher`、填写分配和禁用入口；本期待办只承载老师填写任务。

### 8.12 学生详情中的采集记录

学生详情使用三个并列页签：成长报告、评价记录、采集记录。学期选择和五育能力模型只放在“成长报告”中，切换到评价记录或采集记录后不重复展示。

采集记录列表规则：

- 同时展示家长填写任务答卷和老师填写任务记录，统一称为“采集记录”。
- 只展示已经提交或标记完成的记录；未填写和草稿继续从“待我填写”处理，不作为正式学生资料展示。
- 按完成或更新时间倒序排列。
- 卡片展示采集名称、对应业务入口与完成方式标签、完成时间和实际填写人。
- 不展示“已完成”、题目数、任务状态、说明或答案摘要。
- 已结束和已归档任务的完成记录继续展示。
- 点击卡片进入独立采集详情。
- 从采集详情返回学生详情时，保持在“采集记录”页签，便于连续查阅。

采集详情使用一张基本信息卡和一个连续问答列表：

- 基本信息卡展示采集名称、可选说明、采集类型、实际填写人和完成时间。
- 问答列表按表单字段顺序展示问题和格式化答案，不为每道题创建独立卡片。
- 可选字段没有填写时展示弱化的“未填写”。
- 选择题的自定义答案继续显示为“选项：补充内容”。

数据与权限规则：

- 按学生编号查询记录，不按学生当前班级查询；学生转班后历史记录仍然保留。
- 一次采集任务对一名学生最多展示一条完成记录。
- 任务创建人可以查看本人任务中的该学生记录；被分配教师只能查看明确分配给本人的学生采集记录。
- 学生详情不能绕过原采集任务权限展示健康、住址、家庭等敏感答案。
- 普通题目答案只作为本次采集结果，不自动覆盖学生基础信息，也不进入成长档案或期末报告。
- 学校已启用的成长字段已经绑定标准数据结构，不要求老师确认字段映射。
- 老师或家长提交成长字段后直接写入学生成长数据；同一任务中的普通题目仍只保留答卷。

## 9. 生命周期与操作规则

### 9.1 状态机

家长填写任务：

```text
草稿 --发布--> 收集中 --结束收集--> 已结束 --归档--> 已归档
  |                 ^          |                    |
  └--永久删除       └--重新开放┘          恢复到已结束
```

老师填写任务：

```text
草稿 --开始采集--> 收集中 --结束采集--> 已结束 --归档--> 已归档
  |                    ^          |                    |
  └--永久删除          └--恢复编辑┘          恢复到已结束
```

### 9.2 状态操作矩阵

| 当前状态 | 允许操作 | 禁止操作 |
|---|---|---|
| 草稿 | 编辑、保存、发布、永久删除 | 结束、重新开放、归档 |
| 收集中 | 查看、预览、复制、结束收集 | 编辑、永久删除、直接归档 |
| 已结束 | 查看、预览、复制、归档；未满额时可重新开放 | 编辑、永久删除；满额时重新开放 |
| 已归档 | 查看、预览、复制、恢复到已结束 | 编辑、永久删除、直接重新开放 |

### 9.3 详细规则

- 结束收集后，家长端立即停止接受新答卷。
- 重新开放保留原答卷、范围规则和建议完成时间，并按当前班级成员重新对账动态范围。
- 当已完成数等于可送达数且可送达数大于0时，问卷视为100%采集完成，不展示“重新开放”，后端也必须拒绝重新开放。
- 归档是可恢复操作，不需要二次确认。
- 恢复后进入“已结束”，不会直接进入“收集中”。
- 复制任何已发布问卷时生成新草稿，保留标题、说明、题目、范围规则、同步策略和建议完成时间，清空答卷，标题增加“（副本）”。
- 已发布问卷不能永久删除。即使前端被绕过，后端也必须拒绝。
- 状态转换必须在数据库事务中校验旧状态，避免并发请求越级转换。
- 100%采集完成时禁止重新开放只适用于家长填写任务；老师填写任务即使全部完成，仍允许恢复编辑。
- 老师填写任务结束后，所有填写人待办立即从待填写入口隐藏，逐生记录变为只读。
- 老师填写任务恢复编辑后，只为仍有未填写或草稿记录的负责人恢复聚合待办；本人负责记录已经全部完成的教师不重新出现待办。
- 复制老师填写任务时保留字段、范围规则、同步策略和填写分工，清空全部学生内容并将对象记录重置为未填写；新任务开始时按新的组织关系重新生成填写分配。

| student_name_snapshot | string | 发布时学生姓名 |
| class_id_snapshot | string | 发布时班级编号 |
| class_name_snapshot | string | 发布时班级名称 |
| reachable | boolean | 当前是否存在有效填写渠道；家长绑定变化时更新 |
| included_by | enum | class，表示由动态班级范围加入 |
| scope_status | enum | active/exited，退出范围后保留记录但停止待办 |
| first_included_at | datetime | 首次进入范围时间 |
| exited_at | datetime/null | 最近退出范围时间 |

唯一约束：`collection_task_id + subject_type + subject_id`。

### 11.5 collection_assignment

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 填写分配编号 |
| collection_task_id | string | 采集任务编号 |
| subject_id | string | 对应信息主体 |
| respondent_type | enum | guardian/teacher |
| respondent_id | string/null | 指定填写人；家长共享待办时可为空并在提交时锁定 |
| respondent_name_snapshot | string/null | 发布时填写人姓名快照，便于审计和历史展示 |
| assignment_rule | enum | bound_guardian/creator_teacher/homeroom_teacher/assigned_teacher |
| record_status | enum | pending/draft/completed |
| updated_at | datetime | 最近更新时间 |
| completed_at | datetime/null | 完成时间 |

唯一约束：`collection_task_id + subject_id`。家长填写任务中任一家长提交后锁定实际填写人；老师填写任务在开始时将每条学生记录明确分配给创建人或对应班主任。

### 11.6 teacher_collection_todo

该表是教师聚合待办的读模型或缓存，不是逐生状态的唯一数据源。也可以由 `collection_assignment` 实时聚合，但必须保证查询性能和状态一致。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 聚合待办编号 |
| collection_task_id | string | 采集任务编号 |
| respondent_teacher_id | string | 被分配教师 |
| todo_status | enum | pending/completed/closed |
| assigned_count | integer | 本人负责记录数 |
| completed_count | integer | 本人已完成记录数 |
| updated_at | datetime | 最近更新时间 |
| completed_at | datetime/null | 本人全部完成时间 |

唯一约束：`collection_task_id + respondent_teacher_id`。

状态规则：

- 任务收集中且本人存在未完成记录时为 `pending`。
- 本人负责记录全部完成时为 `completed`，不再进入待填写查询。
- 任务结束或归档时为 `closed`。
- 任务恢复编辑时，仅仍有未完成记录的负责人恢复为 `pending`。
- 计数必须由逐生填写分配聚合更新，不允许前端直接写入。

### 11.7 collection_answer

| 字段 | 类型 | 说明 |
|---|---|---|
| assignment_id | string | 填写分配编号 |
| field_id | string | 字段编号 |
| answer_json | json | 结构化答案 |

推荐答案结构：

```json
{
  "selectedOptionIds": ["option-1", "option-3"],
  "customText": { "option-3": "补充内容" }
}
```

- 单选和多选使用以上对象；单选的 `selectedOptionIds` 只能有1项。
- 量表题直接保存数值，例如 `4`。
- 简答题直接保存字符串，例如 `"家长填写的回答"`。
- 多项填空题保存结构化对象，例如 `{ "fillValues": { "sub-item-1": "小满", "sub-item-2": "小满" } }`；键使用填空项稳定编号，不使用可能被老师修改的名称。
- 单行文本、多行文本和日期保存字符串；数字保存数值或可精确解析的数字字符串。
- 老师填写任务保存草稿时允许缺少必填答案，标记完成时必须进行完整校验。

## 12. 接口建议

接口路径仅作为前后端评审基线，研发可以按现有服务规范调整命名，但不能改变状态和权限规则。

### 12.1 教师端

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/teacher/collections?scope=created&status=&mode=` | 查询当前教师创建的任务列表 |
| GET | `/teacher/collection-todos?status=pending` | 查询分配给当前教师且本人未全部完成的聚合待办 |
| GET | `/teacher/collection-todos/pending-count` | 查询当前教师待填写采集任务数，用于“我的”数量提示 |
| GET | `/teacher/students/{studentId}/collection-records?cursor=` | 查询当前教师有权查看的该学生已完成采集记录 |
| POST | `/teacher/collections` | 创建草稿 |
| PUT | `/teacher/collections/{id}` | 更新草稿，非草稿返回409 |
| DELETE | `/teacher/collections/{id}` | 永久删除草稿，非草稿返回409 |
| POST | `/teacher/collections/{id}/publish` | 发布或开始采集，保存范围规则并生成首批接收记录和填写分配 |
| POST | `/teacher/collections/{id}/end` | 收集中转已结束 |
| POST | `/teacher/collections/{id}/reopen` | 家长填写任务重新开放或学生采集恢复编辑 |
| POST | `/teacher/collections/{id}/archive` | 已结束转已归档 |
| POST | `/teacher/collections/{id}/restore` | 已归档转已结束 |
| POST | `/teacher/collections/{id}/copy` | 复制为新草稿 |
| GET | `/teacher/collections/{id}` | 查询基本信息和表单字段 |
| GET | `/teacher/collections/{id}/statistics` | 查询家长填写任务完成情况和逐题统计 |
| GET | `/teacher/collections/{id}/submissions?status=` | 查询家长填写任务答卷名单 |
| GET | `/teacher/collections/{id}/submissions/{submissionId}` | 查询单份家长答卷 |
| GET | `/teacher/collections/{id}/fields/{fieldId}/responses` | 查询问答题全部回答，支持search、class_id和cursor |
| GET | `/teacher/collections/{id}/fields/{fieldId}/sub-items/{subItemId}/responses` | 查询某个填空项的全部回答，支持search、class_id和cursor |
| GET | `/teacher/collections/{id}/student-records?status=&search=` | 查询老师填写任务逐生记录；创建人返回全部，填写人只返回本人负责记录 |
| GET | `/teacher/collections/{id}/student-records/{studentId}` | 查询某名学生的采集内容 |
| PUT | `/teacher/collections/{id}/student-records/{studentId}` | 保存逐生草稿或完成记录 |

接口权限规则：

- `scope=created` 必须按 `creator_teacher_id` 过滤，不能把分配给当前教师的其他人任务混入“我发起的”。
- 聚合待办接口只返回当前空间、任务收集中、本人存在未完成记录的老师填写任务。
- 待办卡片返回创建人、本人负责数和本人已完成数，不返回其他教师负责学生的明细。
- 逐生详情与保存接口必须校验当前教师是任务创建人或该学生记录的 `respondent_id`。
- 非创建人不得调用结束、恢复、归档、复制和删除接口。
- 开始学生采集时，`assignment_mode=homeroom` 且存在无法匹配有效班主任的班级，返回422和缺失班级编号，不创建部分任务。
- 发布接口必须按当前账号权限再次校验全部班级编号，禁止信任前端传入的年级或班级集合。
- 组织服务的班级成员、在校状态和家长绑定变化事件触发范围对账；同一事件重复投递不得生成重复接收记录或待办。
- 动态对账只处理收集中的任务。已结束和已归档任务保留历史，不接收新增学生。
- 学生采集历史接口必须复用原任务和填写分配权限，只返回已提交或已完成记录，并支持服务端分页。

### 12.2 家长端

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/parent/students/{studentId}/questionnaires/pending` | 查询当前学生待填写问卷 |
| GET | `/parent/students/{studentId}/questionnaires/{id}` | 查询问卷题目和当前提交状态 |
| POST | `/parent/students/{studentId}/questionnaires/{id}/submissions` | 提交答卷 |

### 12.3 返回码约定

| 状态码 | 场景 |
|---|---|
| 400 | 参数格式错误 |
| 403 | 无空间、问卷或学生权限 |
| 404 | 问卷或答卷不存在 |
| 409 | 状态不允许、已经提交或版本冲突 |
| 422 | 题目、范围或答案业务校验失败 |

提交答卷接口应支持幂等键。网络重试不能产生重复答卷。

## 13. 异常与边界场景

| 场景 | 处理 |
|---|---|
| 草稿标题或题目不完整 | 可以保存草稿，不能发布 |
| 发送范围为空 | 禁止发布，保留当前选择 |
| 前端提交无权限班级 | 发布接口返回403，不创建部分任务或接收记录 |
| 全部目标学生未绑定家长 | 允许发布；完成率为0，所有目标学生进入未绑定列表，家长端不生成待办 |
| 收集中班级新增或转入学生 | 幂等新增接收记录；已绑定家长立即生成待办，未绑定则等待绑定事件 |
| 收集中学生转出或离校 | 停止未完成待办并标记已退出；已提交答卷和审计记录保留 |
| 已退出学生重新进入范围 | 恢复原接收记录，不重复创建，不清空原有内容 |
| 问卷结束后班级新增学生 | 不加入；重新开放后仅动态班级范围执行一次成员对账 |
| 建议完成时间早于当前时间 | 允许发布；发布后立即显示已到建议完成时间，但问卷仍保持收集中 |
| 建议完成时间已到 | 问卷继续收集，教师端显示逾期提示 |
| 家长打开后老师结束收集 | 页面可继续查看，提交时返回409并提示已结束 |
| 两位家长同时提交同一学生 | 数据库唯一约束只接受第一份，另一份返回409 |
| 老师连续点击结束或归档 | 接口幂等返回当前状态，不产生重复数据 |
| 已结束后重新开放 | 原答卷和完成率保留，未完成人员可以继续提交 |
| 已结束且已完成数等于可送达数 | 不展示重新开放；接口返回409，避免制造无法新增答卷的收集状态 |
| 已归档问卷恢复 | 恢复到已结束，不生成家长待办 |
| 问卷复制 | 生成独立草稿，不复制答卷和统计结果 |
| 题目无人回答 | 统计为0，不报错，不隐藏题目 |
| 简答回答超长 | 前后端统一限制长度，建议最多1000个字符 |
| 大规模全校问卷 | 列表、答卷和简答回答均由服务端分页，前端不得一次加载全部数据 |
| 老师填写任务保存不完整内容 | 允许保存为草稿；标记完成时返回422并定位缺失字段 |
| 学生采集已结束时继续编辑 | 保存接口返回409；老师恢复编辑后再保存 |
| 学生记录已完成后再次修改 | 采集中允许修改并保留完成状态，记录更新时间和操作者 |
| 选择各班班主任但某班未配置班主任 | 禁止开始采集，返回缺失班级；不得只生成部分分配 |
| 同一班主任负责多个班级或多名学生 | 仍只生成一个聚合待办，进度按本人全部负责记录计算 |
| 班主任关系在开始采集后发生变化 | 历史填写分配保持不变，不自动转交，避免任务范围和责任人漂移 |
| 填写人尝试查询其他班主任负责的学生 | 接口返回403，前端不展示该记录 |
| 填写人完成本人最后一条记录 | 聚合待办原子更新为完成，“我的”数量和待我填写列表同步减少 |
| 创建人结束学生采集 | 所有未完成聚合待办关闭，填写人已打开页面再次保存时返回409 |
| 创建人恢复学生采集 | 仅仍有未完成记录的负责人恢复待办，已全部完成的负责人不出现待办 |
| 学生采集记录仍为未填写或草稿 | 不进入学生详情采集记录页签 |
| 采集任务结束或归档 | 已完成记录继续在学生详情展示，未完成记录不展示 |
| 学生转班或离校 | 历史记录继续按学生编号关联，不随当前班级丢失 |
| 不同采集包含同名字段 | 分别保留在各自采集记录中，不自动合并或覆盖基础信息 |

## 14. 非功能要求

### 14.1 性能

- 问卷列表首屏接口建议在1秒内返回。
- “我的”待办数量接口建议在500毫秒内返回，可按教师和任务状态建立索引或使用聚合读模型。
- 统计接口在1万份答卷规模下建议在2秒内返回，可使用预聚合或缓存。
- 答卷列表和简答回答默认每页20条。
- 统计计算应由后端完成，前端只负责展示，避免大规模答卷传到手机端计算。

### 14.2 安全与隐私

- 教师只能查看授权空间内本人创建的任务，以及明确分配给本人的学生记录。
- 任务创建人可以查看任务全部目标记录；普通填写人不能查看其他填写人的记录和答案。
- 家长只能查看与本人绑定学生相关的问卷。
- 所有写操作记录操作者、时间、旧状态和新状态。
- 学生姓名、学号和家长关系属于敏感信息，接口日志不得完整输出答卷内容。

### 14.3 可用性与无障碍

- 手机端主要触控区域不小于44px。
- 列表、创建页、详情页和答卷页必须独立纵向滚动，不能因内容过多无法继续操作。
- 底部浮层使用统一组件，支持遮罩关闭、明确标题和无障碍名称。
- 状态反馈使用短提示，不在页面长期堆叠说明文案。

### 14.4 一致性

- 教师预览和家长真实填写复用同一题目渲染组件。
- 前后端共享题型、状态和答案结构定义，避免字符串口径不一致。
- 日期时间统一使用学校时区保存和展示，服务端存储建议使用 UTC（协调世界时）。

## 15. 验收标准

### 15.1 创建与发布

- [ ] 新建问卷时题目列表为空，不自动添加单选题。
- [ ] 家长填写任务不重复展示“题目”标题，分组开关和添加题目入口保持清晰；题目为0时不重复展示第二个添加入口。
- [ ] 问卷说明最多500个字符，编辑态最多展开约6行，失焦、确认发布和详情中完整展示。
- [ ] 新建和编辑家长填写任务时可从顶部预览当前未保存内容，底部仍只保留保存草稿和下一步两个操作。
- [ ] 单选、多选、评分、多项填空、问答、日期和数字题均可创建、保存和发布。
- [ ] 多项填空题支持2至6个子项，子项名称不可为空或重复，并可独立设置必填。
- [ ] 量表默认5级，可配置2至10级，家长作答和统计按实际级数展示。
- [ ] 页面不提供复制题目能力。
- [ ] 自定义填写选项只通过“更多”入口添加。
- [ ] 页面按年级聚合后端授权班级，使用左侧年级、右侧班级的双栏级联。
- [ ] 领导、管理员可勾选全部年级；科任老师只能看到并选择后端返回的实际任教班级。
- [ ] 发送范围与教师个人信息页复用同一班级级联组件，不提供指定学生入口。
- [ ] 建议完成时间默认关闭，关闭时问卷可以正常发布。
- [ ] 发送范围为空、标题为空或没有有效题目时不能发布。
- [ ] 已选班级默认跟随收集期间的学生新增和转入。
- [ ] 新增学生接收记录与待办幂等，转出学生不再计入当前完成率但历史答卷仍保留。

### 15.2 家长填写

- [ ] 只有目标范围内、可送达、未提交且问卷收集中的学生出现待办。
- [ ] 必答题和自定义填写内容均完成后才能提交。
- [ ] 多项填空题只校验必填子项，可选子项未填写不阻止进入下一题或提交。
- [ ] 同一学生无法提交第二份答卷。
- [ ] 老师结束收集后，家长提交失败并看到明确提示。
- [ ] 建议完成时间到达后，老师未结束收集时家长仍可提交。

### 15.3 数据与答卷

- [ ] 完成率分母只使用可送达学生数。
- [ ] 完成情况只在数据页整体展示一次。
- [ ] 多选题比例允许总和超过100%。
- [ ] 简答不超过5条时全部展示，超过5条时只展示高频词和最新2条。
- [ ] 多项填空按子项分别显示有效回答；超过5条时可进入对应子项的全部回答页。
- [ ] 全部回答支持搜索、班级筛选和每次20条加载。
- [ ] 答卷页支持已完成、未完成和未绑定筛选。
- [ ] 产品中不存在提醒未完成家长入口和相关接口。

### 15.4 生命周期

- [ ] 收集中问卷可以结束收集，但不能直接归档或删除。
- [ ] 未达到100%采集的已结束问卷可以重新开放、复制和归档。
- [ ] 已完成数等于可送达数且可送达数大于0时，已结束问卷不能重新开放。
- [ ] 已归档问卷可以恢复到已结束和复制。
- [ ] 只有草稿可以永久删除，删除前有二次确认。
- [ ] 已发布问卷不存在永久删除入口，后端也拒绝删除。
- [ ] 顶部始终只有收集中、已结束、草稿3个页签。
- [ ] 已归档通过已结束页中的二级入口访问。

### 15.5 页面质量

- [ ] 问卷列表不展示重复状态标签、百分比和点击说明。
- [ ] 问卷详情不展示发送对象和状态标签。
- [ ] 详情只有数据、答卷两个页签，不存在概览和题目分析重复页签。
- [ ] 多答卷、长问卷和全部回答页面均可以正常滚动到底部。
- [ ] 页面中不存在“以下为N份有效答卷的描述性统计”等解释性废话。

### 15.6 统一采集编辑器

- [ ] 点击新建后直接进入采集编辑器，不要求先选择互斥任务类型。
- [ ] `添加内容`提供`普通题型 / 成长数据`两个页签。
- [ ] 同一任务可以同时包含普通题目、记录日期和任意多个本校已启用成长字段。
- [ ] 问卷成长字段与PC设置中的启用结果一致，不按问卷能力再次过滤字段。
- [ ] 选择任一成长字段后自动生成记录日期规则，各字段可以分别选择。
- [ ] 填写人选择时日期题必填；本次统一日期时发布前必须设置日期且填写端不展示日期题。
- [ ] 一份任务只有一个成长记录日期，不出现第二个日期或成长数据组。
- [ ] 记录日期缺失时阻止成长记录保存，不能用提交时间兜底。
- [ ] 老师或家长填写在确认发布时统一设置，切换填写人不会清空或改变内容。
- [ ] 老师或家长提交成长字段后立即生成带测量日期的成长记录，不要求老师再次录入。
- [ ] 学期目标不出现在本期采集编辑器中。
- [ ] 确认开始页默认展示“填写分工－我来填写”，点击后通过底部浮层切换为“各班班主任”，不增加第4步。
- [ ] 选择“我来填写”时全部学生记录分配给创建人；选择“各班班主任”时按班级快照正确分配。
- [ ] 任一目标班级没有有效班主任时不能开始采集，且不生成部分对象记录或待办。
- [ ] 选择范围后每名学生生成一条未填写记录，不生成多条教师待办。
- [ ] 学生名单支持搜索和全部、待完成、已完成筛选；待完成合并未填写与草稿，草稿行显示“待继续”并优先排列。
- [ ] 逐生表单可以保存不完整草稿，完成时校验全部必填字段。
- [ ] 已完成记录在采集中可以再次修改，保存后仍为已完成。
- [ ] 结束采集后记录只读；恢复编辑后可继续修改，即使完成率为100%。
- [ ] 老师填写任务使用逐生记录和教师聚合待办；家长填写任务使用答卷和家长端待办。
- [ ] “我发起的”只展示当前教师创建的任务，其他人创建但分配给当前教师的任务只进入“待我填写”。
- [ ] 同一采集任务分配给同一教师的多条学生记录只生成一个聚合待办。
- [ ] “我的”底部导航和头像区下方仅在存在待填写采集时显示任务数量，无待办时完全隐藏。
- [ ] 待我填写卡片按本人负责范围展示进度，进入后只显示本人负责学生。
- [ ] 普通填写人无法查看其他班主任的学生，且不展示结束、恢复、归档和复制操作。
- [ ] 本人负责记录全部完成后，待办数量自动减少；任务从待我填写列表消失。
- [ ] 创建人结束采集后所有填写人待办关闭；恢复编辑时仅未全部完成的负责人重新出现待办。
- [ ] 以教师为信息主体的问卷仍不可创建，不因学生采集待办能力而生成以教师为信息主体的问卷待办。

### 15.7 学生详情采集记录

- [ ] 学生详情展示成长报告、评价记录、采集记录三个页签，文字在手机宽度内完整显示。
- [ ] 学期选择和五育能力模型只在成长报告页签展示。
- [ ] 采集记录同时包含有权限的家长填写任务答卷和已完成学生采集记录。
- [ ] 未填写和草稿记录不进入学生详情。
- [ ] 记录卡片只展示名称、类型、完成时间和实际填写人，不展示重复完成状态和答案摘要。
- [ ] 点击记录进入独立详情，问答内容使用连续列表并可正常滚动到底部。
- [ ] 从采集详情返回后仍停留在采集记录页签。
- [ ] 已结束和已归档任务的完成记录仍可查看。
- [ ] 无权限教师不能通过学生详情查看其他任务或其他填写人的敏感答案。
- [ ] 采集答案不会自动覆盖学生基础信息。

### 15.8 采集数据边界

- [ ] 数据去向跟随具体字段，不跟随整份采集任务。
- [ ] 普通自定义问题没有数据项关联入口，也不会根据问题文案自动匹配。
- [ ] 成长字段完成后形成带记录日期的学生成长记录。
- [ ] 成长字段按统一字段键进入学生详情和档案；同一任务中的普通题目只保留答卷。
- [ ] 期末报告按配置读取标准成长数据，不读取整份混合采集答卷。

## 16. 指标

首版上线后建议记录以下指标：

| 指标 | 说明 |
|---|---|
| 问卷发布成功率 | 进入确认发布后成功发布的比例 |
| 家长提交完成率 | 已完成学生数 ÷ 可送达学生数 |
| 平均完成时长 | 家长打开问卷到成功提交的时间 |
| 草稿继续编辑率 | 保存草稿后再次进入编辑的比例 |
| 结束后重新开放率 | 判断建议完成时间和结束机制是否合理 |
| 归档使用率 | 已结束问卷中被归档的比例 |
| 提交冲突率 | 因重复提交或状态变化返回409的比例 |
| 学生采集完成率 | 已完成逐生记录数 ÷ 目标学生数 |
| 逐生草稿继续率 | 保存逐生草稿后再次打开并完成的比例 |
| 恢复编辑率 | 已结束学生采集被恢复编辑的比例，用于判断纠错需求 |
| 班主任分工使用率 | 老师填写任务中选择“各班班主任”的任务比例 |
| 教师待办完成率 | 已完成聚合待办数 ÷ 已生成聚合待办数 |

不以“提醒点击率”为指标，因为 V1 不提供提醒功能。

## 17. 依赖与风险

### 17.1 依赖

- 教师空间和组织权限服务。
- 当前有效班主任关系和教师账号状态。
- 班级、学生和家长绑定关系。
- 组织服务的班级成员、在校状态和家长绑定变更事件。
- 教师端应用内待办入口和数量查询能力。
- 家长端待办或消息入口。
- 服务端分页、统计和幂等能力。
- 操作审计日志。

### 17.2 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 全校问卷答卷量大 | 手机端卡顿、统计接口超时 | 服务端分页、预聚合、缓存 |
| 动态班级成员变化导致人数波动 | 老师看到目标人数和完成率变化 | 保存范围规则与接收记录，变更进入审计日志，统计只计算当前有效目标 |
| 组织事件重复或乱序 | 重复待办、学生状态回退 | 接收记录唯一约束、事件版本号和幂等对账 |
| 多家长重复提交 | 产生多份答卷 | 学生维度唯一约束和幂等提交 |
| 状态并发操作 | 问卷越级转换 | 事务校验旧状态和版本号 |
| 简答高频词误导 | 用户误认为 AI 结论 | 只展示词频和次数，不生成结论 |
| 已发布问卷误删 | 数据不可恢复 | 数据层禁止删除，使用归档代替 |
| 班主任关系缺失或错误 | 任务无法正确送达 | 开始前整体校验，返回缺失班级并阻止部分发布 |
| 聚合待办与逐生状态不一致 | 角标或进度错误 | 逐生记录作为事实来源，事务更新或可重建聚合读模型 |
| 发布后班主任发生变化 | 原负责人无法继续填写 | V1保持发布快照并记录审计，后续提供受控转交能力 |

## 19. 当前 Demo 与正式开发差异

当前 Demo 使用浏览器本地数据模拟教师端和家长端联动，主要用于确认页面、信息层级和状态闭环。正式开发不能直接沿用本地存储方案，必须完成以下替换：

1. 表单字段、采集任务、对象记录、填写分配和答案写入服务端数据库。
2. 所有状态转换和删除规则由后端校验。
3. 家长待办从真实绑定关系和目标快照生成。
4. 统计由后端按统一口径计算。
5. 大规模列表使用服务端分页。
6. 提交接口实现学生维度唯一约束和幂等。
7. 增加权限、审计、异常监控和数据备份。
8. 老师填写任务使用服务端逐生记录接口，不以整份问卷 JSON 覆盖保存。
9. 老师填写任务待办接入真实教师账号、班主任关系和应用内待办服务。
10. 待我填写接口按当前教师服务端过滤逐生记录，不能只在前端过滤。
11. 以教师为信息主体的问卷开放前复用统一教师待办底座，并补充教师作为信息主体的提交页面；本期以教师为信息主体的问卷仍不创建待办。
12. 当前 Demo 使用固定的班主任 Mock（模拟）映射展示分工效果；正式开发必须使用真实班主任关系，并执行缺失班主任的整体发布校验。
13. 当前 Demo 在前端聚合学生采集历史；正式开发必须由服务端按学生、任务权限和填写分配过滤并分页返回。
