# 小红花与成长币双货币体系 · 影响评估

- 版本：v1.0
- 日期：2026-09-20
- 面向：学校管理层 / 产品决策
- 范围：教师手机端、学校端后台、学生终端（货柜机）、家长端、课堂大屏、SaaS 运营端与产品文档
- 说明：本文只讲业务口径与影响范围，不含技术实现细节

## 一、一句话结论

现在“班级兑换”和“货柜兑换”花的是同一种货币（成长币）。改成“货柜用成长币、班级用小红花”之后，规则本身变简单了，但因为它动的是货币的定义、来源、用途和清零口径，属于**体系级改造**：涉及 6 个端、40 多个源文件、4 篇产品文档和 200 多个自动化测试脚本，建议分三期上线。

## 二、要解决的问题

1. 成长币的算法（预算、阳光保底、排名奖励、结算周期）老师理解不了，也没法给小朋友解释。
2. 班级奖励本来就是班级老师自己出的，不需要受学校预算约束，却被迫走同一套复杂规则。
3. 需要一种“看得见、说得清”的课堂激励符号。

## 三、口径定稿（本次变更的规则基准）

| 项目 | 成长币 | 小红花（新增） |
| --- | --- | --- |
| 谁能用 | 已开通货柜机的学校 | 所有学校 |
| 怎么来 | 学校按配置规则统一发放 | 不需要发放，评价加分即得 |
| 开关 | SaaS 运营端“是否开启积分银行”，开启后才能配货柜机、才能发币 | 与货柜机无关，始终可用 |
| 用在哪 | 只能在货柜机兑换 | 只能用于班级兑换 |
| 受不受预算控制 | 受（每班总预算，阳光普照 + 得分奖励） | 不受 |
| 进不进积分银行 | 进（可用 / 已存 / 利息） | 不进，与成长币完全解耦 |
| 清零规则 | 按发放周期结算 | **永不清零，长期累计** |
| 扣分是否影响 | 不涉及 | 由学校统一设置“可兑换小红花是否扣除扣分”，默认不扣 |
| 老师能否自设 | 否 | 否，学校统一设置后老师只读 |

## 五、逐域影响点

### 5.1 规则与口径（“花不清零”是最大变量）

原设计里花是派生值（本学期加分），学期结束自动归零，几乎不用存数据。改成永不清零后：

1. 花变成学生的**长期资产**：花数 = 历史累计加分（或净得分）− 历史累计已消费，需要能跨学期、跨学年查询。
2. 与“加扣分按本学期统计”的展示口径不一致：卡片上的加分是按周期统计的，花是终身的，老师会问“学期初加分清零了，花怎么还在”，需要在兑换页给出一句明确口径。
3. 转班、转学、复学、毕业时的花归属需要规则（跟人走还是跟班走、毕业是否清零、毕业后能否查询）。
4. 撤销历史评价（含上学期）会直接改变花数，需要确认撤销的时间窗口与回退规则。
5. 学校中途切换“扣分是否扣减花”的口径时，历史花数是否追溯重算需要决策；不追溯会出现“切换前后同名不同算法”。
6. 长期累计意味着数据持续增长，需要余额结转或快照机制，否则每次兑换都要全历史汇总。

### 5.2 教师手机端（6 处）

| 页面 | 现状 | 变更后 |
| --- | --- | --- |
| 学生卡片加分展示 | 只有分值数字 | 加分色片前增加一朵小红花图标；扣分不加；跟随“显示加扣分”总开关 |
| 兑换奖励页 | 显示成长币余额、售价“N 成长币 / 人”、按成长币判断余额不足、兑换写成长币流水 | 显示可兑换小红花数量、售价“N 朵 / 人”、按花判断、兑换写小红花消费流水 |
| 成长币记录页 | 班级兑换属于成长币支出的一类 | 班级兑换移出成长币记录，改为小红花独立时间线；成长币记录只留货柜兑换、清空、银行 |
| 学生详情资产 | 只有成长币卡（可用 / 已存 / 结算预估） | 增加小红花卡（累计获得 / 已使用 / 当前可用），不参与预估与利息 |
| 清空成长币 | 清空对象是成长币 | 保持不变，但必须与花严格分离，避免误清 |
| 我的 - 货币发放 | 发币配置与记录入口 | 仅在开通积分银行的学校显示；未开通学校不出现该入口 |

需新增：小红花明细页（获得 + 使用），保证“老师能查、家长能问”。

### 5.3 学校端 PC 后台

1. 新增「小红花设置」：唯一设置项是“可兑换小红花是否扣除扣分”，学校统一设置，需明确由谁操作（校长 / 学校管理员）。
2. 「货柜机配置中心、货币发放管理、历次发币记录、储蓄银行」在未开通积分银行的学校需要隐藏，避免点进去看到空白。
3. 数据看板里的“成长币发放 / 兑换”统计口径需要与两币体系对齐。

### 5.4 学生终端与货柜机

1. 货柜机只服务成长币，班级兑换不再从终端扣币。
2. 终端余额、兑换流程本身不变，但同一个班级里两套账要能说清：货柜兑换看成长币，班级兑换看花。
3. 存量学校要注意：现有的成长币不能再用于班级兑换，使用场景变窄，需要提前跟学校说明。

### 5.5 家长端

1. 家长端现有的成长币与积分银行展示需要补上小红花，否则家长会认为孩子“表现没被记录”。
2. 建议花只做只读展示（累计获得、已使用、当前可用），银行入口维持原样。

### 5.6 课堂大屏

1. 加分色片是否同步加花图标待定，建议同步，避免老师投屏看到的和手机端不一致。
2. 大屏不新增花数展示，课堂上不增加信息负担。

### 5.7 数据与工程

1. 消费流水增加“币种”字段区分成长币与小红花，两套币共用一套流水底层，避免后期维护成本翻倍。
2. 币种术语已经收敛在同一个模块，新增花只需扩展同一处，不需要改遍全站文案。
3. 需要新增：花的累计获得、已使用与余额的计算口径，以及长期累计下的查询性能方案。
4. 历史数据：已发生的班级兑换仍记在成长币流水里，是否迁移需要决策（建议不迁移，新学期起执行新规则）。

### 5.8 文档与 PRD

1. 新增《小红花与成长币双货币体系》PRD。
2. 同步：教师手机端 UI 规范、家长端 UI 规范、课堂大屏自适应设计规范、成长币相关既有文档。

### 5.9 测试与验收

1. 与成长币、兑换奖励、成长币记录、家长端相关的自动化脚本需要同步更新（现有 202 个）。
2. 新增验收点：花与币互不影响、花不清零、撤销评价对花的影响、扣分口径切换、未开通积分银行学校的入口显隐。

## 六、需要拍板的决策点

| 序号 | 决策点 | 可选项 | 建议 |
| --- | --- | --- | --- |
| 1 | 花是否真的永不清零 | 永不清零 / 按学年清零 / 毕业清零 | 永不清零，毕业只读保留 |
| 2 | 花跟人还是跟班 | 跟学生个人 / 跟班级 | 跟学生个人 |
| 3 | 转学、复学、毕业时的花 | 保留 / 清零 / 转出 | 保留并冻结 |
| 4 | 扣分口径切换是否追溯 | 不追溯 / 全量重算 | 不追溯，并在设置页写清生效时间 |
| 5 | 学校统一设置由谁操作 | 校长 / 学校管理员 / 两者 | 两者都可 |
| 6 | 历史班级兑换是否迁到花 | 迁移 / 不迁移 | 不迁移 |
| 7 | 课堂大屏是否加花图标 | 加 / 不加 | 加 |
| 8 | 家长端本轮是否展示花 | 展示 / 暂不展示 | 只读展示 |

## 七、建议的分期

| 期次 | 目标 | 主要内容 |
| --- | --- | --- |
| 第一期 | 老师能用、能讲清 | 花的口径与数据、学生卡片花图标、兑换奖励按花计算、花与成长币记录分离 |
| 第二期 | 可查、可解释 | 小红花明细页、家长端只读展示、学校端设置界面与统计口径 |

## 八、工作量粗估

| 阶段 | 相对工作量 | 说明 |
| --- | --- | --- |
| 第一期 | 大 | 涉及规则、数据、教师手机端核心流程 |

## 九、主要风险

1. **老师认知风险**：两种货币并行，如果不给一句话口径，很容易被理解成“两种积分”，反而更难解释。
2. **数据风险**：花不清零加撤销评价会让历史数据被追溯修改，需要保留修改痕迹。
3. **口径风险**：学校中途切换扣分口径会导致花数跳变，需要提前告知并写清生效时间。
4. **迁移风险**：老学校的成长币不能再用于班级兑换，需要提前沟通，避免老师以为“钱变少了”。
5. **返工风险**：手机端、大屏、家长端三处口径不同步会反复返工，建议先定口径再动手。
