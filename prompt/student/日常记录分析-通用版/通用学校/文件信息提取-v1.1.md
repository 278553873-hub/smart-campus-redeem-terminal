# 📌 文件信息提取 v1.1

你需要根据我提供的图片内容，**判断图片中的事件类型**，并提取相关信息，最终返回结果必须是 **JSON**，且返回结构中必须包含 `image_content` 字段。

用户**可能会额外提供**一段**老师录入的文字或语音转写原文**（下称“补充评论”），但**补充评论并非必传**。
若提供了补充评论，应结合图片内容与补充评论判断事件类型、提取相关字段；`comment` 按对应事件类型的规则生成。若未提供补充评论，则仅基于图片内容输出最终结果。

## 输出格式强制要求

* **最终返回结果必须是合法 JSON**
* **只允许返回 JSON 本身，不允许输出任何无关信息**
* **禁止输出 Markdown 代码块、解释说明、分析过程、前后缀文本、提示语或备注**
* **输出内容必须能被直接当作 JSON 解析**
* **枚举字段闭合要求**：当 `event_type = "competition_event"` 时，`competition_level` 与 `competition_type` 属于必填决策字段，不是可选摘录字段；必须从各自枚举中选择一个最接近值，严禁输出空字符串、`null`、`未知` 或省略字段；若 `competition_level` 在现有明确线索下仍无法稳定识别，则默认选择“校级”

## 0. 输入信息来源（新增规则）

你可能会收到以下一类或两类输入：

* **图片内容**：用于识别比赛、证书、活动现场、文字说明等核心事实
* **补充评论（可选）**：老师录入的文字或语音转写原文，可补充班级、学校、身份、表现描述等上下文

你必须遵守以下原则：

* **补充评论不是必传**：若没有补充评论，则所有判断与字段提取都只基于图片内容完成；只有在补充评论明确提供时，才允许纳入分析
* **图片仍是重要事实依据**：比赛名称、参赛人员、奖项、赛项、日期、赛区等核心事实，优先从图片中识别；但如果老师补充评论对同一事实给出了明确且冲突的表述，则以老师补充评论为准
* **补充评论不仅可补充上下文，也可覆盖冲突事实**：例如学生班级、学校、老师原始评价语气、现场补充说明等，在比赛事件或证书事件中可用于丰富最终 `comment`；一般事件的 `comment` 按第4节规则处理。若其中对比赛名称、参赛人员、奖项、赛项、时间等事实有明确修正，按老师补充评论输出
* **只允许使用明确提供的信息**：仅可使用图片中明确可见的信息，以及补充评论中明确写出的信息；禁止推断、脑补、补全缺失事实。但 `competition_event` 下的 `competition_level`、`competition_type` 是封闭枚举决策字段，不按“缺失事实”处理：级别无法稳定识别时默认“校级”，类型无法稳定归入艺术类/科技类/体育类时默认“其他类”
* **遇到冲突时以老师补充评论为准**：若补充评论与图片在比赛名称、参赛人员、奖项、赛项、时间等核心事实冲突，必须以老师补充评论为准，且不要混合两套冲突信息

**以下 `comment` 融合与改写要求仅适用于比赛事件和证书事件；一般事件的 `comment` 按第4节规则处理。**

* **最终 comment 必须融合有效补充信息**：如果补充评论中明确提供了班级、学校、身份、表现描述，或对图片事实做了明确修正，应自然融入最终 `comment`
* **`comment` 生成顺序必须固定**：先独立提取图片中的事实信息并写入 `image_content`，再阅读老师补充评论，最后将两部分信息整理合并为最终综合分析结果；若两者冲突，必须以老师补充评论中的明确表述为准
* **`image_content` 与 `comment` 的职责必须区分**：`image_content` 只记录图片中可直接识别出的内容，不得混入补充评论；`comment` 必须是合并图片内容与补充评论后的综合分析结果
* **`comment` 是最终综合分析结果内容**：必须基于前述合并结果生成，输出自然、完整、可直接展示的最终句子；不要机械拼接原文，不要只重复图片文字，也不要只照搬老师评论

## 1. 事件类型判断（必填字段逻辑）

你必须结合图片内容与补充评论综合判断事件类型，字段：`event_type`；若两者冲突，以老师补充评论中的明确表述为准
可选枚举：

* **competition\_event**（比赛事件）
* **certificate\_event**（奖状/证书事件）
* **general\_event**（一般事件）

判定优先级如下：

1. **competition\_event**：先根据图片识别是否为比赛、竞赛、评比、展评、展览入选、作品评选、活动选拔等带有明确参与结果的场景，再结合老师补充评论校正；若最终合并后的结果能清晰识别比赛事件所需事实字段（参赛人员、活动名称、项目/主题、结果描述），则判定为 `competition_event`。即使图片形式是奖状、荣誉证书或获奖证明，只要证书内容承载的是某项比赛/评比/展评/入选/选拔活动的参与结果，也应优先按 `competition_event` 处理；不得仅因 `competition_level` 或 `competition_type` 没有直接文字线索而改判其他事件类型
2. **certificate\_event**：先根据图片识别是否为奖状、荣誉证书、表彰文件、获奖证明等证书场景，再结合老师补充评论校正；若最终合并后的结果只属于个人荣誉、校内表彰、身份称号或行为表扬，不承载具体比赛/评比/展评/入选/选拔活动结果，但能明确识别学生姓名与证书内容，则判定为 `certificate_event`；例如“优秀学生”“三好学生”“文明之星”等校内荣誉或表彰
3. **general\_event**：在先提取图片信息、再阅读老师补充评论并完成合并后，仍然既不满足比赛事件，也不满足奖状/证书事件，或关键信息缺失无法稳定判断

### competition\_event 必填字段

* `participants`
* `competition_name`
* `comment`
* `project_name`
* `competition_level`
* `competition_type`

如果图片初步属于比赛/竞赛获奖场景，但在先提取图片信息、再结合老师补充评论后，除 `competition_level`、`competition_type` 外的必填事实字段仍无法获取（为空、缺失、无法识别），则**不能**判定为 `competition_event`。
`competition_level`、`competition_type` 只要已经判定为 `competition_event`，就必须基于现有明确线索选择最接近枚举值，不得因未逐字出现级别或类型名称而留空或降级；若 `competition_level` 在现有明确线索下仍无法稳定识别，则默认选择“校级”。
此时：

* 若最终合并后的信息仍明确属于奖状/证书/表彰场景，则判定为 **`certificate_event`**
* 若连奖状/证书场景也无法成立，则判定为 **`general_event`**

### certificate\_event 必填字段

* `participants`
* `comment`

当图片初步识别为奖状、荣誉证书、表彰文件、获奖证明等证书场景时，必须先判断证书内容是否承载了比赛/竞赛/评比/展评/入选/选拔等活动结果；若承载此类活动结果，必须优先尝试判定为 **`competition_event`**，并为 `competition_level`、`competition_type` 选择最接近的枚举值。只有在最终合并后的信息不承载具体活动结果、仅体现个人荣誉/校内表彰/身份称号/行为表扬，且至少能明确识别到学生姓名与证书内容时，才可判定为 **`certificate_event`**。
此类事件中：

* `competition_name` 若无真实比赛、评比、展评、入选或选拔活动名称，必须为空字符串
* `project_name` 若无真实赛项、作品、项目、活动主题或展示项目名称，必须为空字符串
* `competition_level` 仅在确认为非活动结果型证书时为空字符串；若存在可归入 `competition_event` 的活动结果，必须选择最接近级别
* `competition_type` 仅在确认为非活动结果型证书时为空字符串；若存在可归入 `competition_event` 的活动结果，必须选择最接近类型

如果 `certificate_event` 连 `participants` 或 `comment` 都无法获取，则必须判定为：

➡️ **general\_event（一般事件）**
➡️ 并且所有字段一律设置为空字符串或空数组（即所有值为空）。

## 2. 当 event\_type = "competition\_event" 时的字段要求

* **仅提取图片中明确可见的信息，以及补充评论中明确给出的信息；若两者冲突，以老师补充评论中的明确表述为准**
* `competition_event` 必填字段不允许为空；其中 `participants`、`competition_name`、`comment`、`project_name` 必须来自图片或补充评论中的明确内容
* 若图片是证书/奖状场景，但无法明确识别学生、活动名称/主题、活动结果等核心事实 → 优先判为 `certificate_event`，而不是直接判空
* 非必填字段如果缺失 → 用空字符串
* `competition_level` 与 `competition_type` 在 `competition_event` 中必须选择最接近的枚举值，不允许为空；它们不要求图片逐字写出“国家级/省级/市级/区级/校级”或赛事类型名称，必须依据图片或补充评论中明确出现的比赛名称、赛项内容、赛区/选拔阶段、活动范围、落款单位、盖章单位、组织单位等信息综合判断；若 `competition_level` 在现有明确线索下仍无法稳定识别，则默认选择“校级”
* `competition_level` 判断应以学生本次实际参与、获奖、晋级截止或被表彰的层级为准，而不是只看赛事总名称的最高层级；若总赛事名称与赛区、选拔阶段、落款或盖章体现的实际层级不同，应优先采用实际层级
* `competition_type` 判断应以比赛名称、赛项名称、项目内容或证书文本中能直接支持的类别为准；若无法稳定归入艺术类、科技类或体育类，必须选择“其他类”，不得留空

## 当图片中出现奖状、证书、获奖证明、表彰文件、荣誉证书等场景时，必须严格遵循以下规则，否则跳过以下规则：

* 若该证书在先提取图片信息、再阅读老师补充评论并完成合并后，能清晰包含比赛、竞赛、评比、展评、展览入选、作品评选、活动选拔等活动名称或活动结果，并满足 `competition_event` 的事实字段要求，则判定为 `competition_event`；不得因为 `competition_level`、`competition_type` 没有直接文字线索而改判或留空
* 对于画展、作品展、评选、展评、入选、选拔、展示活动等结果型证书，只要能明确识别学生、活动名称或主题、参与结果，就应作为 `competition_event`；`competition_level` 必须从落款、盖章、组织单位、活动范围或学校/区域信息中选择最接近级别，无法稳定识别时默认“校级”；`competition_type` 无法稳定归入艺术类/科技类/体育类时默认“其他类”
* 若该证书在最终合并后的结果中只体现荣誉/表彰/奖状属性，且不承载具体比赛、评比、展评、入选或选拔活动结果，但仍能明确识别学生姓名与证书内容，则判定为 `certificate_event`
* 若在完成合并后，学生姓名或证书内容仍无法识别，则判定为 `general_event`

1️⃣ 学生姓名识别规则

* **participants 字段仅允许填写学生姓名**
* **学生姓名的提取顺序必须为：先读取图片中明确可见的学生姓名，再阅读老师补充评论中的学生姓名信息，最后合并；若两者冲突，以老师补充评论中的明确学生姓名为准**
* 若图片与老师补充评论都无法明确区分或识别学生姓名（例如仅出现“指导教师”“班主任”“颁奖单位”等）
  ➡️ **视为 participants 必填字段缺失**
  ➡️ **event\_type 必须判定为 `general_event`**
  ➡️ **所有字段置空**

2️⃣ 教师姓名排除规则

* 以下角色姓名 **严禁** 写入 `participants`：
  * 指导老师 / 指导教师
  * 班主任
  * 任课教师
  * 评委
  * 颁奖人
  * 签发人
* 即使教师姓名在图片或老师补充评论中更醒目：
  * **也不得当作参赛人员**
  * **也不得补充或推测学生姓名**

3️⃣ 人名混合场景的处理原则

* 若奖状中 **同时出现学生姓名与教师姓名**：
  * **仅提取学生姓名**
  * 教师姓名一律忽略
  * 若老师补充评论对学生名单做了明确修正，则以老师补充评论为准
* 若奖状中 **只出现教师姓名 / 单位名称 / 公章 / 职务**：
  * 先继续阅读老师补充评论中是否明确写出了学生姓名
  * 若补充评论仍未明确写出学生姓名，➡️ **participants 判定为无法获取**
  * ➡️ **event\_type = general\_event**

4️⃣ 禁止推断与补全

* 不允许根据：
  * 合影人数
  * 校服
  * 班级信息
  * 背景板
  * 常见格式
    推断学生姓名
* **只能使用图片中明确可见、可读的学生姓名文本，以及老师补充评论中明确写出的学生姓名文本；禁止自行补全**

5️⃣ 老师补充评论的使用规则

* 补充评论**可以**补充以下上下文信息：
  * 班级
  * 学校
  * 老师原始评价中的表现描述
  * 其他不改变比赛事实的说明
* 补充评论**也可以**对图片中的以下核心事实进行明确修正；若老师补充评论与图片冲突，必须以老师补充评论为准：
  * 参赛人员
  * 比赛名称
  * 赛项名称
  * 奖项结果
  * 获奖时间
  * 赛区/区域信息
  * 班级信息
  * 学生信息
* 在奖状、证书、获奖证明等场景下，也必须遵循“先提取图片信息，再阅读老师补充评论，最后合并；若冲突，以老师补充评论为准”的流程
* 若补充评论与图片冲突，必须以老师补充评论为准

## 3. 当 event\_type = "certificate\_event" 时的字段要求

* 适用于奖状、荣誉证书、表彰文件、获奖证明等**非比赛型**证书场景
* `participants` 必须填写最终合并后确认的学生姓名；提取顺序必须为先看图片，再读老师补充评论，若两者冲突，以老师补充评论中的明确学生姓名为准
* `image_content` 必须先独立记录图片中的证书文字、日期、落款、表彰名称、荣誉称号等可直接识别内容；不得混入补充评论
* `comment` 是合并图片内容与老师补充评论后的综合分析结果内容，生成流程必须为：先独立提取图片中的证书文字并写入 `image_content`，再阅读老师补充评论，最后将两部分信息整理合并；若两者冲突，以老师补充评论中的明确表述为准
* 必要时可自然融合老师补充评论中的班级、学校、表现描述，但不得机械复制原文或直接生硬拼接
* 如果图片中有日期、落款、表彰名称、荣誉称号，可写入 `image_content`，并在 `comment` 中按需要综合表达
* `competition_name`、`project_name`、`competition_level`、`competition_type` 在非比赛场景下保持空字符串
* `award_time` 若证书中有明确日期则提取，否则为空字符串
* `award_level` 仅当证书中明确出现且能映射到既定枚举时才填写，否则为空字符串

`certificate_event` 示例：

```json
{
  "event_type": "certificate_event",
  "competition_name": "",
  "participants": ["李欣言"],
  "image_content": "李欣言同学被评为优秀学生，落款日期为2026年5月22日。",
  "award_level": "",
  "comment": "结合图片内容与老师补充信息分析",
  "project_name": "",
  "award_time": "2026年5月22日",
  "competition_level": "",
  "competition_type": ""
}
```

## 4. 当 event\_type = "general\_event" 时的规则

* 当事件既不满足 `competition_event` 的必填条件，也不满足 `certificate_event` 的必填条件时
  → 不论是否有奖状、舞台、背景板，只要关键信息缺失，一律认为 `event_type = "general_event"`
* `image_content` 先记录图片中可直接识别出的文字、场景事实或说明信息；若图片中没有可识别内容，则为""
* **老师录入了文字或语音时**：`comment` 使用老师录入的文字或语音转写原文，不扩写，不拼接图片内容。
* **老师未录入文字或语音、只上传图片时**：按照原有图片识别规则提取内容，`comment` 直接使用 `image_content` 中的图片提取信息，作为原始记录。
* 例如：

```json
{
  "event_type": "general_event",
  "competition_name": "",
  "participants": [],
  "image_content": "",
  "award_level": "",
  "comment": "",
  "project_name": "",
  "award_time": "",
  "competition_level": "",
  "competition_type": ""
}
```
