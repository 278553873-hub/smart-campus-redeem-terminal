组件与复用盘点

目标是让多位前端工程师在 UI 改造中共享同一套基础能力：先识别已有组件、复用热点和重复实现候选，再明确公共组件与业务页面的边界，避免同一功能重复写样式。

结论：部分统一，复用边界未收敛

已有公共组件可以支撑主要流程，但同类能力仍有页面内手写版本；最大风险不是组件数量多，而是多个工程师不知道“应该复用哪一个”。

公共能力存在，入口不唯一弹窗、选择、搜索、缺省态已经有公共组件，但学生选择器、确认操作和局部弹层仍存在重复拼装。

对维护的影响：同一规则需要修改多处；视觉 Token 更新后无法自动覆盖旁路实现；同一流程在不同页面出现不同的搜索、选中、提交和反馈方式。

盘点原则：先按“职责”识别组件，再按“使用场景”记录变体。只有结构和行为稳定的部分进入公共组件，业务差异通过配置和回调传入。

组件层级

四层职责从下到上逐步组合；业务页面不得直接改写基础层样式。

基础层 → 业务组合层
L1 · 基础层

Token 与基础控件

提供颜色、字号、圆角、间距、图标和选择标记等稳定视觉语言。

示例：teacherMobileTokens、MobileSelectionIndicator应唯一
L2 · 通用组件层

导航、选择、搜索与反馈

提供跨页面重复出现的控件和交互状态，统一触控区、焦点和反馈。

示例：CompactSegmentedControl、MobileSearchInput优先复用
L3 · 容器层

弹窗、缺省态与卡片

提供页面结构、滚动、遮罩、动作区和无障碍能力，不知道业务提交逻辑。

示例：MobileBottomSheet、MobileEmptyState当前有旁路
L4 · 业务组合层

学生、报告与班级流程

把通用组件组合成业务任务，负责候选数据、默认值和提交后的结果。

示例：StudentCompactSelectGrid、ClassInviteFlow重点收敛

重复实现风险

这里列的是值得进入统一设计任务的候选，不是要求所有业务界面变成完全相同。

12 个候选 · 5 个重点族
R1 · 高

学生选择器

添加小组、调整成员、颁发奖章和批量操作都有“搜索 → 网格 → 选中 → 提交”流程，最容易被重复拼装。

推荐 MobileStudentPickerSheet
R2 · 高

底部弹窗外壳

提示、班级选择、离校确认、记录、档案和问卷存在多个相近外壳，圆角、遮罩、滚动和焦点容易分叉。

推荐 MobileBottomSheet
R3 · 中高

确认操作

删除、离校、报告生成和奖章发放都需要确认，但主次按钮、危险色和关闭行为并不天然一致。

推荐 MobileConfirmSheet
R4 · 中高

Tab 与分段切换

互斥视图混用底线、胶囊和局部按钮，需按一级视图、下级筛选和条件筛选分层。

按语义选择公共控件
R5 · 中

学生卡片

花名册卡片、选择项和学生详情入口信息相近，但展示和选择职责必须分层，不能互相复制。

推荐分离展示与选择

案例：学生选择器如何复用

统一的是选择流程与基础视觉，不是把分组、奖章和批量操作的业务规则硬塞进同一个页面。

由公共组件统一由业务页面传入
弹窗外壳、搜索区、学生网格、学生项基础结构、选中标记、空状态、底部主操作区候选学生集合、默认选中学生、是否仅看未分组、是否全选当前结果、是否显示归组信息
触控尺寸、圆角、遮罩、滚动、焦点管理、关闭行为、人数文案生成是否允许跨组移动、底部动作名称、提交后的业务回调、二次确认和结果刷新
不可由业务覆盖：圆角、阴影、搜索框样式、选中颜色、按钮拼接规则可有业务差异：完成（3人）、提交发放（3人）、仅看未分组等结构化配置
盘点结论：添加小组、调整成员、颁发奖章和批量操作应共享一个“学生选择”基础能力；差异通过配置和回调表达。教师手机端页面保持现状，公共组件设计待产品确认后进入任务。

后续新增组件先填写这些字段，工程师可以直接判断“复用、扩展还是新建”。

实现数量 / 引用文件数实现 1 套；引用 39 个文件区分“高复用单一入口”和“多套实现并存”。

行为差异 / 业务例外是否允许跨组移动、是否二次确认把业务规则留在组合层，不污染公共组件。

统一状态已统一 / 部分统一 / 待统一 / 有明确例外让多人协作时知道当前是否可以继续复用。

多人协作规则

这部分是给 UI 改造中并行工作的前端工程师看的最小约束。

先查目录，再写页面公共组件是协作入口；新建组件必须说明它与现有组件的职责差异。

复用优先：先在盘点报告和组件目录中搜索同类职责；有公共组件就通过 props（属性）或配置扩展，不复制 JSX 和样式。

新增有条件：只有在结构、状态或业务边界确实不同，且现有组件无法通过配置表达时，才新增组件，并补充盘点字段和使用范围。

样式归属：颜色、字体、圆角、间距、阴影和触控尺寸只能来自 Token 或公共组件；业务页面只负责数据和流程。
