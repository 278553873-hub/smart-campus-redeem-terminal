# 家长手机端 UI/UX 设计规范

本规范适用于“家长手机端”微信小程序。家长端直接复制教师手机端的 Token（设计令牌）架构、视觉基线和组件规范；本文件只补充家长端的用户任务、权限和底部导航映射。教师手机端规范有更新时，家长端同步更新，不再维护第二套互相偏离的视觉基线。

家长端的核心用户不是学校管理员或教师，而是孩子家长，其中可能包含年龄较大的用户。因此页面必须优先保证：一眼看懂、少读文字、少做判断、少被装饰干扰。

---

## 1. 产品定位

### 1.1 使用场景

家长打开小程序，主要是为了快速确认：

- 孩子最近在学校表现怎么样。
- 有没有被表扬或被批评。
- 月度报告、期末报告是否可查看。
- 孩子的成长币中，“可用”和“已存”分别有多少。
- 是否需要把可用货币存入积分银行。

### 1.2 设计目标

- 页面信息必须简洁、清晰、低压力。
- 每个页面只回答一个核心问题。
- 不用解释用户一眼能看懂的内容。
- 不把教师端、终端端、后台端的信息密度搬到家长端。
- 不为了“显得完整”增加备注、说明、标签、简介。

### 1.3 权限边界

- 家长端可以查看孩子成长信息，并在功能开放时记录已绑定孩子的日常表现。
- 家长端可以查看报告。
- 家长端可以从孩子信息卡进入学生档案列表。
- 家长端可以查看成长币的“可用”“已存”和存储记录。
- 家长端可以进行积分银行存储。
- 家长端不能兑换奖励、不能直接兑换商品。

## 2. 视觉基础规范

### 2.1 主色与辅助色

家长端采用与教师手机端一致的品牌红体系，并保留教师端已有的正向、辅助橙和成长币业务色。

| 角色 | 色值 | 用途 |
|---|---|---|
| 品牌主色 | `#E02727` | 主按钮、底部导航选中态、核心数据强调 |
| 品牌深色 | `#B51F1F` | 主色文字、描边按钮文字、焦点后的深色层级 |
| 正向状态 | `#278779` | 表扬、完成、稳步成长等正向状态 |
| 辅助强调色 | `#F75C03` | 待办、需要关注的提醒和辅助操作 |
| 成长币奖励 | `#FA9C00` | 成长币、收益数字和奖励拆分，面积保持克制 |
| 页面背景 | `#F8F6F5` | 家长端整体浅暖灰背景 |
| 内容卡片 | `#FFFFFF` 或接近白色 | 承载主要内容 |
| 主要文字 | 深灰或接近黑色 | 标题、重要对象、关键数字 |
| 辅助文字 | 中性灰 | 时间、来源、状态等弱信息 |

使用要求：

- 主操作优先使用 `#E02727`，文字使用白色；次级操作使用白底描边和 `#B51F1F` 文字。
- 正向、提醒、奖励色只表达对应业务语义，不作为装饰性多色铺陈。
- 不使用高饱和大面积背景，不使用终端端炫光风格。
- 辅助灰字不能承载关键含义。

### 2.2 字体与字号

家长端必须优先照顾年龄较大的家长阅读体验。

| 信息类型 | 推荐字号 | 要求 |
|---|---:|---|
| 页面标题 | 22px | 清晰即可，不加副标题解释 |
| 重要对象名称 | 16px - 18px | 加粗，易识别 |
| 卡片标题 | 15px - 17px | 不使用过细字重 |
| 正文说明 | 14px - 15px | 仅必要时出现 |
| 辅助信息 | 12px - 13px | 不承载关键含义 |
| 核心数字 | 28px - 36px | 高对比、短标签；同类数字统一角色 |
| 主要按钮文字 | 14px - 15px | 加粗、可快速识别 |

字号要求：

- 同一卡片内字号层级不超过 3 种。
- 关键操作文字不得低于 14px。
- 禁止大段 12px 灰字说明。
- 同类信息在不同页面应保持同一字号角色。

### 2.3 圆角、阴影与卡片

家长端视觉应柔和但不花哨。

| 组件 | 推荐圆角 | 要求 |
|---|---:|---|
| 顶部信息条、主要卡片 | 20px | 柔和、统一 |
| 表单输入框 | 12px | 明确可输入边界 |
| 主按钮 | 12px | 保持稳定识别 |
| 底部导航容器 | 0px | 复用教师端白色固定底栏，不使用悬浮胶囊 |
| 弹窗顶部圆角 | 28px | 与底部抽屉形态一致 |
| 小标签、小图标容器 | 12px - 16px | 不要过度装饰 |

阴影要求：

- 卡片阴影要轻，避免厚重悬浮感。
- 弹窗可使用更明显阴影，以建立层级。
- 普通卡片默认不使用实体四周边框，依靠白色表面、浅暖灰背景和 `--tm-shadow-card` 建立层级。

### 2.4 间距与密度

- 页面左右边距建议保持 20px 左右。
- 卡片内边距建议 14px - 20px。
- 卡片之间间距建议 12px - 20px。
- 首屏最多承载 1 个核心任务区和 1 个列表起始区。
- 不为了“呼吸感”牺牲核心信息读取效率。

### 2.5 2026-06 家长端轻科技视觉修订

本章节为 2026-06 家长端样式统一后的最新视觉基准；如与 2.1 或 2.3 中早期黄色主按钮、超大圆角建议冲突，以本章节为准。

家长端采用“浅暖灰背景 + 白色卡片 + 红色品牌主操作 + 小面积状态色”的教师端统一视觉方向。

使用要求：

- 页面背景接近白色，只使用教师端定义的浅暖灰氛围，避免多色大面积渐变造成脏感。
- 家长端复用教师端“配色方案 / 渐变样式”预览控件；默认使用“方案八 · 红蓝清晖”与“弥散”，渐变只作为低饱和背景氛围，不承载业务信息。
- 内容卡片以白色为主，使用轻阴影和克制圆角，不能所有组件都使用超大圆角。
- 功能 icon 使用教师端统一的线性图标和语义色；品牌入口使用红色，完成和表扬使用正向绿，待办使用辅助橙，成长币使用奖励金色。
- 待改进不使用灰色，避免误解为不可用或不重要。
- 确认类按钮使用品牌红纯色或轻微红色层级，不使用纯黑、深蓝或黄色大按钮。
- 圆角按组件层级分级：卡片、按钮、图标、底部抽屉分别控制，不允许局部临时写死成过度圆润风格。
- 学生头像真实上传优先，未上传时显示姓名姓氏第一个字，不使用随机卡通头像兜底。

### 2.6 Token（设计令牌）迁移规则

家长端直接复制教师端 `mobile-app/styles/teacherMobileTokens.ts` 的 Token 结构和数值。页面暂时保留 `--pm-*` 语义别名，以降低业务迁移风险；别名全部指向 `--tm-*`，不再自行维护颜色、字号、圆角或阴影：

- 颜色：`--pm-brand-*` 指向教师端品牌红、辅助橙和成长币奖励，`--pm-status-*` 指向教师端正向和负向状态。
- 字体：页面标题、区块标题、卡片标题、正文、辅助信息和指标数字使用固定字号角色，不在业务页面临时写新字号。
- 圆角：控件 12px、内层卡片 16px、主卡片 20px、底部抽屉 28px；特殊组件必须说明例外原因。
- 触控：可点击控件最小触控尺寸为 44px，主按钮高度不低于 48px。
- 阴影和动效：卡片、控件、浮层分别使用教师端统一阴影和动效，不再局部拼接旧的深色阴影公式。
- 配色控件：在家长端演示环境中提供与教师端同款的“配色方案”和“渐变样式”选择器，选项与渲染算法直接来自 `mobile-app/styles/teacherGradientPreview.ts`；家长端默认值为 `scheme-8 + diffuse`。

## 3. 文案规范

### 3.1 少即是多

家长端文案必须克制。能通过标题、数字、列表结构理解的信息，不再追加说明文字。

不推荐：

```text
成长
最近评价与关键统计
```

推荐：

```text
成长
```

不推荐：

```text
报告
月度报告与期末报告
```

推荐：

```text
报告
```

不推荐：

```text
积分银行
成长币的“可用”“已存”与存储记录
```

推荐：

```text
积分银行
```

### 3.2 禁止重复解释状态

如果界面已经通过结构表达了状态，不再增加说明标签。

不推荐：

```text
当前绑定的孩子
```

原因：用户能通过位置、选中态、页面内容理解当前状态，重复标签会增加视觉噪音。

### 3.3 报告卡片不展示简介

学生档案不作为底部一级入口，只能从孩子头像或孩子信息卡进入。进入后先显示档案列表，再查看具体档案明细。

报告卡片只展示必要识别信息，不展示内容简介。

报告卡片应包含：

- 报告类型。
- 时间范围。
- 状态或入口。

报告卡片不应包含：

- 总结段落。
- AI 摘要。
- 亮点列表。
- 灰色长说明。

AI 指人工智能。家长始终需要进入详情查看报告正文，列表页的任务只是帮助家长找到报告。

问卷不作为一级入口，只能出现在建档流程或具体档案明细的来源记录中。

### 3.4 只在必要处解释

允许说明文字的场景：

- 首次未绑定孩子，需要解释为什么看不到数据。
- 表单错误或操作失败，需要告诉用户如何处理。
- 银行存储会改变成长币的“可用”和“已存”，需要在操作确认处说明影响。
- 涉及隐私、授权、数据安全，需要简短说明。

说明文字要求：

- 单句优先。
- 不超过 20 个中文字符为宜。
- 不连续出现两段说明。
- 不使用技术术语。

## 4. 交互与组件规范

### 4.1 标题栏

- 标题栏高度建议 44px。
- 标题居中，字号 17px，加粗。
- 标题栏只显示页面名，不加常规副标题。
- 有返回路径的页面必须提供明确返回按钮。

### 4.2 按钮

- 主要按钮高度不低于 48px。
- 主要按钮使用 `#E02727` 背景和白色文字。
- 按钮文字应直接说明动作，不使用装饰性箭头。
- 禁用态使用低饱和灰色，避免误认为可点击。
- 按钮必须有触控按压反馈，例如轻微缩放或背景变化。

### 4.3 输入框

- 输入框高度建议 48px - 52px。
- 输入框边界必须清晰，聚焦态使用教师端焦点环 Token。
- 手机端短数字输入框（如兑换密码）聚焦时不加边框色与焦点环，只保留光标；边界靠静态描边表达。
- 小字号的提示文案必须用与输入框等高的独立居中层渲染，不得依赖原生占位符：原生占位符与输入文字共用基线，字号更小的一方会明显偏低，看起来没有垂直居中。
- 密码显隐图标固定使用“图标代表当前状态”：密码掩码时显示闭眼图标，明文显示时显示睁眼图标；统一复用公共 `PasswordRevealButton`，不在页面里自己写判断。
- 表单字段应按真实填写顺序渐进展示。
- 表单错误必须说明如何修正，不只显示红色状态。

### 4.4 弹窗与浮层

- 弹窗、抽屉、浮层必须提供关闭方式。
- 关键流程中的弹窗必须提供返回或取消路径。
- 遮罩要保证底层内容不会干扰阅读。
- 弹窗中的主要操作保持单一，避免多个按钮抢主次。
- 弹窗内容应聚焦当前任务，不展示无关信息。

### 4.5 底部导航

家长端底部导航固定为 3 个入口：

```text
成长 / 报告 / 我的
```

禁止增加：

- 首页。
- 记录。
- 资产。
- 我的。
- 商城。
- 兑换。

积分银行保留为成长页内的入口卡片，不作为底部一级导航；“我的”承载个人资料、孩子管理和设置。学生档案属于孩子信息详情，不适合作为常态一级入口。

## 5. 信息密度规范

### 5.1 一屏信息数量

每个手机首屏建议最多出现：

- 1 个当前上下文区域。
- 1 组核心统计或 1 个核心操作区。
- 1 个列表起始区域。

避免首屏同时出现成长、报告、积分银行、说明、入口卡片等多种任务。

### 5.2 卡片内容

卡片只保留决策必要信息。

评价记录卡片可包含：

- 五育维度。
- 时间。
- 标题。
- 分值。

评价明细卡片按“评语、图片、底部信息”排列：评语独占完整宽度；图片按原顺序使用三列等尺寸正方形缩略图，单图、双图同样靠左排列，无图不占位；老师和时间位于底部左侧，分数位于底部右侧，窄屏时辅助信息可换行。点击图片后使用公共图片预览组件查看完整图片，支持切换、关闭、键盘操作及加载失败重试。图片与对应评价共用明细可见性设置；撤回明细权限时，已打开的图片预览也必须关闭。演示数据可使用现有插图，真实数据应使用该条评价的原始图片。

学生档案列表卡片可包含：

- 档案名称。
- 建档日期。
- 阶段或状态。

报告入口卡片可包含：

- 报告类型。
- 时间范围。
- 查看入口。

银行记录卡片可包含：

- 存储或收益标题。
- 时间。
- 金额变化。
- 简短来源。

### 5.3 删除优先级

如果页面显得拥挤，按以下顺序删除：

1. 标题下灰色副标题。
2. 用户一眼能理解的解释文案。
3. 状态标签。
4. 卡片简介。
5. 装饰图标和装饰背景。

---

## 6. 禁止项

家长端禁止出现以下设计：

- 页面标题下的常规灰色解释副标题。
- “当前绑定的孩子”等重复状态标签。
- 报告列表中的内容简介。
- 学生档案底部一级入口。
- 兑换奖励、兑换商品主入口。
- 与当前页面任务无关的入口卡片。
- 教师端管理操作，如生成报告、导出全班、记录学生。
- 终端端强视觉风格，如大面积炫光、复杂动效、游戏化装饰。
- 大段说明文字堆叠。
- 让关键操作依赖小图标点击。

## 7. 评审清单

每次修改家长手机端前，必须检查：

- [ ] 页面是否只回答一个核心问题。
- [ ] 是否删除了用户一眼能看懂的备注说明。
- [ ] 顶部标题是否没有多余副标题。
- [ ] 是否没有重复状态标签。
- [ ] 报告列表是否没有简介。
- [ ] 底部导航是否仍为成长、报告、我的；积分银行是否只作为成长页内入口。
- [ ] 是否没有兑换奖励或兑换商品主入口。
- [ ] 主要按钮高度是否不低于 48px。
- [ ] 主要按钮是否使用 `#E02727` 背景和白色文字。
- [ ] 正向、提醒、奖励色是否只用于对应业务语义。
- [ ] 同类卡片圆角、阴影、边框是否一致。
- [ ] 年级较大的家长是否能在 3 秒内理解当前页面要做什么。

成长币收支列表补充（2026-10-23）：成长页原成长币卡片增加“收支明细”只读入口，独立于“进入银行”。列表沿用白卡、年份筛选、收入/支出筛选、来源筛选及月份分组；共用 shared/growthCoinFlow.ts 的分类与奖励格式，保留“成长嘉奖”，兼容每周、每月和加分奖励。说明最多两行，到账币数与评价加分分别显示，不增加单笔点击详情。家长没有正向评价明细权限时，加分奖励仅显示评价加分、不透出指标名称。存取操作与存单仍留在银行原页面。

## 2026-11 成长首页视觉修订（仅首页内容区）

依据已确认的薄荷绿效果图，成长首页内容区采用薄荷至浅青背景、青绿色主操作、细渐变边缘的评价主区域和白色银行区域。本节覆盖上述教师端红色继承规则，仅作用于 `.parent-growth-home`；底部导航、其他页面和公共弹窗不变。

- 顶部显示真实孩子资料、独立切换按钮及单一消息入口；零待办仍可进入。
- 总分始终显示，表扬与待改进分别遵循现有可见性配置；明细只在详情页展示。
- 成长币区域显示配置的货币名称与可用余额，保留收支明细、预计可得与兑换密码入口，服从成长币功能开关；银行为二级能力，仅开启时显示已存及进入银行入口。
- 字号集中定义于首页样式：标题28、区块标题20、正文14、辅助12、总分44、金额32；同类角色统一。金额过长允许换行，不截断资金信息。
