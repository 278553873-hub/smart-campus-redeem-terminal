# 教师手机端 UI 规范

> 适用范围：教师微信小程序手机端，包括记录页、班级列表、班级详情、学生详情、我的页面、底部导航、悬浮录入条、记录详情弹层。
>
> 本文件是教师手机端唯一的人类可读 UI（用户界面）规范，替代旧 `PHONE_UI_GUIDELINES.md` 和独立的 `design-token.md`。业务范围、权限、数据与状态流转归对应 PRD（产品需求文档）维护，不在本文件重复定义。

## 1. 设计目标

教师手机端的核心任务是让老师在移动场景下快速完成记录、查看和追溯。视觉目标不是“传统信息化系统”，而是清爽、可信、有人工智能科技感，但不牺牲信息密度和可读性。

- 清爽：核心氛围页使用浅色弥散背景，查看与配置页使用纯白标题栏、浅灰内容区和白卡承载，减少装饰与说明文案。
- 高效：首屏展示更多有效记录，减少头像、说明、重复按钮等非必要信息。
- 可辨识：记录学生与记录班级使用不同模式色，避免老师误切流程。
- 可信：AI（人工智能）生成内容明确标注，字段关系清晰，分值语义一眼可辨。
- 克制科技感：使用浅渐变、轻玻璃和线性图标，不使用重玻璃、3D 图标、大量 emoji 或强发光。

教师手机端唯一可执行令牌源为 `mobile-app/styles/teacherMobileTokens.ts`。本规范定义“何时使用哪类语义”，代码源定义颜色、字号、圆角、阴影、间距和动效的具体值。页面不得在局部重新声明主题变量，也不得继续引用蓝紫、靛青旧令牌体系。班主任助理、校长助理和问卷采集类型只能使用该文件定义的角色或受众 Token。

教师手机端报告图表下方的简单解析规则统一维护在 `TEACHER_MOBILE_CHART_RULES.md`，解析固定输出“总结”和“补充”两个字段，本规范不重复定义具体话术模板。

### 1.1 Token（设计令牌）架构

令牌按三层维护：

- Primitive（原始值）：基础色板和原始尺寸，只允许在令牌源内部使用。
- Semantic（语义值）：品牌、文字、页面、表面、边框和状态，是通用界面的默认引用层。
- Component（组件值）：记录模式、导航、图表、阴影、圆角、触控、字号、间距和动效，业务组件优先引用这一层。

常用变量域：

| 变量域 | 职责 |
|---|---|
| `--tm-brand-*` | 品牌、辅助与奖励语义 |
| `--tm-bg-*`、`--tm-text-*`、`--tm-border-*` | 页面、表面、文字与边界 |
| `--tm-record-*`、`--tm-status-*` | 记录对象与正负结果 |
| `--tm-role-*`、`--tm-audience-*` | 人工智能助理角色与采集受众 |
| `--tm-edu-*`、`--tm-chart-*` | 五育分类与数据图表 |
| `--tm-tag-*`、`--tm-gender-*` | 无业务含义的点缀与性别角标 |
| `--tm-radius-*`、`--tm-shadow-*`、`--tm-size-*` | 组件形态、层级与触控 |
| `--tm-report-*` | 班级报告页面留白、卡片间距与卡片内部节奏 |
| `--tm-font-*`、`--tm-space-*`、`--tm-duration-*` | 排版、间距与动效 |

使用顺序固定为：组件级 Token 优先，语义级 Token 其次。业务页面不得直接引用原始色板，不得新增一次性十六进制色值、阴影公式或临时主题变量。

## 2. 全局视觉基调

### 2.1 背景

- 教师手机端页面背景分为“氛围背景”和“纯色分层背景”，由公共屏幕背景组件统一管理，业务页面不得自行绘制整页背景。
- 氛围背景使用可与白色卡面稳定区分的浅暖灰底，品牌红与辅助橙只作为低透明弥散光；适用于记录页、班级列表、学生成长档案和“我的”页等需要连续品牌氛围的页面。
- 记录页根据记录模式微调顶部氛围：记录学生使用极浅品牌红，记录班级使用极浅辅助橙。
- 记录页下半屏与班级列表、“我的”页复用同一暖白渐变和极低透明续光，不单独增加纯白收净层。
- 纯色分层背景使用 `--tm-page-plain-header-bg` 承载状态栏和标题栏，使用 `--tm-page-plain-content-bg` 承载内容区；两者之间不使用渐变、光晕或装饰图层。
- 班级学生列表、班级报告、学校数据报表、科目管理、部门管理、货币发放、建议反馈、问卷采集和档案设计统一使用纯色分层背景。科目管理与部门管理使用独立紧凑条目，通过间距区分数据，不使用大圆角容器包裹多条数据或以横线分隔。
- 学生详情使用“沉浸顶部背景 + 纯色内容区”的混合背景：公共屏幕背景的品牌浅渐变必须延伸到状态栏顶部，并在页签下方逐步过渡到 `--tm-page-plain-content-bg`，渐变终点必须与内容区底色一致，不得形成固定高度的横向截断；只允许该页面接管顶部安全区，不得将沉浸规则扩散到其他纯色分层页面。
- 纯色分层页面的标题栏保持纯白，内容区保持浅灰，普通白色卡片依靠底色明度差建立层级；业务页面不得覆盖为整页纯白或局部自定义灰色。
- 长页面使用固定在屏幕层的公共背景，滚动内容根容器保持透明，禁止按内容高度拉伸或重复渐变。
- 背景只负责氛围，不承载信息，不得影响正文对比度。

### 2.2 卡片

- 普通内容卡片使用 `--tm-bg-surface`；需要轻玻璃材质时使用 `--tm-bg-surface-glass`。
- 普通卡片不使用实体 `border`（边框）、环形阴影或其他四周线条；只有 AI 语义卡片允许保留语义描边。
- 普通卡片使用 `--tm-radius-card` 和 `--tm-shadow-card`；控件、卡内分组和弹层分别使用对应组件级 Token，不在页面内另设圆角或阴影。
- 普通卡片使用“无线条表面分层”：以白色卡面与浅暖灰页面建立明度差，只允许单层、向下扩散、无四周起始线的极淡环境阴影。
- `--tm-shadow-card-raised` 只用于需要比普通卡片更强层级的区域，不得作为所有卡片的默认阴影。
- 必须在纯白承载面上展示的白色操作卡片使用 `--tm-shadow-card-on-white`；第一层中性环境阴影只用于补足顶部和侧边层级，第二层向下扩散，不得用实体描边、灰色填充或品牌色条代替。
- Tailwind CSS（工具类样式框架）消费完整阴影 Token 时统一使用 `[box-shadow:var(--tm-shadow-card)]` 形式，禁止使用会被识别为阴影颜色的 `shadow-[var(--tm-shadow-card)]`。
- 禁止嵌套多层重卡片；AI 解读可作为记录卡内部的独立结果区。
- 班级报告统一使用 `--tm-report-page-inline` 控制页面左右留白、`--tm-report-card-gap` 控制板块间距、`--tm-report-card-padding` 控制卡片内边距、`--tm-report-card-content-gap` 控制标题到内容的间距。四项组件 Token 分别映射到 20、24、16、16 像素的基础间距尺度；所有报告板块必须通过统一 `ReportSection` 消费，禁止在具体板块覆盖 `p-3`、`px-3` 等局部间距。

### 2.3 字体

- 字体族由教师手机端公共样式统一提供，业务页面不单独覆盖。
- 问卷、采集表等内容对象的行内标题使用 `--tm-font-size-document-title`；它只服务于可直接编辑的内容标题，不替代页面导航标题。
- 页面普通正文、老师原文和 AI 评语使用 `--tm-font-size-body`。
- 记录卡标题、AI 解读标题使用 `--tm-font-size-card-title`。
- 辅助时间、标签分别使用 `--tm-font-size-meta` 或 `--tm-font-size-compact`。
- 总分与统计摘要使用 `--tm-font-size-metric`，并只出现在对应摘要组件内。
- 普通正文使用常规或中等字重，强字重只保留给页面标题和关键数字。

## 3. 颜色系统

### 3.1 模式色

模式色只表示“记录流程”，不表示加分或扣分。

| 模式 | 强调 Token | 可读文字 Token | 浅底 Token | 用途 |
|---|---|---|---|---|
| 记录学生 | `--tm-record-student-primary` | `--tm-record-student-text` | `--tm-record-student-soft` | 顶部模式切换、原始语音胶囊、学生记录页弱氛围 |
| 记录班级 | `--tm-record-class-primary` | `--tm-record-class-text` | `--tm-record-class-soft` | 顶部模式切换、原始语音胶囊、班级记录页弱氛围 |

模式色只允许用于小面积强调，不得作为整张记录卡、AI 解读区或输入面板的大面积底色。
模式强调色不得承载普通字号文字；浅底上的文字必须使用对应可读文字 Token。

### 3.2 分值语义色

分值语义色只表示事件正负，不表示记录对象。

| 语义 | 背景 Token | 边框 Token | 文字 Token |
|---|---|---|---|
| 加分 | `--tm-record-positive-bg` | `--tm-record-positive-border` | `--tm-record-positive-text` |
| 扣分 | `--tm-record-negative-bg` | `--tm-record-negative-border` | `--tm-record-negative-text` |

规则：

- 加分不得使用橙色，橙色容易被理解为警示。
- 扣分不得只依赖负号，必须通过浅红边框、浅红背景和负分数字共同表达。
- 记录班级即使处于橙色模式，扣分仍使用负向红语义。
- AI 解读卡整块表面跟随事件结果：正向使用浅绿表面，负向使用浅红表面；一条记录经 AI 拆事件后只会是正向或负向，不设计正负混合态。
- 记录对象使用中性深色文字展示，不再使用模式色胶囊；指标名称保持中性，颜色只表达分值正负。
- 待办数量、删除二次确认、错误和其他负向状态继续引用 `--tm-status-negative-*` 语义 Token，但其色值必须复用品牌红体系，不得维护或引入独立暗红色板。删除菜单文字和删除确认按钮使用 `--tm-status-negative`；表单错误、校验边界和必填星号才使用 `--tm-status-negative-strong`。

### 3.3 全局导航色

- 底部导航是全局导航，选中色固定使用 `--tm-brand-primary`。
- 底部导航不得跟随记录学生/记录班级分段控件变色。

### 3.4 人工智能助理角色色

- 班主任助理使用鲜活翡翠青角色 Token，表达陪伴、成长与班级日常；该色只服务班主任助理，不覆盖学生采集使用的玉石青受众色。
- 校长助理使用品牌红与奖励金角色 Token，表达学校品牌与管理决策。
- 两个页面共享助理卡片结构，但分别通过 `--tm-role-headteacher-*` 和 `--tm-role-principal-*` 注入角色语义。
- 打字机文字统一使用深色角色正文作为底色；班主任助理以浅翡翠青扫光，校长助理以管理金扫光，确保动效可见且页面内部颜色统一。
- 角色色只用于对应助理页面；底部导航、普通按钮和 AI 解读仍遵循全局教师端语义。
- 系统开启“减少动态效果”时停止文字流光，并回退为对应角色深色静态正文。

#### 3.4.1 人工智能助理报告承接

- 班主任助理与校长助理报告统一接收带版本号的 JSON（结构化数据格式）。人工智能只返回报告内容与证据，不返回颜色、图标、圆角、阴影、组件名或页面排序。
- 前端按报告类型维护区块白名单、固定标题和固定顺序。未知区块忽略并记录校验信息；协议版本不兼容、报告对象缺失或没有有效区块时进入“报告暂时无法展示”错误态，不得让页面空白或崩溃。
- 班主任周报固定按“本周重点行动、需要关注的学生、班级信号、评价视角”展示；班主任月度复盘固定按“下月记录建议、本月评价画像、关注对象、评价视角、指标与表达”展示。
- 校长周报与月报固定先展示管理判断和管理动作，再展示核心指标、改善进展与问题信号；学期报告固定先展示总体判断和下学期行动，再展示指标、使用情况、亮点、实践与问题。
- 成功报告只使用判断、行动、指标、洞察和实践五类业务卡片。指标在一张卡片内部使用无阴影数据单元，不形成卡片套卡片。
- 依据、解读、核实重点、发生情境和案例价值统一通过公共底部抽屉渐进披露；正文不得重复铺陈同一证据，触发按钮保持 44 像素触控区域。
- 报告至少保存协议版本、报告编号、报告类型、对象、周期、生成时间、提示词版本和数据快照编号。历史报告冻结生成时的数据快照与提示词版本，不随后续数据变化自动改写。
- 页面必须覆盖生成中、已生成、部分有效、数据不足、生成失败和协议错误状态；数据不足时不调用人工智能，生成失败允许重试，部分有效时只展示通过校验的区块。

### 3.5 问卷采集受众色

- 家长问卷使用 `--tm-audience-guardian-*`，学生信息采集使用 `--tm-audience-student-*`，教师问卷使用 `--tm-audience-teacher-*`。
- 受众色只用于类型色条、图标、标签和短进度条，不得铺满整张卡片或页面。
- 类型必须同时展示图标或文字，不得只依赖颜色区分。
- 未开放的采集类型不展示在新建采集入口中。

### 3.6 点缀色与性别色

- 花名册头像、分组标签等不承载业务语义的位置，使用 `--tm-tag-*` 派生点缀色；点缀色不用于状态、权限或分类判断。
- 性别仅通过头像角标表达，男生使用 `--tm-gender-male`，女生使用 `--tm-gender-female`；头像底色不得与性别绑定。
- 承载文字时使用对应深色文字 Token，不直接使用只适合图形的点缀色。

### 3.7 图表用色

图表按业务含义选择颜色，禁止用单一主题色覆盖不同数据关系：

1. 分类色：只表达指标分类，不表达正负或告警。班级报告中的“五育”是国家“五育并举”育人理念下的固定业务名称，不代表页面只能展示德智体美劳五个一级项；一级指标必须读取学校当前启用的指标配置，可按学校特色增加、减少或改名。班级报告使用可循环扩展的 `--tm-chart-indicator-*` 分类 Token，同一学校、同一指标在得分图、事件图、图例和下钻明细中保持一致；不得在页面内按固定五项硬编码。仍明确采用德智体美劳标准维度的其他图表可以继续使用 `--tm-chart-edu-*`。
2. 百分比色：学校数据报表中的年级覆盖率、班级覆盖率和指标覆盖率统一使用同一套 `--tm-chart-percentage-*` 分档 Token。低于 60% 使用 `percentage-low`，60% 至低于 80% 使用 `percentage-medium`，80% 至 100% 使用 `percentage-high`；柱体、数值、进度条和浅色分区必须按同一函数计算档位，禁止按报表模块或指标级别固定配色。
3. 报表类型色：并列或下钻指标使用品牌、辅助与奖励语义帮助区分，只表达数据类型，不表达告警。
4. 正负色：正向绿只用于加分、正向状态和覆盖率高档；负向分值使用负向红。普通数量不得因为数值为正数就统一使用绿色。
5. 对比色：分类维度使用分类实色，自身历史系列使用 `--tm-chart-series-muted-opacity`，外部参照使用 `--tm-chart-series-peer`，次级汇总使用 `--tm-chart-series-total`；总分等需要突出展示的中性核心结果使用 `--tm-chart-data-default`。图例只表达系列维度，并且必须与图中系列保持一致。
6. 手机端“评价记录分布”默认只呈现本周期正向与负向事件的占比，使用一条百分比堆叠条直接表达整体构成；图下只显示“正向 / 负向”与对应百分比，不重复总记录数、原始条数、周期增减和年级差异。占比色块只承载数据表达，不设置点击或记录下钻。板块标题右侧的“对比详情”只渐进披露本周期、上周期和年级平均的精确条数。对比详情使用纯文字数值对照表：表头弱化，本周期列使用较强字重，其他参照列使用常规字重，数字使用等宽数字排版；不使用进度条、比例轨道、虚线或临时最大值刻度，也不重复“增加、减少、还差、优于”等结论。板块下方的简单解析是默认页面唯一的趋势结论层，使用浅中性底提示块承载。
7. 学校数据报表中的年级、班级评价数属于普通数量，柱体、数值标签分别使用 `--tm-chart-data-default`、`--tm-chart-data-default-text`，不使用品牌红或辅助橙代替数据色。顶部使用单层“报表类型 + 周期”筛选并整体吸顶，不复制首屏态和吸顶态，不随滚动缩放、淡入淡出或改变高度。标题栏与筛选栏必须由页面内部单一滚动层管理，使用连续的纯色背景并重叠 1 像素消除设备缩放产生的亚像素缝隙；标题栏内部控件不得通过内边距撑破固定高度，禁止滚动内容从两者之间透出。两行筛选统一使用 44 像素的 `--tm-report-filter-row-height`，不在类型与周期之间或筛选区底部增加分割线。类型筛选使用开放式文字页签，字号使用 `--tm-report-type-font-size`，选中态只使用品牌文字和底部短线；周期使用字号更小的 `--tm-report-period-font-size` 五等分紧凑按钮，选中项使用品牌实底，视觉色块通过 `--tm-report-period-pill-height` 和 `--tm-report-period-pill-inline` 收敛为 28 像素高且随文字宽度变化，按钮本身仍保持 44 像素触控高度，未选项使用次级文字。“指标使用情况”与年级覆盖率按实际百分比共同映射 `percentage-low / medium / high`。年级覆盖率、年级评价数、教师使用排行榜及其他报告卡片的标题右侧入口统一使用品牌红文字加右箭头的轻量入口，不增加胶囊底色、描边或阴影，并保持不低于 44 像素的触控高度。

颜色映射属于报表业务语义，必须集中定义并由相关图形、进度条和数值标签共同复用。网格线、浮层和触摸高亮分别使用 `--tm-chart-grid`、`--tm-chart-tooltip` 和 `--tm-chart-hover`，不在图表组件内临时配色。

图表填充色保持清亮，不为追求单个色块的高对比度而整体压暗。数值、标签和必要边界使用对应的 `*-text` 深色 Token；正负分同时显示正负号，对比关系必须同时使用直接标签、填充形态或线型表达，禁止只依赖颜色或透明度传达信息。

| 报表语义 | 填充 Token | 文字 Token | 浅底 Token |
|---|---|---|---|
| 普通数据 | `--tm-chart-data-default` | `--tm-chart-data-default-text` | `--tm-chart-data-default-soft` |
| 正向 / 加分 | `--tm-chart-positive` | `--tm-chart-positive-text` | `--tm-chart-positive-soft` |
| 提醒 / 临界 | `--tm-chart-warning` | `--tm-chart-warning-text` | `--tm-chart-warning-soft` |
| 负向 / 扣分 | `--tm-chart-negative` | `--tm-chart-negative-text` | `--tm-chart-negative-soft` |

### 3.8 班级报告日期与来源筛选

- 时间范围是父筛选，必须直接位于页面导航标题下方；数据来源是由时间范围决定的子筛选，位于日期下方。视觉顺序、DOM 顺序和吸顶顺序都必须保持“日期 → 来源 → 报告内容”，禁止让下方日期反向改变上方来源。
- 班级报告默认展示“本周、全班汇总”。“全班汇总”和“我的记录”是固定来源，始终展示；其他老师只在当前周期内实际产生过评价记录时展示，没有记录的其他老师直接隐藏，不使用禁用项占据空间。顺序固定为“全班汇总、我的记录、其他评价老师”，当前登录老师不在其他老师列表中重复出现。
- 日期变化后，当前来源在新周期仍有效时保留选中；来源失效时自动回到“全班汇总”，并将来源标签栏平滑调整到选中项。该状态变化通过选中项本身反馈，不增加提示文案、Toast 或确认弹窗。
- 点击“自定义”后使用公共底部抽屉选择开始和结束日期，页面内不直接展开日期输入框。只有两个日期均已填写且范围有效，点击“应用日期”后才更新日期、来源和报告内容；取消或关闭抽屉继续保留当前已应用范围。应用成功后，在日期选项下方增加 40 像素浅中性摘要行，依次展示日期图标、“自定义时间”、完整日期范围和“修改日期”入口；日期使用 13 像素半粗主文字，辅助标签与操作使用 12 像素次级样式，不增加独立卡片或额外说明。
- 日期与来源共同位于一个连续的白色工具区，不再使用独立日期卡片、来源浮层、多重阴影或日期与来源之间的分隔线。默认态严格收敛为 44 像素日期行和 44 像素来源行，`--tm-report-filter-padding-top`、`--tm-report-filter-padding-bottom`、`--tm-report-filter-padding-pinned` 和来源上下内边距令牌均为零；只有已应用自定义日期时增加 40 像素摘要行。工具区与报告卡片共同使用 `--tm-report-page-inline` 建立唯一左右基线。
- 日期选项始终保持 `--tm-size-touch` 的 44 像素触控区域，使用五等分开放式文字标签，不增加分段轨道、独立色块或选中卡片。选中项使用 14 像素半粗品牌文字，并通过 `--tm-report-date-indicator-width`、`--tm-report-date-indicator-height` 控制的底部短线强化状态；未选项使用 14 像素中等字重次级文字。默认态和吸顶态不得改变字号、宽度或选中形态。
- 数据来源用于班级内的高频连续对比，在日期下方使用单行横向直达标签，不再通过弹窗选择。来源顺序仍为“全班汇总、我的记录、其他评价老师”；来源项通过 `--tm-report-source-item-inline` 获得独立水平留白，不以压缩间距强行塞满固定数量。常见 4 至 5 个来源优先露出，超过一屏后自然横向滚动，并允许下一项部分露出作为滚动提示，不压缩姓名或隐藏条数。
- 来源行保持 `--tm-size-touch` 的 44 像素触控高度，选中态视觉胶囊使用 `--tm-report-source-pill-height` 的 28 像素高度和 `--tm-report-source-pill-inline` 的 6 像素水平内边距，使其保持紧凑而不缩小触控区域。当前来源使用主题红实底、反白文字和中性轻阴影，其他来源使用透明背景、13 像素中等次级文字和独立水平内边距，不增加边框。“我的记录”和其他老师名称后使用紧凑半角括号展示当前日期范围的评价条数，例如“我的记录(1)”；条数最高显示为“(999+)”，使用 11 像素中等字重和等宽数字。“我的记录”为 0 条时仍显示“(0)”，“全班汇总”不附加条数。
- 页面滚动超过阈值后，日期和来源整体吸顶，并在 `--tm-duration-panel` 内只过渡工具区边界、阴影和垂直内边距；不得改变左右边界、日期字号、来源字号、标签间距或选中形态。吸顶区只在底部保留 `--tm-border-subtle` 边界和中性轻阴影，避免与正文叠在一起。
- 上述日期、来源和双状态尺寸统一由 `--tm-report-date-*`、`--tm-report-source-*`、`--tm-report-filter-*` 组件 Token 管理，业务页面不得重新写死像素或百分比。
- 切换日期或数据来源后，概况、图表、积分排行、需要关注和学生覆盖情况必须使用同一数据口径。全班汇总统计当前周期内的多位评价老师，单个老师视角的评价老师数按一位计算。
- “五育得分分布”和“五育事件分布”默认只展示学校配置的一级指标概览，标题保持“五育”。板块标题右侧使用“查看明细”进入公共底部抽屉；点击图表中的一级指标可直接进入对应二级指标。“查看明细”不得在抽屉内重复一级概览，首次打开默认进入学校配置的第一个一级指标，再次打开优先恢复该类图表最近查看的一级指标。
- 下钻抽屉顶部固定使用单行横向一级指标标签切换当前分支，选中项使用主文字和品牌色底部短线，不使用红色文字或实底胶囊。点击其他一级指标后直接切换到其二级图表；只有进入三级时才显示“一级指标 > 二级指标”返回路径，减少二级页面的重复导航。
- 得分下钻始终复用概览的三系列柱状图，同时展示加分、扣分和总分，禁止下钻后更换图形语法。存在子级时，点击柱组或横轴指标名称进入下一层；横轴指标名称统一使用主文字黑色，轻量箭头使用次级灰色，按压柱体提供高亮反馈。三级叶子不展示箭头。当前层级超过一屏时允许图表横向滚动，每屏优先展示 4 至 5 个指标，长名称不得倾斜显示。
- 事件下钻始终复用概览的环形图，按当前父级重新计算各子指标占比；存在子级时点击扇区进入下一层，三级叶子不可继续点击。得分与事件下钻均不得使用纯表格替代图形比较，也不得把精确值只藏在触摸浮层中。
- 各级数据必须由三级事件向上汇总，日期和来源变化后同步重算；一级、二级、三级总量不得出现口径不一致。下钻图保持学校配置顺序，不按当前数值重新排序，避免切换日期或来源后指标位置跳动。
- 一级指标切换标签保持不低于 44 像素触控高度；得分下钻的柱组与横轴名称、事件下钻的扇区分别作为触控入口。标题右侧“查看明细”作为首次使用的明确入口，图表点击作为熟练用户的直达入口。默认报告页不铺开二级、三级指标，不增加操作说明文案。

### 3.9 班级报告积分排行与需要关注

- “积分排行”只表达积分数据，不将积分等同于学生综合表现。分段选项统一使用“总分”和“进步幅度”；老师可见文案不使用“净得分”。总分按加分减扣分计算，进步幅度必须以当前周期相对上周期的总分变化为依据，不得使用无比较基准的模拟增量。
- 积分排行主卡默认展示前 10 名；当前班级超过 10 人时，通过“查看全部 X 名 / 收起排行”渐进披露完整班级名单，按钮中的人数必须与当前数据口径下的排行人数一致。前 3 名使用项目内统一的透明皇冠图片承载数字 1、2、3，图片通过 CSS 遮罩依次复用奖励金、中性银和辅助橙语义 Token，不在业务代码中硬编码图片颜色；第 4 名起保持普通数字，不扩大名次列宽或挤压学生姓名。皇冠不能替代排名数字，也不得只依赖颜色区分名次。学生行保持不低于 `--tm-size-touch` 的触控高度，点击后进入学生详情。
- “需要关注”聚合当前周期和五育维度中值得老师留意的积分表现，不使用“重点关注对象”“双向榜单”等旧名称或重复说明文案。五育筛选读取与两张五育图表相同的学校一级指标配置，使用横向滚动的紧凑条件控件；当前项与积分排行分段控件保持一致的品牌选中层级。
- 需要关注默认并列展示“加分TOP10”和“扣分TOP10”两个浅色数据分区，每区在主卡内直接展示完整 10 名，不增加二次展开入口。栏目主标题必须先说明榜单依据，分别按当前筛选口径下的学生累计加分、累计扣分从高到低取前 10 名；“表现突出”和“需关注”作为同一行右侧的次级结论，不得替代榜单依据。正向分区背景和文字分别使用 `--tm-chart-positive-soft`、`--tm-chart-positive-text`，负向分区背景和文字分别使用 `--tm-chart-negative-soft`、`--tm-chart-negative-text`；同时使用栏目文案、分值正负号和语义色表达正负含义，不增加额外的加减图标，也不得只依赖颜色。
- 两个数据分区属于同一报告卡内部的信息分组，只使用浅色表面和 `--tm-radius-control` 建立边界，不增加常驻描边、阴影或独立卡片层级。双栏水平内边距使用紧凑间距令牌，把有限宽度优先分配给标题、姓名和分值；榜单依据使用 14 像素粗体，次级结论使用 11 像素中等字重，二者保持单行完整显示并形成明确层级。学生姓名和分值使用 14 像素半粗文字，名次、姓名和分值使用稳定网格对齐，分值使用等宽数字；每行保持不低于 `--tm-size-touch` 的触控高度。
- “需要关注”学生行只承载当前筛选口径下的汇总排名，不设置整行点击或记录下钻。学生姓名可直接进入学生详情，名次和分值保持只读。自定义周期可能覆盖较长时间，禁止在该板块内直接加载规模不可预测的评价记录。

### 3.10 学生覆盖情况

- “已覆盖人数”是板块摘要，与“学生覆盖情况”标题在同一行右侧展示；使用紧凑的普通数据浅底标签和半粗关键数字，不独占一行，标签不得高于标题区或使用强提醒色。
- 列表不设置独立的排序 Tab 或方向切换控件。“评价次数”和“评价老师数”直接作为可点击表头，点击非当前列时默认从少到多排序，再次点击当前列时切换为从多到少。
- 卡片内边距和标题区到表头的净间距分别使用 `--tm-report-card-padding` 与 `--tm-report-card-content-gap`。表头使用无边框的浅中性圆角表面和较强字重，与数据行形成明确层级；当前排序列使用品牌文字色，并通过排序图标与 `aria-sort` 同时表达字段和方向，非当前列保留弱化的可排序图标。
- 表头按“学生姓名、评价次数、评价老师数”三列对齐，不增加无业务含义的序号。三个表头统一使用 13 像素半粗字重；姓名列通过 `--tm-report-coverage-name-inset` 建立左侧缓冲，“评价老师数”列为文字和排序图标预留稳定列宽及右侧安全留白，不得贴近表头圆角边界。
- 数据单元只展示裸数字，不重复“次”“位”等已由表头说明的单位；无障碍名称保留完整单位。评价次数为 0 和评价老师数为 0 时，分别使用一致的负向文字色，不增加胶囊背景；其他普通数量使用常规字重与次级文字。
- 排序状态只通过表头文字色、排序图标与 `aria-sort` 表达，不给当前排序列的数据单元重复增加背景或字重，避免形成连续的控件感。顶部“已覆盖”统计保持原有 12 像素字号及中等、半粗字重，不随表格强化而加重。
- 表头排序按钮保持不低于 44 像素触控高度；数据行与数值区域分别使用 `--tm-report-coverage-row-height`、`--tm-report-coverage-value-height`，形成 48/24 像素的舒展比例。数据行使用等宽数字并保持列宽一致，不设置整行点击或记录下钻；学生姓名可直接进入学生详情，评价次数和评价老师数保持只读。主卡片与“全部学生覆盖情况”底部抽屉复用同一列表组件，完整清单只扩展汇总数据范围，不继续下钻学生记录；两处列宽、排序状态、姓名入口与零值样式必须一致。
- “查看全部学生”保留不低于 44 像素的触控区域，仅使用文字与右箭头表达进入完整清单，不增加整行浅底和圆角容器。

## 4. 记录页信息结构

### 4.1 页面结构

从上到下：

1. 顶部安全区和微信胶囊避让。
2. 当前全局来源支持的记录对象；只有同时支持记录学生和记录班级时展示记录对象切换。
3. 当前记录对象对应的“指标”弱入口；双记录对象时由紧邻的选中项表达学生或班级上下文，不重复扩写入口文案。
4. 全量记录事件流。
5. 悬浮录入条。
6. 固定底部导航。

控制关系固定为：`当前全局来源 → 记录对象 → 指标体系`。记录页只消费当前全局来源的权限和数据，不展示来源名称，也不提供来源切换；来源管理留在班级页和我的页。个人来源、协作来源和未开通班级记录能力的学校来源以学生为隐含默认记录对象，不展示“记录学生”单项切换控件。只有已开通班级记录能力的学校来源展示“记录学生 / 记录班级”分段控件。

- 班级来源触发器只在班级页和我的页展示；个人、协作、学校分别使用单人、多人、学校图标，尾部统一使用向下箭头表示打开来源选择抽屉。
- 记录页禁止展示来源触发器、来源名称或来源抽屉，避免低频全局切换侵入高频记录流程。
- 单一记录对象不是可切换状态，禁止用禁用 Tab、单项分段控件或“记录学生”标题重复说明默认上下文。
- 微信标题栏高度通过 `wx.getMenuButtonBoundingClientRect()` 计算：`(胶囊上边界 - 状态栏高度) × 2 + 胶囊高度`。当前演示手机壳为 `(60 - 54) × 2 + 32 = 44` 像素，并通过 `--mini-program-title-bar-height` 注入页面；业务切换胶囊的可见高度使用 `--tm-record-scope-visual-height` 的 36 像素，不得高于微信标题栏，内部按钮仍保留 `--tm-size-touch` 的 44 像素触控高度。
- 双记录对象时，第一行仅展示 176 像素宽的“记录学生 / 记录班级”切换胶囊，指标入口左对齐放在下一行。单一记录对象时不展示切换行，指标入口直接占用第一行，禁止保留空白胶囊行。
- 双记录对象分段控件使用无边框的半透明白色完整表面和轻阴影，选中项使用对应模式浅色；未选中项不得使用类似禁用状态的大面积灰底。
- 顶部工具行以记录卡内容区为对齐基准：分段控件与指标入口均左对齐记录卡。每一行都必须限制在 `--mini-program-capsule-right-inset` 左侧；第二行用于表达“当前记录对象 → 指标体系”的层级，不用于堆放其他低频操作。

### 4.2 记录卡结构

记录卡内从上到下：

1. 记录时间 + 更多操作。
2. 原始输入区。
3. AI 智能解读区。

当前页默认展示当前登录账号记录，不展示教师头像和姓名。

### 4.3 原始输入区

- 语音录入：先展示原始语音播放入口，再展示语音转译文字。
- 文本录入：直接展示原始文本。
- 图片录入：展示图片证明缩略图，再展示必要的识别/转译文字。
- 原始文本使用 `--tm-font-size-body`，最多默认展示 2 行，详情在卡片点击或更多操作中展开。

语音播放入口：

- 使用轻胶囊按钮，包含播放图标、`原始语音`、波形、时长。
- 记录学生语音胶囊使用浅红，记录班级使用浅橙。
- 不使用 3D 图标，不使用黑色重底。

## 5. AI 智能解读卡

### 5.1 交互原则

- AI 解读整块卡片可点击进入编辑。
- 当整块卡片可点击时，字段内不再重复展示编辑 icon。
- 总分是汇总结果，不是单字段编辑入口，不得设计得像可编辑胶囊。

### 5.2 布局

AI 解读卡从上到下：

1. 标题行：人工智能形象 + `AI 智能解读` + 轻短强调线 + 右侧总分摘要。
2. 字段区：时间、对象、指标。
3. AI 评语。

- 每张包含 AI 解读结果的记录卡都在绿色或红色解读区下方、白色记录卡内部展示右对齐的“内容由AI生成”。声明使用 11 像素弱文字，不增加图标、背景、描边或独立卡片；识别中状态和没有 AI 解读结果的普通文件卡不展示。
- 记录独立进入详情、导出或分享后继续保留声明；经教师修改的 AI 内容使用“内容由AI生成，已由教师修改”。

字段顺序固定为：

```text
时间 → 对象 → 指标 → 评语
```

字段区对齐：

- 左侧标签列固定短宽度，右侧内容统一起点。
- 标签文字简短，使用 `时间`，不使用 `发生时间`。
- 指标行内部使用“指标名称左对齐、分值右对齐”。

### 5.3 对象展示

- 学生对象必须显示班级，例如 `林小杰(2025级1班)`。
- 多学生默认最多展示 2 个学生 + `+N人`。
- 点击 AI 解读卡或 `+N人` 后，在弹窗中展示完整对象列表。
- 班级对象直接展示班级名称，例如 `2025级1班`。

### 5.4 指标展示

- 指标必须展示三级结构，例如 `德育-遵纪守法-遵守纪律`。
- 一个事件可能匹配多个指标，必须支持多行指标。
- 每行指标右侧独立展示分值，例如 `+2`、`-1`。
- 指标标签不得使用重渐变，避免抢总分和评语层级。

### 5.5 总分展示

- 总分放在 AI 标题行右侧。
- 使用矩形摘要块，不使用圆形装饰章。
- 加分为青绿系，扣分为粉色系。
- 文案结构为：大数字 + 小字 `总分`。

## 6. 悬浮录入条

- 悬浮录入条跨记录页和班级详情页复用。
- 位置固定在底部导航上方，不永久压缩记录流的可见高度；列表尾部必须预留足够滚动空间，保证任何内容都可滚动到录入条上方。
- 中间主按钮为 `按住 说话`，左右为拍照和键盘/文本入口。
- 使用线性图标，不使用 3D 图标和 emoji。
- 使用无边框白色操作面板和中性图标，模式色不进入输入面板；统一使用悬浮层阴影 Token 与记录内容分层。

## 7. 底部导航

- 底部导航固定三入口：记录、班级、我的。
- 选中色固定品牌主红，不随页面业务模式变色。
- 未选中项使用 `--tm-nav-item-default`，保证小字号文字和图标对比度。
- 底部导航属于全局组件，使用高不透明白底和向上扩散的中性阴影与滚动内容分层，不使用明显顶部分隔线。
- 页面已有内部滚动容器时，底部安全留白只能由内部列表负责，外层不得重复增加白色占位。

## 8. 其他教师页面迁移规则

- “我的”页管理工具与更多工具在常规手机宽度下统一使用四列紧凑入口，即每行展示 4 个图标；权限过滤后不足四项时保持左对齐，不为填满整行放大图标或入口宽度。

### 8.1 班级列表

- 使用同一浅色弥散背景和白卡体系。
- 多来源账号复用统一来源触发器；页面不重复展示已由当前来源表达的归属分组。
- 学校版筛选工具行使用紧凑控件；控件统一通过 `--tm-bg-surface` 与 `--tm-shadow-control` 建立层级，禁止常驻外边框，仅复选框本体和焦点状态保留必要边界。
- 排行榜使用“奖杯图标 + 排行榜”轻入口；是否展示由对应 PRD 的版本和能力规则决定。
- 微信小程序真机必须通过 `wx.getMenuButtonBoundingClientRect()` 获取胶囊位置，将右侧安全距离注入 `--mini-program-capsule-right-inset`；顶部来源行只能在该安全区左侧排布，禁止按固定像素左移规避胶囊。演示手机壳必须注入同一安全区变量用于真机预演。
- 班级页标题栏只保留来源切换，并将其置于 `--mini-program-title-bar-height` 内上下居中；手机壳已提供状态栏顶部偏移时，页面不得再增加顶部内边距。个人来源已有班级时，在来源下方使用无卡片、无阴影的紧凑工具行：左侧反馈班级总数或当前显示数量，右侧提供“班级管理”入口；管理抽屉保留创建班级、加入班级和显示设置。禁止用悬浮加号承载这组语义不同的能力。个人来源真正没有班级时，缺省态直接展示创建班级和加入已有班级。
- 班级卡片优先展示班级名称、年级、人数、任教关系和主要入口；元信息区与操作区使用留白分层，不增加卡片内部横线。
- 班级号与年级、人数共用同一条紧凑元信息行，统一使用 `--tm-font-size-compact`；班级号仅通过字重、颜色与复制图标表达可操作性，不新增独立信息卡。
- 班主任、副班主任身份使用浅橙标签；普通任教学科使用中性标签，不使用多彩标签区分科目。一个教师的真实角色与任教学科均完整展示，无任教关系时不保留空标签区。
- 学生列表是班级卡片的高频主要入口，使用浅红品牌样式；班级报告使用中性次级样式，橙色不作为主要按钮色。
- 复制班级号必须反馈成功或失败；可见短提示与读屏状态使用同一结果文案。
- 班级排行榜使用白底品牌红轻入口，与筛选控件等高，不使用大面积渐变色。
- 更多菜单统一使用白色浮层、`--tm-shadow-control` 和 `--tm-size-touch`。
- 更多菜单图标只使用品牌、辅助、奖励、正向和中性 Token，不使用蓝紫多彩体系。
- 操作项按业务权限生成；无权限操作不展示，不允许先展示再在点击后拦截。具体权限由对应 PRD 维护。

### 8.2 班级详情

- 可以复用悬浮录入条。
- 在班级详情页录入时，AI 识别对象优先限定在当前班级范围内。
- 学生/分组切换使用克制分段控件，不抢记录入口层级。
- 花名册头像按序轮换 `--tm-tag-*` 点缀浅底，不承载语义，不与性别绑定；性别仅通过头像右下角 `--tm-gender-*` 角标表达。
- 学生与分组的多选选中态统一使用品牌红；分组标签只使用点缀色和中性色，禁止蓝紫多彩体系。
- 学生花名册使用自适应高密度网格：常规手机宽度一行4人，内容宽度达到480像素后允许一行5人，单张学生卡宽度不得低于84像素。列表左右留白使用12像素，卡片横向间距使用10像素、纵向间距使用12像素，卡片高度固定为136像素并使用 `--tm-radius-inner` 圆角。卡片常驻展示头像、姓名、完整学号、等级图标及本学期表扬/批评次数；学号置于卡片顶部，使用9像素中性弱色与常规字重，支持老师按号语音评价后的核对。
- 学生等级由本学期已确认评价记录的净得分实时派生，扣分必须同步回退头像进度、减少图标或降低等级，不保存独立等级字段。换算固定为1颗星2分、5颗星换1个月亮、5个月亮换1个太阳、5个太阳换1个皇冠；同级最多展示4个图标，4个皇冠为展示上限。
- 头像外环只表达距离下一枚等级图标的进度，统一使用奖励金色，不随等级切换颜色；常态静止，分值变化时使用标准动效时长过渡，并遵守系统“减少动态效果”设置。等级标识使用统一的金色饱满立体图片，不使用通用线性图标；视觉复杂度必须随等级递增：星星保持单一金黄，月亮增加橙色体积，太阳增加橙红光芒与纹理，皇冠增加红色饰带、徽记与更丰富的金色细节，使老师可仅凭视觉判断等级高低。星星、月亮、太阳与皇冠均使用水平正向构图；皇冠必须保持正面对称、底座水平，禁止倾斜、旋转或使用侧透视。等级图标下方使用两个不贴边的24×18像素局部色片展示表扬与批评次数，分别使用正向浅绿、负向浅红背景和对应深色数字；色片只承载数据分组，不使用按钮样式、粗描边、图标或说明文字，组件必须通过读屏标签完整说明两项数字的含义。
- 性别角标直接使用 `--tm-gender-*` 彩色粗线图标，不增加白色图标和彩色圆底；图标与头像重叠时必须保留足够的边缘对比度。
- 表扬/批评次数按已确认评价事件计数，与分值强度分开：一次加5分仍计1次表扬，一次扣5分仍计1次批评；批量记录对每名命中的学生分别计1次。卡片不增加规则说明、距升级分数或其他解释文案，精确记录通过学生详情渐进披露。

### 8.3 学生详情

- 记录列表内的 AI 解读样式应与记录页保持一致。
- 学生详情中的基础资料编辑、校园币等入口不使用 AI 解读卡样式。
- 学生基本信息使用有左右留白的独立轻玻璃卡片，统一引用卡片圆角和阴影 Token；页面顶部的浅暖灰到品牌浅红氛围由公共屏幕背景承载并延伸覆盖模拟手机状态栏，底部必须柔和收敛到内容区浅灰，不使用蓝黄绿混合渐变。班级、学号使用中性标签，在校状态使用正向绿标签，离校状态使用中性标签。
- 学生详情接管顶部安全区时，返回入口单独位于状态栏下方，页面导航不再承载“档案/学籍”。学生卡从微信胶囊行下方开始，未开启真实手机效果时状态栏高度自动归零，不额外制造顶部空白。
- 基础资料编辑入口绑定在学生头像上，头像右下角使用与教师个人信息一致的相机角标；点击进入完整学生编辑页，不在详情页直接触发拍照或换脸，也不在身份区顶部重复展示铅笔按钮。
- 基础资料编辑页更换头像统一使用公共底部抽屉；先在“系统头像 / 上传头像”间选择来源，进入上传后再渐进披露“拍照 / 从相册选择”。系统头像按发型轮廓分组排序，单击只更新选中态，确认后才写入学生资料。
- 学生成长档案使用学生卡右上角的“文件夹图标 + 档案”轻量入口，保留中文识别，不收进更多操作，也不使用语义含混的书本或勾选图标。
- 学籍管理与成长档案并列放在学生卡右上角，使用“图标 + 两字中文”轻量入口；两者默认统一使用中性深灰和中性按压底色，不以品牌红制造主次关系。点击“学籍”直接打开状态抽屉，离校等高风险操作继续通过抽屉和二次确认渐进披露，状态标签本身不承担管理入口。
- 钱包、存款统一使用奖励金语义，并入学生身份卡底部的同一行；只使用细分隔线区分身份信息，不再建立独立资产卡片、阴影或外间距。“明细”作为该行末尾的低权重入口，触控高度不得低于 `--tm-size-touch`。
- 成长概览、成长报告、采集记录页签使用品牌浅红轨道、白色选中项和品牌红文字，与教师端其他分段控件一致。
- 成长概览固定展示本学期实时五育积分和评价记录，不提供历史学期筛选；五育雷达图默认直接展示，评价记录在雷达图下方作为独立内容板块直接展示，不再通过数量链接进入二级列表。成长报告与采集记录复用同一学期筛选，采集记录在所选学期内自动按月份分组，不额外提供月份或自定义时间筛选。
- 评价记录使用时间、评价人、指标三个独立筛选入口。时间固定为全学期、本周、上周、本月、上月、自定义，评价人直接展示可选教师且不提供姓名搜索，指标按一级、二级、三级逐层披露并允许在任意层级应用；点击单条记录后进入详情，跨老师修改继续在记录详情中渐进披露。
- 五育雷达图的当前学生使用品牌红轮廓、班级平均使用中性灰轮廓；德智体美劳的数据点分别使用固定五育分类 Token，禁止蓝紫数据面。
- 评价记录整卡按结果使用正向浅绿或负向浅红表面，指标名称保持中性，颜色只表达分值正负；原始记录默认收起。
- 采集记录仅在类型色条和标签中使用家长/学生受众色，其余文字、阴影、空状态使用全局教师端 Token。
- 学生成长概览不展示成长数据摘要、卡片或入口，也不展示身高、体重、BMI（身体质量指数）、视力、体测、健康结论等字段；相关数据的采集和管理由对应业务流程承载，不侵入评价记录这一高频查看路径。
- 成长档案中的成长字段只配置“选填 / 必填”。新增字段默认选填；添加内容抽屉切换到“成长数据”后，必须在主标签和成长分类之间使用低强调说明，仅解释持续记录与跨场景复用价值、系统统一定义的不可编辑约束，不增加单独帮助页或大面积强调提示卡。抽屉只负责勾选字段，不在字段行尾重复显示“选填”或“必填”。字段添加后默认使用与普通字段一致的非编辑态，不标注“成长数据”；数字字段仍按统一成长字段目录展示自身的小数精度和单位。点击字段后才渐进披露完整只读内容、必填开关和删除操作：数字显示精度与单位，单选显示全部选项，文本显示只读文本区；不可修改的字段名称与文本内容统一使用 `--tm-input-readonly-bg / border / text` 展示灰色只读状态。成长字段名称、题型与选项由平台定义，不在档案设计中修改或复制；只有模板主动配置的必填字段可以阻止保存。
- 档案补录必须选择实际记录日期，以“档案补录”作为来源写入统一成长数据，并把当时的值、日期和来源保存为当前档案快照；后续成长数据修正不自动改写该档案。未填写的选填字段保留为空。

### 8.4 我的页面

- 保持清爽白卡和轻玻璃，但信息密度低于记录页。
- 菜单项不使用过重字重，不写显而易见说明文案。

### 8.5 共享业务组件

- 自定义采集、按档案采集和档案设计复用同一表单构建器，字段、分组、选项和校验规则由对应 PRD 维护。
- 问卷采集与档案设计选择成长字段时复用同一分类选择器。顶部使用可横向滚动的开放式分类标签并显示已选数量，下方只展示当前分类字段；分类切换保持不低于 `--tm-size-touch` 的触控高度，切换分类不得清空其他分类的选择或字段设置。不增加默认“全部”分类，不把所有分类同时展开成长列表。
- 全局底部抽屉、确认弹窗、菜单和提示统一复用公共组件，不允许业务页面临时写死结构或样式。
- 模态底部抽屉的背景统一使用 `--tm-mask` 半透明中性蒙层，只降低背景层级，不对整页内容增加模糊或彩色阴影；打开时保持父页面滚动位置稳定，默认聚焦抽屉容器但不主动拉起软键盘，只有用户明确点击输入控件后才聚焦输入。
- 共享组件必须使用教师手机端公共 Token，并完整提供默认、按压、聚焦、禁用、只读、加载、成功和错误状态。普通输入框默认使用 `--tm-input-bg` 白色表面、`--tm-input-border` 可识别边界和 `--tm-input-text` 主文字；禁用与只读分别使用 `--tm-input-disabled-*`、`--tm-input-readonly-*`，禁止把可编辑输入框默认画成灰底。
- 学生批量修改等紧凑行编辑场景使用 `--tm-compact-editor-*` 组件 Token。每个对象独立成行，字段和选择控件横向排列，条目之间通过留白区分；控件默认使用浅边界，聚焦时再显示品牌边界和焦点环。不得使用深色输入边框拼成表格，不得把多个对象包进带分割线的大卡片。
- 问卷采集与档案设计的列表级新建操作统一使用内容区右下角的公共悬浮创建按钮；顶部导航只保留返回和标题，列表尾部必须预留按钮与底部安全区所需的滚动空间。
- 页面级缺省态统一复用 `MobileEmptyState`，只展示对应插图和一行结果文案，不增加操作说明。采集与档案为空使用 `default-state-giraffe-worried-clipboard-3d-color-v1.png`；学生、分组或班级为空使用 `default-state-giraffe-chair-3d-color-v1.png`；搜索无结果使用 `default-state-giraffe-magnifier-3d-color-v1.png`；科目或部门为空使用 `default-state-giraffe-box-clipboard-3d-color-v1.png`。所有彩色缺省图统一存放在 `mobile-app/assets/resources/default-states/`，并使用透明背景 PNG。
- 档案设计演示初始不预置校本档案，首页不展示`校本档案`栏目标题和数量统计。无校本档案时使用项目统一缺省图居中展示，正文只保留`暂无档案`，不增加功能说明或操作提示；右下角公共悬浮创建按钮可使用强化阴影变体建立唯一主操作层级。
- 点击档案设计的悬浮创建按钮后进入`新建档案`公共底部抽屉，不再跳转到独立选择页。`完全新建`使用横向白色实心卡片、无边框；下方标题使用`从模版新建`，模板区域保持`--tm-bg-surface`白色背景。模板卡片使用顶部全宽 `16:7` 系统头图缩略图和下方档案名称、适用年级，不保留通用文件图标、内容缩略图或装饰色条；`一年级初始成长档案`默认使用`成长绿 + 成长记录`，`学生个性与特长档案`默认使用`学习蓝 + 学习探索`，模板预览和复制创建必须继承相同外观。两类卡片统一引用`--tm-shadow-card-on-white`，在纯白背景上通过中性双层环境阴影建立边界。模板保持横向滑动并露出下一张卡片边缘；选择模板后沿用模板预览与确认使用流程，抽屉内不展示字段数量、生成规则或其他逻辑说明。
- 采集任务的老师/家长填写方式在点击新建后、进入编辑器前完成分流；采集内容编辑页不重复展示或修改填写人。采集列表只展示`老师填写 / 家长填写`标签，不向老师暴露普通、成长、混合等底层内容类型。采集设计草稿不作为列表状态或页签展示；每位老师在当前学校的`老师填写 / 家长填写`两个来源下分别最多自动保留一份最新有效编辑记录，不展示手动保存按钮或自动保存状态。只有标题、说明、内容、分组、范围、主题、日期或任务设置至少一项偏离空白默认值时才保存；完全空白退出不生成草稿。再次新建并选定同一填写来源时，通过公共底部抽屉选择`继续编辑 / 重新创建`。
- 填写人确认后进入`选择采集内容`底部抽屉。`自定义采集`作为独立区块置于上方，`按档案采集`及已启用档案列表作为另一独立区块置于下方；已启用档案使用一行两张的紧凑竖向卡片，按照`16:7`头图、档案名称、适用年级和内容数量展示，不使用单列图标列表、分隔线或展开箭头。档案较多时由抽屉内容区纵向滚动，标题栏和关闭入口固定。浮层不展示字段映射、写回规则或其他系统说明。
- 档案设计正文只配置名称、适用年级和档案内容。新建档案的档案名称与新建采集的采集名称复用同一文档标题输入：不重复展示可见字段标签，使用文档标题字号和底线聚焦，限制40字；完成设计时若名称为空，就地显示错误并自动定位到输入框。编辑已有档案保留普通字段样式。适用年级是多选控件，使用 `phoneRadius.sm` 的8像素小圆角，不使用标签型胶囊圆角；触控高度仍不得低于 `--tm-size-touch`。新建与编辑状态复用同一底部设计工具栏，依次使用三个 44×44 像素的`图标 + 文案`透明工具按钮承载`大纲 / 风格 / 设置`，默认态不展示圆形底、边框或阴影，只在按压时显示浅色反馈；右侧的`预览`次按钮和`完成`主按钮使用等分宽度与统一44像素高度，五个相邻按钮统一使用`--tm-space-2`间距。使用中或已停用档案点击完成后只保存修改并保持原状态；主按钮不使用全宽或52像素大按钮。新建档案完成设计后保存为`待启用`并直接进入档案详情，不先返回列表。
- 外观设置和基础设置只通过编辑页底部公共抽屉渐进披露。外观设置提供低饱和主题底色、系统预设横向头图和无头图选项；头图使用标题栏下方独立的全宽 `16:7` 容器与 `object-cover` 裁切，不受正文水平留白影响，模板预览、档案详情和已有档案编辑态均直接贴合标题栏下边界，不保留页面顶部间距。选择主题或头图后必须立即作用于当前档案编辑画布，并同步用于档案预览、学生填写和档案详情。每套主题必须同时提供背景、主色、强调文字、按压色、浅色和浅色按压 Token，并在档案容器内联动选中年级、添加内容、分组标记、开关、输入焦点及主按钮；白色内容卡片、中性文字、固定底部承载面和删除/错误状态色保持全局语义。基础设置只承载`展示分组`和`档案更新规则`；更新规则只保留`仅填写一次 / 可重复填写`，默认仅填写一次。档案设计按当前账号自动保存最新一份有效编辑记录，不显示`已自动保存`状态，也不保留手动保存草稿按钮；只有名称、年级、内容、分组、主题、头图或更新规则至少一项偏离空白默认值时才保留草稿，完全空白的新建档案退出后不生成恢复提示，清空全部配置并恢复默认值后同步移除已有草稿。
- 学生成长档案首页只展示该学生已经形成的档案，不直接铺出学校已启用但尚未填写的档案。每种档案只展示一张当前档案卡；可重复填写只在老师从右下角公共悬浮`新增档案`入口选择已有档案并确认数据更新日期后更新当前档案，同时保留更新记录，不增加同名档案数量。打开已有档案进行编辑属于纠错，同样覆盖当前档案。仅填写一次允许随时编辑纠错，但不得从新增入口重复建立。学生档案列表和详情展示业务数据更新日期，不使用技术保存时间替代。
- 档案列表在常规手机宽度使用一行两张的紧凑竖向档案卡，按照`16:7`头图、档案名称、适用年级和状态标签的顺序展示；头图使用`object-cover`铺满卡片顶部，未配置头图时使用当前主题底色与弱化的无图标记保持固定高度。名称使用卡片标题字号，最多展示两行并预留稳定高度；适用年级使用单行次级文字，只展示年级内容，不重复展示`适用年级：`标签；状态是列表唯一标签。不展示成长字段、手动字段、字段总数、更新规则或主题名称。点击整张卡片打开公共底部操作抽屉，不使用`档案操作`通用标题，直接以档案名称作为抽屉标题，并在标题下方单独展示状态标签。状态操作独占一行并保持最高层级：待启用档案使用品牌实心`启用档案`，已停用档案使用品牌实心`重新启用`，使用中档案在相同位置使用中性实面`停用档案`，避免把停用表现为鼓励操作。`预览 / 编辑`归入`问卷设计`，`复制档案 / 删除档案`归入`更多操作`；两组次级操作分别使用双列浅中性操作块，统一行高、圆角、图标尺寸和按压状态，只通过分组标题与垂直留白建立层级，不增加状态分隔线、组内分隔线、描边或阴影。删除操作保持相同块面结构，仅图标和文字使用负向语义色，并保留二次确认。基础设置、档案正文、业务卡片和固定底部不再提供删除入口。待启用档案详情顶部将名称状态与适用年级拆成独立卡片，适用年级卡片只展示年级；中部完整展示用户配置的分组、字段顺序、必填标志、题型和全部选项。成长字段与手动字段共同归入用户配置的业务分组，不额外生成“成长数据 / 手动填写”展示分组。详情只读，不保存答案、不生成学生草稿；固定底部只保留`继续编辑 / 启用档案`。
- 档案设计不提供“自动带入”学生信息配置。姓名、班级等身份信息沿用学生详情上下文，不在档案填写页和历史详情中重复展示；独立导出或打印时由系统按统一版式默认展示，身份资料缺失不阻止档案留档。
- 学生成长档案的新增入口点击后通过公共底部抽屉选择当前学校已启用且适用该学生年级的档案；尚未形成的档案允许开始填写，已形成且可重复填写的档案允许再次填写，已形成且仅填写一次的档案显示`已建立`并禁用，同一档案已有待填写采集任务时显示`待填写中`，点击后直接进入原采集任务且不允许再次创建。按档案采集列表在档案名称下展示内容数量；采集写回和学生档案再次填写都只更新当前档案，不自行增加档案数量。再次填写前选择并保存数据更新日期，不展示归属周期或周期规则说明。
- 按档案采集每次成功写回后都要更新当前档案的业务数据更新日期。任务包含成长字段时使用发布前选择的记录日期；不包含成长字段时默认使用该学生实际提交日期，不额外增加日期选择控件。档案是否可重复填写只决定能否再次发起，不改变日期写入规则。
- 按档案采集完整继承一份档案的布局、分组、字段、顺序和必填规则。编辑页使用表单构建器只读态展示内容，不出现分组开关、字段删除、拖动、分组菜单、组内添加、添加内容或添加分组。
- 按档案采集不在标题、说明和记录日期之间增加来源状态、分隔线或`内容固定`等解释文案。只读字段直接承担核对作用：单选、多选展示全部选项，评分展示完整分值，多项填空展示全部子项；文字、数字和日期保持紧凑，仅展示名称与类型。自定义采集继续通过`普通题型 / 成长数据`页签渐进添加内容。
- 小程序子页面标题栏只承载返回与居中标题，右侧完整预留给微信原生胶囊，不放置预览、更多或其他业务操作；标题栏必须消费 `--mini-program-capsule-right-inset`，不得依赖固定像素偏移。
- 班主任助理与校长助理报告的历史入口放在标题栏下方的报告上下文行右侧，统一使用历史图标加短文案，并保持不低于 `--tm-size-touch` 的触控高度；禁止只展示无文案图标或侵入微信胶囊区域。
- 班主任助理当前行动建议与评价复盘使用透明标题栏承接屏幕级角色背景，居中展示当前班级名称；历史详情和报告示例优先展示报告自身标题，并在内容区保留班级上下文。
- 低频配置通过底部抽屉或更多菜单渐进披露，不侵入高频记录流程。
- 表单构建器列表态按“连续题号列 + 填写效果预览”排版，题干或字段名只展示一次；点击具体题目或字段后才进入编辑态并展示名称、选项等编辑控件。列表态字段名称使用 `--tm-font-size-card-title` 和半粗字重，输入提示使用 `--tm-font-size-compact`、常规字重和 `--tm-input-readonly-text`，提示层级必须弱于字段名称。档案设计和自定义采集新增普通字段时，以题型名称作为真实可用的默认字段名，单选和多选同时生成`选项1 / 选项2`；新增后自动展开并聚焦字段名，未修改的默认值在聚焦时临时让位并显示`请输入字段名称`，选项聚焦时同样显示`请输入选项内容`，失焦且为空时恢复对应默认值。该智能默认行为不改变成长字段和按档案采集的固定字段。日期、数字、文字、单选和多选在列表态均不额外展示题型图标；所有字段进入编辑态后也不展示题型图标或“文字 / 单选 / 多选 / 日期 / 数字”类型名称，展开卡直接从字段名称开始；题型图标只用于新增类型选择。点击当前题目或字段卡外的区域即退出编辑态，点击另一项时直接切换编辑对象。文字、数字和日期等不可操作的预览必须使用 `--tm-input-readonly-border`、`--tm-input-readonly-bg` 和 `--tm-input-readonly-text`，不得复用可编辑输入框的较深边界或控件阴影。
- 问卷或采集表的标题、说明在新建和草稿编辑时常驻可编辑，仅保留下边框；说明输入初始使用单行触控高度，最多支持 500 字并随内容完整增高，空内容不预留两行高度，输入后完整展示且不做行数截断，错误态保留负向下边框和明确文案。
- 自定义采集正文不重复展示“题目”标题，`展示分组`开关移入底部`设置`抽屉；按档案采集不展示“题目”标题和分组开关；档案设计可保留“字段”标题。分组标题使用浅中性底标题行、卡片标题字号和加粗字重建立结构层级，不为整个分组增加重卡片或阴影；自定义采集和档案设计的组内添加动作使用品牌浅底并明确为“添加题目 / 字段到本组”，“添加分组”使用中性浅底和结构型图标置于分组列表末尾。自定义采集与档案设计的正文序号只表达顺序，不承担拖动；分组排序、组内题目排序和跨组移动统一进入底部`大纲`抽屉。分组更多菜单只保留编辑和删除。
- 家长问卷与学生信息采集的新建、草稿编辑页底部统一使用单行五段操作：三个 44×44 像素的`图标 + 文案`透明工具按钮承载`大纲 / 风格 / 设置`，右侧`预览`次按钮和`下一步 / 完成`主按钮等宽、等高，五项统一使用`--tm-space-2`间距。大纲只承载结构排序；风格提供受控的经典红、成长绿和学习蓝，以及与档案设计共用的系统预设头图和无头图选项，选择后立即作用于当前编辑画布、预览、教师填写和家长填写。头图固定使用标题栏下方的全宽`16:7`容器并通过`object-cover`铺满；从档案发起采集时默认继承档案头图，并将学习蓝、成长绿映射为对应采集主题，之后允许单独调整。设置承载分组等低频任务配置；按档案采集保持内容结构只读。预览读取未发布内容且不产生提交副作用，标题栏不承载业务操作。
- 问卷采集的`收集中 / 已结束`列表在常规手机宽度使用一行两张的紧凑卡片，卡片只展示名称、老师或家长填写标签、日期与完成进度，不展示设计草稿。点击整张卡片打开公共底部操作抽屉，不直接进入详情；采集名称作为弹窗标题，标题下只展示状态。`查看详情 / 预览`固定归入`查看采集`，`复制采集 / 结束收集 / 归档`固定归入`任务管理`，相同操作不得因老师或家长填写而改变位置。只有家长填写且正在收集的问卷在状态下方增加`邀请家长填写`主操作；老师填写问卷不使用`结束收集`填补主操作位。操作块统一使用浅中性表面、相同行高与圆角，通过分组标题和留白建立层级，不增加分隔线或多余说明。
- 发送范围的双栏级联在右侧当前年级标题行提供`全选本年级`，并以未选、半选、全选三态复选框反馈结果；该操作只影响当前年级下有权限的班级，不改变左侧年级浏览状态。
- 问卷发布必须使用公共确认浮层二次确认，并明确提示发布后问卷内容和学生范围不可编辑；页面本身不常驻展示这条权限说明。发布成功后，家长填写问卷立即打开`邀请家长填写`二维码浮层；收集中的家长问卷在操作抽屉中继续以该入口作为主操作。老师与家长问卷的`结束收集`统一归入`任务管理`并使用公共危险确认浮层二次确认，确认文案说明结束后停止继续填写、未完成任务可重新开放。二维码只携带问卷邀请凭证，不包含学生姓名、学号或目标范围。
- 教师预览与家长真实填写必须复用同一问卷组件；学生信息采集预览与老师逐生填写必须复用同一字段表单组件。首题将问卷标题和说明作为独立、无卡片的文档头部，与题目卡分层展示。填写内容以 14 像素为基准，辅助信息使用 12 像素、说明、选项、输入内容和填写态分组标签使用 14 像素、题目使用 16 像素、问卷标题使用 22 像素。填写态分组标签使用次级文字色和半粗字重，独立放在题目卡上方，不使用底色、描边或品牌色；编辑态分组标题继续使用 18 像素和加粗字重表达结构大纲。单选、多选和单行输入不低于 52 像素，评分按钮保持 44×44 像素，底部操作按钮使用 15 像素。
- 两类预览和真实填写统一使用共享问卷主题 Token。经典红、成长绿和学习蓝只改变页面背景、主操作、选中控件和输入焦点等品牌语义；进度条、题型标签、选项容器、普通文字、白色内容卡片以及成功、错误、必填等状态语义保持独立 Token，禁止用大面积品牌浅色表达普通结构层级。
- 填写态的必填标志统一在题目或子字段名称后显示 `*`，不展示“必答”“含必填项”等文字；多项填空仅在实际必填的子字段后显示 `*`。
- 题目或字段编辑态底部统一使用“必填 + 更多”操作行。多项填空题的必填状态由各填空项独立设置，题目底部不再重复展示整题必填。更多菜单承载复制、删除及题型个性化设置；删除必须二次确认，复制项插入原项之后并进入编辑态。
- 多项填空题在同一题目内纵向展示2至6个短文本子项；创建端直接编辑子项名称和必填状态，通过列表末尾的“添加填空项”渐进增加，不常驻展示数量说明。填写端使用带可见标签的单行输入框，统计和答卷按子项分别展示。
- 自定义采集和档案设计正文中的题号或序号只表达内容顺序，不承担拖动；点击底部`大纲`后，在公共底部抽屉中展示当前分组与题目或字段结构，并支持分组排序、组内排序和跨组移动。预览中的输入、选择和评分控件只表达最终填写样式，不接受输入，不与整项点击编辑冲突。

## 9. 禁止项

- 禁止继续使用旧信息化风格的大灰块、重边框、厚阴影。
- 禁止普通页面复制 AI 解读卡样式。
- 禁止用说明文案解释显而易见的信息。
- 禁止记录卡里重复展示当前登录老师头像和姓名。
- 禁止字段内到处放“改 / 换 / 调”文字按钮。
- 禁止记录学生/记录班级模式色影响底部导航。
- 禁止在记录页大面积铺设红色或橙色背景。
- 禁止把加分做成橙色。
- 禁止使用大量 emoji 或 3D 图标表达 AI 感。
- 禁止教师端继续使用蓝紫、靛青作为品牌色、主操作色、选中态或角色色。
- 禁止业务页面直接引用原始色板、硬编码色值、阴影公式或独立字号体系。

## 10. 触控与无障碍

- 所有可点击控件使用 `--tm-size-touch`，其最小触控尺寸不得低于 `44px × 44px`。
- 真实手机端及桌面端手机壳预览统一隐藏横向、纵向滚动条本体，但必须保留触摸滑动、惯性滚动、键盘滚动与程序定位能力；禁止通过 `overflow: hidden` 隐藏仍需滚动的内容。
- 普通字号文字与背景对比度至少为 `4.5:1`，图标和控件边界至少为 `3:1`。
- 小图标必须放入完整触控容器，不能用图标可见尺寸直接充当点击区域。
- 禁用色只用于真正不可操作状态，不得用于未选中的全局导航。
- 普通输入框和选择框统一使用输入组件 Token，不再直接引用表面或通用边界 Token。默认态使用白底、`--tm-input-border` 边界和主文字，让可编辑性在未聚焦时也清晰；获得焦点后使用 `--tm-input-focus-border` 的 1px 品牌红边界与 `--tm-input-focus-ring` 的 2px 半透明浅红外环。只有真正不可操作或只读的字段才能使用对应灰底 Token。次级按钮继续使用 `--tm-border-subtle`，禁止使用 4px 及以上的实色粗焦点环。
- AI 生成内容必须清晰标注人工智能身份；错误信息必须说明失败原因或下一步操作，不能只显示“失败”。
- 动效只服务状态反馈和空间关系，并遵守系统“减少动态效果”设置。
- 手机端 Toast（轻提示）统一出现在页面上方安全区下方，宽度跟随内容并限制最大宽度；使用短暂淡入、停留、淡出，不使用底部通栏或固定大宽度提示。
